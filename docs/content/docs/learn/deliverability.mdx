建立让冷邮件进入收件箱并保持良好送达表现的完整理解框架：身份验证、邮箱预热、发送量和发件信誉。

<ShortVersion>

- 已投递不等于已进入收件箱：服务商可以接收邮件，却仍将其放进垃圾邮件文件夹。
- 投递位置由身份验证、发件信誉、互动、内容和发送量共同决定。
- 想知道邮件最终落在哪里，唯一的办法是测量。

</ShortVersion>

## 邮件送达能力究竟指什么 [#what-deliverability-actually-means]

将邮件交给邮箱服务商后，它还要经过三道关口。**接收**：SMTP 服务器返回 250，并写入队列 ID。**过滤**：垃圾邮件评分决定是投递、延迟处理还是拒绝。**投递位置**：通过前两关的邮件最终进入收件箱、推广邮件、垃圾邮件或用户自定义的文件夹。

<MailJourney />

| 关口 | 判定依据 | 检查内容 |
| --- | --- | --- |
| 接收 | SMTP 250 | 是否符合 RFC、速率限制、基本 IP 封禁 |
| 过滤 | 垃圾邮件评分 | 身份验证对齐、内容扫描、信誉查询 |
| 投递位置 | 用户可见的位置 | 收件箱、推广邮件、垃圾邮件或用户规则指定的位置 |

“投递成功率”几乎总是只反映第一道关口。Gmail 或 Microsoft 的接收端可能接收 99% 格式有效的邮件，却在发件信誉较差时悄悄将其归入垃圾邮件。SMTP 交互并不会告诉你发生了这件事。Postfix 记录的是 250，你使用的工具显示的则是绿色勾号。

想知道投递后的实际位置，只能进行探测：由预热池伙伴邮箱报告邮件落点；通过[投递位置测试](/guides/placement-tests/)向各服务商的种子测试邮箱发送副本；查看 Gmail Postmaster Tools 展示的 IP 和域名信誉等级；或使用 GlockApps/MailGenius 等种子名单服务。这些信息都无法从 SMTP 响应中推断出来。

<Callout type="info" title="实用定义">
**Deliverability = P(placement = Inbox | acceptance)。** 即邮件送达能力等于邮件已被接收的条件下，最终进入收件箱的概率。本手册中的各项措施都会影响这一条件概率。
</Callout>

## 哪些信号决定投递位置 [#the-signals-that-decide-placement]

<SignalWeights />

### 身份验证对齐 [#authentication-alignment]

DMARC 检查的是：可见 From 邮件头中的域名，是否与 SPF 的 Return-Path 域名或 DKIM 的 `d=` 标签匹配？严格对齐要求完全一致；宽松对齐（默认）允许组织域名一致。即使都通过对齐，DMARC 使用 `p=none` 与使用 `p=reject` 时也会受到明显不同的处理。它们又都不同于另一种情况：域名没有对齐，虽然 DMARC 策略允许放行，但 Gmail 仍会降低评价。参见 [SPF/DKIM/DMARC 指南](/learn/spf-dkim-dmarc/)。

### 发件信誉的三个维度 [#sender-reputation-three-vectors]

服务商分别评估三个独立的信誉：发信 IP、From 域名，以及越来越受重视的 `d=` 签名域名。Gmail Postmaster Tools 将每一项分为四个等级：*高*、*中*、*低*、*差*。信誉良好的域名使用信誉受损的共享 IP，邮件仍可能进入垃圾邮件；信誉良好的 IP 搭配信誉受损的域名也一样。域名良好而 IP 不良这种失衡，是将客户集中到共享基础设施上的冷邮件工具最常见的隐性失败原因。

### 互动信号及其权重 [#engagement-signals-weighted]

并非所有互动的权重都相同。收件人在 24 小时内回复，是其能提供的最强正向信号；其次是将邮件从垃圾邮件文件夹移回收件箱；第三是将发件人加入联系人。阅读但不回复属于较弱的正向信号。标记为垃圾邮件是最强的负向信号，未读即删则是较弱的负向信号。批量归档未读邮件时，Gmail 会在邮件层面将其解读为“这些内容是干扰”，并将这种模式推广到该收件人对同一发件人的其他邮件。

### 内容特征 [#content-fingerprints]

对于首次联系的冷邮件，过滤器对纯文本的评分通常比 HTML 更宽松。某些特征会显著提高垃圾邮件评分：链接域名与发信域名不同、使用 URL 缩短服务（bit.ly、t.co）、使用 `.top` / `.click` / `.zip` 顶级域名、图片与文字比例超过 60%、使用系统字体栈之外的字体、隐藏的 Unicode 字符，以及发送工具添加了退订页脚却没有在可见正文中呈现。让健康邮箱的邮件迅速进入垃圾邮件的一个办法，就是突然改变内容特征：原本只发纯文本的发件人突然采用 Mailchimp 风格模板，会被当作另一类发件人重新评分。

### 通过发送节奏检测异常 [#volume-cadence-as-anomaly-detection]

Gmail 和 Microsoft 都会为每个邮箱建立“正常”行为模型，包括通常每小时发送多少邮件、每日发送量以及收件人的重合程度。偏离正常值超过 2–3 个标准差，就会触发发送量异常检测规则。常见的失败场景是：某个邮箱通过预热平稳递增到了每天 40 封，随后突然在一小时内发出 200 封冷邮件。绝对数量不大，但变化速度极快，这才是被标记的原因。

| 信号 | 权重 |
| --- | --- |
| 身份验证 | 必须满足 |
| 发件信誉 | 高 |
| 收件人互动 | 高 |
| 内容 | 中 |
| 发送量与发送模式 | 高 |

这些权重只表示大致方向，并非绝对数值。服务商不会公布具体公式。

## 必须遵守的阈值 [#the-thresholds-you-must-respect]

下列数字并非估计值，而是来自各服务商公布的指南：Google 的《电子邮件发件人指南》（2024 年 2 月的批量发件人更新）、Amazon SES 的账户级信誉文档，以及 Microsoft 的 Exchange Online 发信政策。

| 服务商与指标 | 警戒值 | 停用阈值或限制 |
| --- | --- | --- |
| Google，垃圾邮件投诉率 | 0.10% | 0.30% |
| Amazon SES，投诉率 | 0.10% | 0.50% |
| Amazon SES，退信率 | 5.0% | 10% |
| Microsoft Exchange Online | 由服务商酌情判定 | 批量发送应使用专门服务 |

对 Gmail 真正重要的是 Postmaster Tools 显示的*用户举报*比例，而非 ARF 反馈回路的投诉率。Yahoo、Comcast 等服务商的 ARF 投诉会以 MIME message/feedback-report 部分的形式送达，是另一类更可靠的信号。这两类指标都应保持在 0.1% 以下。

SES 的退信分为硬退信和软退信。硬退信（5.x.x）立即计入；软退信（4.x.x）只有持续发生时才计入。SES 明确规定，最初 48 小时过后，软退信不计入退信率计算。

Microsoft 不公布投诉阈值；其立场是 Exchange Online 不是商业邮件批量发送服务。Exchange Online Protection 的限制（例如每个连接每分钟 30 封邮件、每天 10,000 名收件人）适用于发信租户，并不代表对批量邮件用途的认可。

## 为什么应以邮箱为中心，而非以工作节点为中心 [#why-mailbox-first-beats-worker-first]

信誉不属于工作节点，而属于 IP、域名和 From 发件邮箱。一个承载 200 个邮箱的工作节点，对应的是 200 份信誉，而不是一份。把工作节点当作统一的限额单位（`worker.cap = 5000`），忽略了实际积累信誉信号的位置。

Warmbly 的默认设置体现了这一点：冷邮件发送上限按邮箱设置，默认为每天 50 封；对于确实具备高容量的邮箱，设置允许提高到每天 5,000 封，但超过 100 封就应有良好信誉的证据支持。每次发送的间隔也按邮箱设置，为 600 秒。工作节点的外发额度按其负责的邮箱计算，即 `Σ mailbox.coldBudget`。在默认设置下，如果一个共享工作节点承载超过约 10 个正在发送冷邮件的邮箱（每天约 500 封冷邮件），系统会显示集中度警告，因为超过这一水平后，一个不良邮箱就可能损害该工作节点的 IP 信誉，连带影响同节点上的所有其他邮箱。

扩大总发送量，应通过增加邮箱数量实现，而不是提高单个邮箱的上限。一个希望每天发送 5,000 封冷邮件的营销活动，应分配给 100 个以上的健康邮箱，按每天 50 封的默认上限运行，而不是让 5 个邮箱各发每天 1,000 封。前一种方案不会显得异常；后一种则是典型的异常发送模式。

| 思路 | 模型 | 原因 |
| --- | --- | --- |
| 错误 | `worker.cap = 5000` | 为每个工作节点设置统一固定上限，忽略了信誉实际归属的位置 |
| 正确 | `worker.cap = Σ mailbox.coldBudget` | 通过增加健康邮箱扩大总量，而不是不断加压现有邮箱 |

## 冷邮件发送方案 [#the-cold-email-send-recipe]

1. 使用专门的子域名发送冷邮件（outreach.acme.com），将信誉问题限制在较小范围。
2. 为子域名配置 SPF、DKIM 和 DMARC。先使用 `p=none`，两周后再启用隔离策略。
3. 营销活动开始前，让每个冷邮件发信邮箱至少预热 3 周。
4. 每个邮箱每天最多发送 50 封冷邮件（只有信誉得到验证时才提高），两次发送至少间隔 10 分钟。
5. 将营销活动的发送量分散到多个邮箱，不要集中发送。
6. 默认使用纯文本。除非需要统计打开情况，否则不添加跟踪像素。
7. 安排两到三封跟进邮件，而不是八封。
8. 遵守禁止发送状态，让退信、投诉和退订结果在各处同步生效。
9. 每周监测投递位置，进入观察等级时就采取行动，不要等到严重恶化。
10. 开展冷邮件营销活动时，继续同时运行邮箱预热。

子域名隔离很重要，因为信誉影响会向上关联到组织域名。`outreach.acme.com` 的信誉受损，短期内不会直接损害 `acme.com` 上的事务性邮件；但如果直接使用的 `acme.com` 信誉受损，就会产生影响。应将冷邮件放在专门用于冷邮件的子域名上发送。

DMARC 策略也应逐步收紧：先使用 `p=none; rua=mailto:dmarc@yourdomain`，观察报告 14 天，确认没有第三方服务在你不知情的情况下依赖该域名发信（这是最常见的意外情况）；然后使用 `p=quarantine; pct=10` 一周，再将 pct 提高到 100，最后改为 `p=reject`。跳过 `pct` 的逐步提升，可能导致激进的 DMARC 策略变更将正常邮件隔离。

单个邮箱每天 50 封的默认上限（只有良好信誉证据支持时才提高）和 600 秒的间隔，并不是什么神奇数字。其依据是两类观察：每隔 10 分钟以上发送一封新邮件的邮箱，在收件方看来与真人打字发信的节奏难以区分；而 Gmail 的异常模型会开始标记那些从较低历史基线突然增加到每天约 150 封以上的邮箱。

## 应该测量什么 [#what-to-measure]

先按邮箱测量，再汇总。工作区平均值会掩盖问题：整体投诉率为 0.05% 的工作区，可能有一个邮箱达到 0.4%，另九个邮箱各为 0.01%；而 Gmail 会标记并降低信誉的，正是那个达到 0.4% 的邮箱。

| 指标 | 测量方式 |
| --- | --- |
| 收件箱到达率 | 通过预热伙伴邮箱和种子名单探测 |
| 投诉率 | 分别按邮箱和工作区统计 |
| 退信率 | 区分硬退信与软退信 |
| 回复率 | 按邮件序列、步骤和版本统计 |
| 正向回复率 | 剔除外出自动回复、退订和负面干扰信息 |
| 禁止发送名单的增长 | 占已联系收件人的比例 |

收件箱到达率是核心指标，但没有探测机制也最难测量。Warmbly 的预热池同时承担这项作用：池中的伙伴邮箱收到预热邮件后，会连同验证令牌一起报告所在文件夹（收件箱、垃圾邮件或推广邮件），这些数据构成发件邮箱的投递位置信号。探测样本量很重要：只有过去 7 天针对同一发件人至少有 20 次投递记录时，才应依据**观察**等级采取行动，否则容易对噪声反应过度。

投诉率有两个来源：ARF 反馈回路（Yahoo、Comcast、AOL、Apple）会以 RFC 5965 邮件形式送达；Google 的“标记为垃圾邮件”比例则只能通过 Postmaster Tools 按域名或 IP 查看。Warmbly 将两者汇总为每个邮箱统一的投诉评分。

## 哪些指标不值得追逐 [#what-not-to-measure]

打开率一直存在于冷邮件工具中，是因为它能给出一个看上去像成果的数字，但它并不等于成果。Apple 邮件隐私保护（iOS 15.4+、macOS 12.3+）会通过 Apple 托管的代理预先获取所有跟踪像素，无论用户是否打开邮件。对于任何 Apple Mail 收件人，“投递”后几分钟内报告的打开率实际上都会接近 100%，而 Apple Mail 在 B2B 邮箱中的占比约为 25–45%。跟踪像素记录的打开情况从来就不是很好的信号，如今更是由噪声主导。

首次冷邮件的点击率则存在另一种问题。大多数写得好的冷邮件根本没有链接：链接相当于跟踪像素的放大版，而收件人会点击陌生邮件中“任何内容”的情况都很少。针对首次冷邮件优化点击率，会鼓励加入大量链接，而链接过多本身就是进入垃圾邮件文件夹的信号。

服务商如果不公布“邮件送达能力评分”的计算公式，其分数就无法审计，也容易被人为操纵。如果你无法用自己的数据复现某个数字，就不要让它决定运营措施。

<Callout type="warn" title="应忽略的指标">
- **打开率**：Apple 邮件隐私保护会代理加载，Gmail 会缓存图片，这个数字充满噪声。
- **点击率（首次冷邮件）**：多数冷邮件没有链接，而诱导收件人“点击任何内容”本身也是进入垃圾邮件文件夹的信号。
- **“邮件送达能力评分”**：尤其是那些不愿公布计算公式的服务商提供的评分。
</Callout>

## 发现问题时怎么办 [#when-you-spot-a-problem]

以下任一情况都应触发本处理流程：在最近 20 次投递组成的滚动窗口中，进入垃圾邮件的比例超过 10%；在至少 100 封已投递邮件的样本中，投诉率超过 0.03%；硬退信率超过 1%；或反复不当处理收到的预热邮件（Warmbly 会将删除预热邮件或将其标记为垃圾邮件的行为归因于收件邮箱，因为只有其所有者能进行这些操作）。

1. 立即暂停受影响邮箱的营销活动。
2. 检查邮箱健康等级。如果处于“观察”或更差等级，暂时不要恢复发送。
3. 确认 SPF、DKIM、DMARC 的对齐状态没有发生偏移。
4. 将该邮箱的预热量降到每天 5 或 10 封，并维持一周。
5. 如果已被隔离，通常需要等待 7 天冷却期；如果已被封禁，则需要等待 30 天，并通过人工审核。
6. 执行信誉恢复流程。

第三步的 DMARC 对齐检查最容易被忽略。一种常见的隐性故障是：有人新增了发信服务（Stripe、Notion 或客服工具），在 From 地址中使用你的域名，却没有将该服务的 DKIM 密钥加入 DNS。DMARC 开始对这部分邮件验证失败，信誉系统获得“此域名正在发送未对齐邮件”的信号，随后与你这些服务无关的冷邮件邮箱也受到影响。

邮箱一旦进入隔离或封禁等级，完整恢复步骤请参见[信誉恢复流程](/learn/reputation-recovery/)。

应在问题出现之前改善邮件送达能力。在进入观察等级时就采取行动，不要等到严重恶化。
