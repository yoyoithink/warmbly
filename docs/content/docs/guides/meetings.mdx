浏览时的筛选、搜索和视图选择会[保存在浏览器标签页中](/guides/browsing/)，刷新页面或切换页面后仍可恢复，并按用户和工作区分别记录。

已预约的通话是销售管道中的重要组成部分：它们会实时出现在会议页面和联系人的时间线上，也能触发自动化流程。

会议有两种来源。**自动**：潜在客户通过已连接的 Calendly 或 Cal.com 链接自行预约，由相应服务商的 Webhook 捕获。**手动**：通过**新建会议**自行记录通话，立即创建，无需跳转外部页面。

## 会议页面 [#the-meetings-page]

会议页面位于 CRM 分类，实时更新。顶部显示四项计数：**即将开始**、**今天**、**预约总数**和**已取消**，基于全部会议计算，而非仅统计已加载的行。时间范围标签可切换为即将开始、过去或全部；搜索可匹配联系人姓名、邮箱或活动名称。

每行显示时间、会面对象、会议名称和地点、来源（`Manual`、`Calendly`、`Cal.com`），以及状态：

| 状态 | 含义 |
| --- | --- |
| 已预约 | 已安排日程 |
| 已改期 | 受邀方调整了时间 |
| 已取消 | 会议已取消 |
| 已完成 | 会议已经进行 |
| 未出席 | 受邀方未参加 |

行操作包括：**添加到日历**（Google Calendar 模板或 `.ics` 下载，在本地生成，无需连接日历）、**加入通话**；通过服务商预约的会议还可**改期**或**取消**，手动会议则可以**删除**。

<Callout type="info" title="改期和取消需在服务商处操作">
对于自动预约的会议，这些按钮会跳转到 Calendly 或 Cal.com。Warmbly 不会自行更改会议时间，而是在收到 Webhook 后反映变化。
</Callout>

## 手动记录通话 [#logging-a-call-manually]

**新建会议**需要填写**标题**（默认为“Call”）、**联系人姓名**和**邮箱**（至少填写一项）、**时间**（默认为下一整点）、**时长**（`5` 至 `480` 分钟，默认 `30`），以及可选的**地点**和**会议链接**。

会议通过匹配邮箱地址关联联系人。如果从已经展示某个联系人的页面打开创建入口，则会固定关联该联系人，确保归属准确。

## 连接 Calendly 或 Cal.com [#connecting-calendly-or-calcom]

连接基于 Webhook，而非 OAuth。从**集成**页面操作：

1. 添加 **Calendly** 或 **Cal.com** 集成，Warmbly 会生成入站 Webhook URL。
2. 将 URL 粘贴到服务商的 Webhook 设置，并订阅以下事件：
   - **Calendly**：`invitee.created`、`invitee.canceled`
   - **Cal.com**：`BOOKING_CREATED`、`BOOKING_RESCHEDULED`、`BOOKING_CANCELLED`

URL 一旦创建，连接就会显示为已连接。

<Callout type="info" title="入站 URL 是共享密钥">
URL 包含一段较长的随机密钥，用于验证传入预约，因此应将其视为凭据。如果泄露，可在连接的**入站 URL** 设置中使用**轮换 URL**。旧 URL 会立即失效，再将新 URL 粘贴到服务商处。
</Callout>

### 带签名的事件投递 [#signed-deliveries]

两个服务商都可以对每次事件投递签名。提供密钥后，Warmbly 会检查签名。在连接的**入站 URL** 设置中粘贴：

- **Calendly**：Webhook 订阅的签名密钥，即创建时设置的 `signing_key`，或 Calendly 返回的密钥。
- **Cal.com**：Webhook 上设置的 **Secret**（密钥）。

此后，没有有效签名的投递会被拒绝，因此仅泄露 URL 不足以伪造预约。超过五分钟的 Calendly 签名也会被拒绝，防止截获的投递被重放。点击**移除**会恢复为仅依赖 URL 验证。

预约映射为 `booked`、`rescheduled` 和 `canceled` 状态。Calendly 将改期表示为取消旧预约并创建新预约；Warmbly 能识别这种情况，显示一个**已改期**事件，而不会留下孤立的取消记录。入站预约处理具有幂等性，重复投递的事件会更新现有会议，不会创建重复记录。

**归属判断**按以下顺序进行：优先使用预约链接携带的联系人 ID，并确认其属于当前工作区，即使潜在客户使用不同邮箱预约，也能保留关联；其次匹配受邀方的邮箱。如果两者均无法匹配，会议仍会显示，只是不关联联系人。

## 预约链接 [#booking-links]

在连接的**预约链接**设置中保存公开日程 URL（`https://calendly.com/you/intro`），即可在展示联系人的位置看到相关按钮：

- 联系人详情和统一收件箱会话中的**预约通话**会在新标签页打开预约页面，预填联系人的邮箱与姓名。若连接了多个链接，会先提供选择。
- [统一收件箱](/guides/unibox/)编辑器中的**预约链接**会将预填好的链接插入回复。

从特定联系人的入口预约时，会将其 ID 作为 `utm_content` 嵌入链接。两个服务商都会通过 Webhook 回传此值，因此即使自行预约时使用了不同邮箱，也能正确归属。

<Callout type="info" title="未保存链接时不会显示按钮">
只有服务商已连接且预约链接已保存时才会显示这些按钮，避免出现无法使用的入口。
</Callout>

## 自动化流程 [#automations]

会议事件可驱动[自动化流程](/guides/automations/)：**已预约**、**已改期**和**已取消**可触发通知（Slack、Discord、Zapier、Make、n8n），而**已预约**和**已取消**也可触发 CRM 操作（HubSpot、Salesforce、Pipedrive、Close）。因此，每次潜在客户预约时，同一流程可以向 Slack 发送“会议已预约”，并在 CRM 中创建或更新联系人。处于 [HubSpot 模式](/guides/hubspot/)或 [Pipedrive 模式](/guides/pipedrive/)的工作区无需为此配置自动化流程：每次预约都会作为会议记录到联系人及其未关闭的商机上。
