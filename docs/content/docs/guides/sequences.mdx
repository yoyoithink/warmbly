邮件序列是营销活动依次发送给每位联系人的一组邮件：先发送首封邮件，再按天间隔跟进。你可以在可视化画布上构建序列，每个步骤是一张卡片，卡片之间的连线决定联系人下一步走向哪里。

<Step>

</Step>

</Step>

</Step>

<Step>

</Step>

## 使用须知 [#good-to-know]

- 跟进默认在同一邮件会话中回复。关闭某个步骤的**在会话中回复**，即可开启新会话。
- 等待时间为 0 至 60 天，按联系人分别计算，因此一位联系人等待不会阻塞其他人。
- 每个序列最多 50 个步骤；每个步骤可在原始版本之外增加最多 5 个 A/B 变体。
- 自动回复和休假通知不是人工回复，不会停止序列。
- **发送测试**发送的是已保存的步骤，而非尚未保存的编辑，因此请先保存。

## 什么是邮件序列 [#what-a-sequence-is]

营销活动为每位联系人执行一组步骤：先发送首封邮件，再按天间隔跟进。你在可视化画布上构建流程，每个步骤是一张卡片，卡片之间的连线决定联系人下一步走向哪里。

## 流程画布 [#the-flow-canvas]

画布从联系人进入的位置开始，自上而下自动布局，并填满窗口。双指滚动或拖动空白处可以平移；双指捏合，或按住 `Ctrl`/`Cmd` 滚动，可以缩放。`Shift+1` 让整个流程适配视图。顶部的**开始**卡片显示 `Contact enters the campaign`，表示联系人进入营销活动，并带有加入后等待多久才发送首封邮件的设置。它与营销活动**设置** > **首封邮件**中的设置相同，参见[营销活动指南](/guides/campaigns/#delay-before-the-first-email)。下方依次是首封邮件和后续步骤。你无需手动画线或排列卡片。

- 将鼠标悬停在连线上，点击其 **+** 可在该位置插入步骤；点击路径末尾的 **+** 可在之后添加步骤。选择器支持搜索和键盘操作。首封邮件是最先创建的步骤，不能在它之前插入任何内容。
- 进入每个步骤的连线会在有等待时间时显示，例如 `3 days`。点击连线或在步骤的路径面板中修改。
- 带条件的步骤会为每个条件拆出一列，并增加**否则**列。Switch 步骤为每个分支值拆出一列。点击列标签可编辑该路径。
- 路径末尾的**转到步骤**会将路径接到流程中已有的步骤，以标签形式显示。下方没有后续内容的路径会结束序列；未指向任何步骤的条件路径显示 `End`。
- 点击卡片，在侧面板编辑步骤。多数修改即时保存；邮件和操作编辑器有各自的**保存**按钮，存在未保存修改时，关闭面板前会要求确认。
- 删除步骤时，如果它恰好只有一个后续步骤，会将原先指向它的连接接到该后续步骤。否则，后续步骤保留但不再连接，不会一并删除。没有任何路径通向的卡片会变淡并显示虚线边框，绝不发送；可通过**转到步骤**连接它。
- 仍缺少必要信息的卡片，例如主题或要添加的标签，会在名称旁显示琥珀色圆点；悬停可查看缺少的内容。每个序列最多 50 个步骤。
- 画布支持协作：你可以看到队友的光标和所选步骤，外框使用各自颜色。按 `/` 可从光标处聊天。参见[协作](/guides/collaboration/)。

营销活动向导会将其中撰写的跟进邮件按顺序连接，并设置等待时间。

</Fold>

## 邮件步骤 [#email-steps]

步骤包含内部**名称**（收件人不可见）、**主题**和富文本**正文**。主题提供变量菜单，可插入 `{{.FirstName}}` 等合并字段。

### 正文编辑器 [#the-body-editor]

工具栏包含撤销和重做，快捷键为 `Ctrl+Z` 和 `Ctrl+Shift+Z`，Mac 上使用 `Cmd`；还提供粗体、斜体、下划线、删除线、标题、项目列表和编号列表、链接、图片、按钮、字体菜单、文字和高亮颜色、对齐、表格、个性化菜单、AI 内容块、条件、随机文本语法和表单链接。`Shift+Enter` 在段落内换行，不新建段落。

**对齐**支持左对齐、居中、右对齐和两端对齐，作用于选区覆盖的内容块。再次点击内容块已有的对齐方式会清除它，让正文恢复继承对齐，而不是给每段固定一种方式。

**字体菜单**设置字体和字号。字号提供 12 至 36 px 的预设，也可在输入框中填入 8 至 96 之间的任意值。只提供各邮件客户端都能解析的字体，每项都是完整的字体回退列表，而非单一字体名：Gmail 和 Windows 上的 Outlook 不会加载网络字体，选择网络字体实际上只会决定读者看到哪个回退字体，因此不如直接选择合适的回退字体。字体和字号都写成文字上的行内样式，因为邮件客户端只可靠地从这里读取。

<Callout type="info" title="尺寸以像素为单位">
所有客户端都支持 `px`。小于 13px 的文字在手机上难以阅读，而大多数冷邮件正是在手机上打开的。
</Callout>

从 Gmail、Outlook、Word 或其他邮件工具粘贴文案时，会保留段落、列表、链接、强调，以及表格、行内样式、颜色、字体和对齐。那些工具附带的空行结构会在导入时移除，例如每个间隔一个空 `div`、Word 的间隔段落，因为编辑器本身已经设置段落间距，保留两套会让每个间隔翻倍。

表格尤其值得了解：它是 Windows 上 Outlook 唯一可靠支持的布局方式，因为该客户端使用 Word 而非浏览器引擎排版。依赖 `position`、`flex` 或 `grid` 的布局在那里会失效。表格菜单可插入两行两列的表格；光标位于表格内时，可以增删行列、合并单元格和删除表格。编辑时看到的虚线单元格边框仅用于编辑界面；实际邮件使用标记中指定的边框。

#### 使用 AI 编写与编辑 [#writing-and-editing-with-ai]

正文中有两种 AI 入口。光标位于文案中时，右侧边栏会出现闪光图标；点击它或按 **⌘J**，可以要求在光标处生成文字或续写草稿。选择一段文字时，上方会出现浮动的**使用 AI 编辑**按钮，提供改进、缩短、扩写、修正语法、更友好、更正式等快捷操作，也可输入自由指令。两种方式都消耗 [AI 积分](/guides/ai-credits/)，并在继续之前提供**撤销**和**再试一次**。

编辑只修改你要求的内容，其余段落保持原样。合并字段、条件、随机文本语法、AI 内容块、表单链接和普通链接都以原有形式传入模型并返回，因此改写不会默默删除 `{{.FirstName}}`、清空 AI 内容块，或断开预约及退订链接。选区内的粗体、斜体和标题是例外：这些样式不会保留，因此重视样式时，应避免把它们包含在选区中。发生在句子内部的改写仍留在句内，不会把段落一分为二；模型判断文案已符合要求时，审阅行会显示**没有修改**，不会声称进行了不存在的改写。

#### 图片 [#images]

图片按钮提供三种方式：上传文件、粘贴地址，或从工作区素材库选择已有图片。也可以直接将图片拖到正文中，或从剪贴板粘贴截图。

上传内容进入整个工作区共享的素材库，因此徽标只需上传一次，就能在每个营销活动中一键使用。支持 PNG、JPG、GIF 和 WebP，每个文件最大 5 MB，与附件共用存储限额，可在**设置 > 账单**查看。

选中已插入的图片，上方会出现小工具栏：设为栏宽的四分之一、一半或全部，或图片原始尺寸；选择左、中、右对齐；填写替代文本。建议填写替代文本。大多数客户端在读者允许前会屏蔽远程图片，因此首次看到的通常就是替代文本；邮件纯文本版本也会用它替代图片。

同一工具栏还可将图片变成链接。在链接字段输入地址后，图片会被包在锚点中发送，整张图片均可点击；字段旁的取消链接按钮可移除该链接。如果输入时没有 `https://`，离开字段时会自动补上，因为没有协议的地址会被邮件客户端当作内部路径，无法到达目标。链接图片与正文中的其他链接一样被跟踪和计数，点击报表使用其替代文本作为名称；纯文本版本也会保留替代文本，并在后面附上目标地址。

从素材库删除图片会同时删除文件，因此已经发送的邮件也将无法加载该图片。控制台会在删除之前要求确认。

<Callout type="warn" title="图片会影响邮件送达能力">
真实个人发送的冷邮件很少包含图片。图片过多的正文，在无法理解图片内容的过滤器看来像批量营销邮件，内容检查也会提示。首次触达通常最多只宜包含一个签名徽标或一张产品图片。
</Callout>

#### 按钮 [#buttons]

图片按钮旁的按钮工具会向正文插入行动号召按钮，并打开设置栏：可修改文字、打开的地址、颜色，选择三种尺寸、方角/圆角/胶囊形状、左/中/右对齐，以及是否铺满整栏。文字颜色随按钮颜色自动调整，浅色按钮会使用深色文字，避免黄色背景配白字。按钮标签与其他文案一样支持合并字段和随机文本语法，因此 `Book a call, {{.FirstName}}` 也可使用。

它生成的是单个单元格的表格，而非仅带样式的链接。Windows 上的 Outlook 使用 Word 排版，忽略 `display: inline-block`，因此带内边距的锚点在那里只会显示成彩色文字，没有周围的按钮方框。将颜色和内边距放在表格单元格上，才能在各种客户端保持外形；这也解释了为什么按钮在 HTML 视图中显示为小表格。

没有地址的按钮只会按外形显示，不会成为指向无效目标的链接。链接字段会保持琥珀色，直到填入地址；它也会像图片链接一样自动补上 `https://`。

<Callout type="warn" title="按钮会呈现营销邮件特征">
首次触达如果看起来像新闻简报，读者就会按简报对待。在冷邮件触达中，一句普通文字加链接通常比按钮更有效，过滤器也会把繁重标记视为群发特征。建议将按钮留给后续步骤、活动邀请，或已经展开对话的回复。
</Callout>

#### 自行编写 HTML [#writing-the-html-yourself]

工具栏右侧的 `</>` 按钮会将正文切换为 HTML。你输入的内容会原样保存，包括合并字段和条件，因此在其他工具中制作的模板可以保留标记。发送时唯一的变化来自发送流程的解析或添加：填充合并字段，将 `<style>` 块内的样式内联到匹配元素，并附加签名、退订页脚和跟踪内容。

HTML 模式是步骤自身的属性，不取决于当前打开哪个标签页。以标记编写的步骤，任何人下次编辑时仍以标记打开，避免设计因重新打开而悄悄被简化。将整封 HTML 邮件粘贴到可视化编辑器时，步骤会自动切换为 HTML 并原样保留标记，因为带有独立 `<head>` 和 `<style>` 块的文档，无法由普通可视化编辑器完整忠实地表示。从文件中复制邮件源码并作为文本粘贴，也会触发相同行为。

切回可视化编辑器时，标记会转换为编辑器自身结构，保留段落、换行、标题、列表、链接、强调、图片、表格、`div` 容器、颜色、字体和对齐。除此之外的内容，会在删除前的确认提示中逐项说明；继续留在 HTML 模式即可保留。

#### 邮件发送时会将 CSS 转为内联样式 [#css-is-inlined-when-the-email-sends]

像平常一样，将 CSS 写在 `<style>` 块中。邮件发送时，每条有匹配目标的规则都会复制到对应元素的 `style` 属性。Outlook.com、Yahoo 和 Gmail 移动应用会直接丢弃内嵌样式表，因此不做内联处理时，依靠类名的设计到达后会失去样式。

实际行为如下：

- 无法内联的规则继续保留在 `<style>` 块中，包括媒体查询、`@font-face`、`@keyframes`，以及依赖 `:hover` 或其他读者交互状态的规则
- 媒体查询如果要覆盖已经成为行内样式的规则，需要在声明中加 `!important`，否则行内样式优先。所有会内联 CSS 的邮件工具都遵循这一点
- 你自己写的 `style` 属性仍优先于样式表规则，而 `!important` 仍可覆盖它，与浏览器一致
- 已内联的规则会从 `<style>` 块移除，避免邮件重复携带同一套样式
- 没有 `<style>` 块的正文不会被处理，现有营销活动发送的内容逐字节保持原样
- 如果希望保留自己编写的层叠规则，并且了解收件客户端，可使用 `<style data-warmbly-inline="false">`，它会完全原样保留

#### 邮件客户端对内容的处理 [#what-mail-clients-will-do-to-it]

正文下方和预览标签页下方的面板会说明标记可能遇到的问题：`<script>`、`<form>` 和 `<iframe>` 被移除，外部样式表不会被客户端加载，某些 CSS 被 Windows 上的 Outlook 忽略，图片没有替代文本，网络字体将回退，以及邮件是否长到会被 Gmail 截断。Gmail 会将超过 102 KB 的内容折叠到“查看完整邮件”链接后，这也会隐藏退订页脚，并导致没有展开邮件的读者不被记录为打开。

这些提示都不会阻止发送。它们存在的原因是邮件 HTML 面对的渲染器行为各不相同，在编辑器中提前发现，总比从收件人回复中才得知更好。

#### 纯文本版本 [#the-plain-text-half]

每封 HTML 邮件都会同时携带纯文本版本，收件服务商也会读取它。

对于在控制台中以 HTML 编写的步骤，Warmbly 不存储纯文本版本，而是在发送时生成：标题和段落保留换行，列表项添加项目符号，表格行变为文本行，每个链接的文字后用括号保留目标地址，样式表和隐藏的预览文字则省略。之后附加邮箱的纯文本签名和退订行。预览标签页会显示结果，让你看到纯文本客户端收到什么。

使用可视化编辑器编写的步骤，会在输入时同步生成纯文本版本，并保留相同信息：图片用括号中的替代文本表示，普通链接、链接图片和按钮都在标签后用括号保留目标地址。否则，纯文本读者只能看到按钮文字，却无处可点。

这只适用于没有现成纯文本正文的情况。通过 API 设置 `body_plain` 后，文本会原样发送；留空则由发送流程从 HTML 生成。

反向转换也适用。通过 API 或代理工具编写的步骤通常只有 `body_plain`，HTML 版本会从该文本生成：保留行，并将裸 URL 转为链接，供点击跟踪改写。在此之前，步骤存储的是编辑器的空 HTML 文档；过去导致空白邮件的正是这个空文档，而非没有 HTML，因为客户端优先选择 HTML 版本，会显示空 HTML 而不是文本。已经具有 HTML 正文的步骤绝不会被覆盖。

两个正文都为空的步骤会在启动时被拒绝，不会发送：没有人会有意启动一个向所有潜在客户发送空白邮件的活动。

### 预览与测试 [#preview-and-test]

预览标签页通过真实发送引擎渲染，因此合并字段、条件和随机文本语法的解析方式与实际发送完全相同。正文在独立框架中按邮件客户端方式展示，而非按编辑器方式。**预览身份**决定为谁渲染：内置示例联系人、活动中的某位潜在客户，或搜索到的任意联系人。这样，名单中实际不存在的自定义字段会显示为未解析的令牌，不会造成一切正常的假象。旁边的邮箱选择器会添加相应发件人的签名，并显示收件人看到的发件人名称。已知营销活动时，预览还会附加退订页脚，并列出活动附件。格式错误的模板，例如有 `{{if}}` 却没有 `{{end}}`，会在活动启动前被标记。可在文案中使用的全部内容，参见[个性化](/guides/expressions/)。

预览中的**发送测试**会通过所选邮箱，将已保存步骤发送到指定地址，按所选联系人渲染，并携带附件、签名和退订页脚。请先保存步骤：测试发送的是已存储内容，而非未保存的修改。测试邮件的打开和点击不跟踪，退订链接也不指向任何人，因此点击不会将任何联系人加入禁止发送名单。

<Callout type="info" title="模板">
可以将已保存模板应用到步骤，也可以从编辑器将步骤保存为可复用模板。模板包含主题和正文，存放在共享素材库中。
</Callout>

### 附件 [#attachments]

在步骤编辑器下方拖放文件，或点击上传区域，即可添加步骤附件。在这里上传的文件只随该步骤的每封邮件发送，不会出现在其他步骤中，也可在同一位置移除。直接附加到营销活动、而非单个步骤的文件，只能通过 API 添加，会随每个步骤发送；它们列在**随每个步骤发送**下，让各步骤都展示自己携带的全部文件。附件计入工作区存储限额，可在**设置 > 账单**查看；会超额的上传以 `storage_limit_reached` 被拒绝，即使两个上传同时争用最后的余量，也不能都成功。删除步骤会同时删除专属于它的文件。

### 操作步骤 [#action-steps]

步骤也可以执行操作而非发送邮件：添加或移除标签、为会话添加标签、创建任务、创建商机或移动其阶段、让联系人退订、发送通知（触发 Webhook 和集成）、运行自动化流程，或执行 Switch 分支。它们像邮件步骤一样位于流程中，尤其适合放在回复分支末尾，例如收到积极回复后创建商机并通知团队。

<Callout type="info">
**为会话添加标签**仅适用于回复。它标记联系人实际回复的会话，因此应放在回复分支上；放在其他位置时，由于没有可标记的会话，不会执行任何操作。
</Callout>

### 条件选择步骤 [#switch-steps]

Switch 步骤将每位联系人路由到多个命名分支之一，例如 `interested`、`not_now`、`wrong_person`。每个分支值在步骤下方占一列，可以在列下添加该分支要执行的步骤。**否则**是没有匹配任何分支的联系人使用的后备路径。重命名分支值会保留其下方步骤。产生实际修改的操作仍以路径上的普通操作步骤表示，因此决策及其后果分别可见。

| 决策方式 | 如何选择 | 费用 |
|---------|--------------|------|
| **AI 提示词** | 自然语言指令，支持与邮件文案相同的变量。每位联系人调用模型一次，读取其数据并恰好选择一个分支值。 | 每位联系人 1 积分，失败退款。没有积分时跳过此步骤，联系人进入后备路径。 |
| **值** | 为每位联系人渲染模板值，例如 `{{.Industry}}` 或任意自定义字段，再与分支名匹配。忽略大小写和首尾空白；将分支值包在斜杠中，可使用不区分大小写的正则表达式，例如 `/^(vip\|enterprise)/`。先匹配普通分支，再按顺序匹配正则。 | 免费，完全确定性 |

AI 决策方式还提供两个可选开关：**网络搜索**根据公司、姓名或企业域名构造查询，查找联系人公司信息，绝不使用邮件内容构造查询；找到结果时额外消耗 1 积分。**深度思考**将困难决策路由到更强的模型档位，按 [AI 积分](/guides/ai-credits/)计量。

在 **AI 可见内容**下，每个步骤都可以决定，除联系人字段外，是否还向模型提供其营销活动历史和最新邮件。两项默认开启。邮件和个人资料字段严格视为内容：邮件中的指令，例如“忽略你的规则”，会被忽略，模型只能返回你命名的分支之一。

Switch 步骤始终按常规调度运行，因此即时回复分支如果进入 Switch，会等待到下一个调度边界。

</Fold>

## 等待时间与发送间隔 [#wait-and-spacing]

间隔属于**目标**步骤，不是独立节点，因此画布没有单独的等待块。进入步骤的连线显示其等待时间，例如 `3 days`；点击可以设置该步骤之前等待 0 至 60 天。没有等待的步骤，连线上不显示时间。唯一不属于步骤自身的延迟，是*首封*邮件之前的等待，位于开始卡片下方的连线上。

等待属于目标步骤，因此所有进入该步骤的路径都使用同一个等待时间。适当拉开跟进间隔，可使发送模式更自然；参见[邮件送达能力](/guides/deliverability/)。

等待按联系人分别计算。一位联系人等待三天才收到跟进，不会阻塞其他人：期间其他联系人的首封邮件和已到期跟进仍会继续发送。只有所有联系人都没有到期任务时，活动才会等待。

<Callout type="info" title="即时分支会跳过等待">
即时路径在事件发生时触发，因此不应用目标步骤的等待时间，相应控件也会隐藏。操作步骤立即执行；邮件步骤立即变为待发送，并在活动下一次调度时发送，通常在 15 分钟内，仍遵循发送时间窗口和邮箱的发送间隔。非即时路径，包括你主动关闭即时性的路径，继续使用目标步骤的等待时间。
</Callout>

</Fold>

<Fold>

## 跟进邮件与会话串联 [#follow-ups-and-threading]

跟进是下一个邮件步骤，作为**联系人已经参与的会话中的回复**发送，而不是突然出现的另一封独立邮件。它携带 `In-Reply-To` 和 `References`，指向该联系人最近收到的营销活动邮件；在 Gmail 中也会写入同一会话，因此在对方收件箱和你的已发送文件夹中，都排列在首封邮件下方。

每个邮件步骤都有**在会话中回复**开关，默认开启。如果某个步骤需要明确开启新会话，请关闭。

- 在会话中回复的步骤没有独立主题：回复沿用会话主题，即开启该会话的邮件发送时使用的主题。编辑器显示该主题，不提供主题输入框。
- 会话跟随每位联系人实际收到的内容。如果开启会话的步骤进行了 A/B 测试，收到变体 B 的联系人后续都在变体 B 的主题下获得回复，收到原始版本的人则沿用原始主题。编辑器会列出各版本主题。跟进逐字沿用首封邮件实际发送时的主题，因此之后编辑开场步骤或联系人，不会改变已经建立的会话主题。
- 关闭**在会话中回复**的步骤使用自己的主题，并开启新会话。之后所有启用会话回复的步骤都接续*这个*新会话。
- 对联系人的首封邮件，此开关不起作用。没有可回复的邮件，因此它会开启会话。
- 同样因为主题属于会话，会话回复步骤上的 A/B 变体只能改变正文。

<Callout type="info" title="首封邮件须确认发送成功后才能设置回复邮件头">
回复邮件头指向邮件服务商实际发送时使用的消息 ID，Warmbly 在工作节点报告发送结果时获知它。如果确认始终没有到达，跟进仍会发送并沿用会话主题，但会作为独立会话。
</Callout>

</Fold>

## A/B 版本 [#ab-variants]

打开步骤编辑器，点击**对此步骤进行 A/B 测试**。

- 步骤自身的主题和正文是**原始版本**对照组；添加变体后，它成为多个具有权重的实验组之一。
- 在原始版本之外，最多添加 5 个变体，即 B 至 F。
- **流量分配条**为每个实验组显示一段。拖动分隔线或输入精确百分比，份额总和始终为 100%；**平均分配**将流量均分给所有启用的实验组。
- 选中实验组可编辑名称、主题和正文。变体主题或正文留空时，复用步骤自身内容。对于在会话中回复的步骤，变体主题会被忽略，因为主题属于会话。对于开启新会话的步骤，变体主题会成为收到它的每位联系人的会话主题，后续接续该会话的跟进也沿用此主题。
- 首个变体默认按 50/50 分配。将某个变体标记为**停用**会将其移出分配，但不删除；删除最后一个变体后，步骤恢复为单一版本发送。

变体开始发送后，每张卡片会显示已发送、打开率、回复率和退信率。Warmbly 识别出**胜出版本**时，会以横幅显示名称、采用的规则和置信等级，并在胜出卡片上添加奖杯标记。

</Fold>

## 分支 [#branching]

分支根据条件路由联系人。在步骤下方点击 **+** 并选择 **If / else**（条件分支），或在步骤 **⋯** 菜单中选择**添加条件**，再在侧面板选择条件并点击**保存**；保存之前，联系人流程不会改变。每个条件在步骤下方占一列，从左到右按 `if` / `else if` / `else` 检查，首个匹配项优先；路径面板中的**提前检查**和**延后检查**可以改变顺序。没有匹配任何条件的人进入**否则**，若该路径没有后续步骤则停止。

| 条件 | 含义 |
| --- | --- |
| `always` | 等待结束后无条件执行 |
| `if opened` / `if clicked` | 在 N 天窗口内发生打开或点击，窗口为 1 至 60 天 |
| `if replied` | 已回复 |
| `if didn't open` / `didn't click` / `didn't reply` | Warmbly 等待完整窗口结束，仅在相应事件仍未发生时进入该路径 |
| `if replied: positive` / `negative` / `neutral` | 按回复意图判断，只检查一次，没有天数窗口 |
| `if auto-reply / out of office` | 回复为自动消息，而非人工回复 |
| `if reply intent is…` | [自动收件箱标签](/guides/inbox-tagging/)从人工回复中识别的意图：同意、想了解信息、想了解价格、暂时不需要、不感兴趣、找错人、退订、安排时间、进行中、问题已解答或不明确。只有开启收件箱自动标签且分类器置信度至少 70% 时才设置；没有标签的回复走“否则”路径。只检查一次，没有天数窗口 |
| `random split` | 随机分配一定比例的联系人，范围 1 至 99% |
| Switch 分支路径 | 由 Switch 下各分支值对应的列决定，不在这里选择。使用已保存的分支值，因此路由本身不消耗积分 |

### 立即分支与下一步骤分支 [#instant-vs-at-the-next-step]

回复意图、`opened` 和 `clicked` 可以**即时**触发，在事件到达时执行，而不是等到下一个计划步骤。`reply intent is` 路径在已分类回复到达时立即触发，路由时无需调用模型。这些路径显示紫色 `instant` 标记，可以逐路径关闭，改为在下一个边界检查。即时路径仍遵循时间窗口：只有在 N 天内打开或点击才运行，未发生则不会运行。

</Fold>

<Fold>

## 回复分支 [#reply-branches]

步骤选择器中的**如果对方回复**会打开一条新路径，在联系人回复时立即触发，默认针对积极回复，可在路径面板修改。点击**保存**添加，再在其下加入要执行的步骤。

- 回复通过会话邮件头匹配，触发其**实际回答的那封邮件**的路径。它不一定是最新步骤，也不会同时触发两封邮件的路径。
- 无法匹配的回复回退到最新步骤。
- 自动回复和休假通知不是人工回复，不触发人工回复路径，也不会停止序列。可以使用 `auto-reply / out of office` 条件处理它们。
- 休假通知本身会暂停该联系人作为潜在客户参与的所有活动中的下一步，直到其返回，避免跟进发到无人值守的邮箱。参见[休假与暂停单个潜在客户](/guides/campaigns/#out-of-office-and-pausing-one-lead)。

</Fold>

<Fold>

## 收到回复后停止 [#stop-on-reply]

这是流程工具栏中的营销活动级开关。开启后，联系人回复会停止其余冷邮件序列，但被回复邮件上的回复分支仍会即时运行。

只有从该营销活动联系人进入发件邮箱的入站邮件才计为回复。从已发送或草稿文件夹同步的串联跟进，即使 `In-Reply-To` 指向更早的营销活动步骤，也仍然属于出站邮件。

营销活动轮换发件账户时，如果邮件客户端引用了同一工作区另一邮箱发出的更早步骤，真实入站回复仍会关联到该营销活动。

联系人新发来一封不回复你任何既有会话的邮件时，会归到你在收到它之前最近发给对方的营销活动邮件。早于你向对方发送任何邮件就已到达的邮件，不归属于任何活动，因此导入旧邮件不会停止序列。

回复到达发送时 reply-to 指定的邮箱时，也按相同方式统计，即使该邮箱从未向联系人发信。这正是[共享回复收件箱](/guides/mailboxes/#a-shared-reply-inbox)的基础：回复会停止序列、运行回复分支，并归功于原始发件邮箱。

如果升级修复了一个经证实由同步的已发送邮件错误生成的回复标记，该联系人会从下一个到期步骤继续，活动回复总数也随之更新。升级还会恢复能够证实的人工回复：它们被某个营销活动邮箱接收，但引用了同一工作区另一邮箱建立的会话。Warmbly 会根据修正后的投递、打开、点击、回复和退信证据重新计算地址验证状态。无法明确判断的历史回复保持不变。

<Callout type="warn" title="开启收到回复后停止">
关闭此开关且序列多于一个步骤时，Warmbly 会在画布上警告：未匹配回复分支的人否则仍会继续收到冷邮件跟进。开启后，你设置的回复分支仍会运行，因此更稳妥。
</Callout>

</Fold>
