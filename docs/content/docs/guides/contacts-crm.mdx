## 使用须知 [#good-to-know]

- 重复项在整个工作区内按转为小写的邮箱地址匹配，因此一个地址对应一个联系人。
- 空单元格不会清除已有值，因此重新导入不完整的导出文件也安全。
- 自定义字段可用于个性化，例如邮件中的 `{{.industry}}`。
- 所有营销活动都会自动跳过已退订联系人。
- **保存为分群**将列表筛选转换为可重复使用的[分群](/guides/segments/)。

## 导入 [#importing]

文件上传和按需 Google Sheets 同步共用同一列映射界面。

**从文件导入**支持 CSV、TSV 或 XLSX，最大 50 MB、50,000 行；CSV 可使用逗号或分号，系统从表头行判断。向导依次经过**上传**、**映射列**、**审阅**和**导入**。可以从联系人页面开始；也可以从营销活动的潜在客户标签页开始，自动将导入内容加入该活动；或从[分群](/guides/segments/)成员列表开始，将每行联系人固定加入该分群。向导会在标题和审阅步骤显示继承的目标，结果页也会确认。

1. **上传。** 文件只上传一次，由服务器读取并分析整个文件的每一列。此时尚未写入联系人。如果从头准备数据，可用**下载示例文件**获取包含所有标准列的 CSV。
2. **映射列。** 每列显示整个文件中的填充率、若干示例值及目标字段。**查找列**和**仅未映射**便于处理很宽的 CRM 导出。**首行为表头**可在表头与数据之间切换第一行的用途。**预览联系人**展示前几行将成为怎样的联系人，并标出缺少可用地址的行。
3. **审阅。** 写入之前检查整个文件，用一行汇总将新增多少联系人、多少已存在于工作区、合并多少重复行，以及多少行无法导入；展开可查看具体行和原因。存在已有联系人时，为它们选择**保持原样**或**更新详情**。**将其加入**可为文件中的所有联系人选择分群、标签和营销活动；分群选择器支持即时创建，还会建议以文件名命名，使导入一步成为受众。**更多选项**控制新联系人是否订阅。如果整个导入会因超过套餐联系人限额或创建超过 100 个标签而被拒绝，这里会提前说明，不会等到写入后才报错；导入按钮也会明确说明实际操作，例如 `Import 1,102 new · update 118`。
4. **导入。** 服务器分批执行，显示实时进度、速度和剩余时间。关闭窗口或刷新页面都不会中断，工作区内所有人都能看到完成状态。运行时，联系人工具栏上的**正在导入**标签显示进度，并可重新打开任务；**停止**会提前结束，保留已导入行。结果报告新增、更新、跳过和失败数量，并列出失败行及原因。**下载以修复**提供全部失败行，保留上传时的数据和原文件表头，在最后一列附上原因，方便修正后重新导入。

如果文件表头与曾导入的文件一致，会自动沿用上次确认的映射，并标记**已记住映射**。上传步骤列出工作区最近的导入，无论已完成还是运行中；打开可查看进度或结果。

至少必须将一列映射到**电子邮件**。

| 字段 | 说明 |
| --- | --- |
| 电子邮件 | 必填，用于去重 |
| 名字、姓氏、公司、电话 | 标准身份字段 |
| 已订阅 | 接受 `yes`、`true`、`1`、`subscribed` 及其相反值 `no`、`false`、`0`、`unsubscribed`。适用于新联系人和选择更新的已有联系人；无法识别的值只会使对应行失败 |
| 标签 | 以逗号或分号分隔的标签名称。不存在的名称会创建，每次导入最多新增 100 个 |
| 自定义字段 | 其他任意信息，可选已有自定义字段，或命名一个新字段 |

### 映射到自定义字段 [#mapping-into-your-custom-fields]

映射菜单在**你的自定义字段**下列出工作区已有字段，使用最多的优先，顶部带搜索框。输入可筛选；输入尚不存在的名称，菜单会提供创建选项。选择已有字段会将该列写入其中，与已有联系人保持一致，读取该字段的所有模板、筛选和分群都能直接使用。

如果列标题对应已有字段，打开菜单前就会自动映射。匹配忽略大小写、空格、下划线、连字符和点，因此 `company url` 列会落到已有 `company_url` 字段，沿用其存储拼写，不会另建第二个字段。自动匹配时，每个字段只对应一列，且电子邮件、公司等标准字段优先。

实例配置 TypeSafe 后，未通过表头匹配的列还会按含义映射，例如 `Job Title` 映射到已有 `Title` 字段、`Firmenname` 映射到公司、`Sector` 映射到 `Industry`。只应用有把握的答案，每个字段仍只对应一列；这些行会标记**按含义匹配，请检查**，直到你修改。它只选择姓名、公司、电话和自定义字段；订阅和标签会改变谁收到邮件、存在什么标签，因此绝不猜测。发送给服务的只有列标题、每列值的类型及字段名称，不包含任何单元格。只有第一行明显是表头时才会发送：其中没有地址、日期或数字，且有命名的 Email 列。参见[数据控制](/development/data-control/#typesafe-judgments)。无论表头叫什么或是否有表头，只要整列是地址，都会映射到电子邮件。

每个自定义映射都会说明结果：**填充现有字段**、**创建新字段**；如果输入名称与已有字段只在大小写或分隔符上不同，则显示**你已有 `Industry`**，并提供**使用它**切换。**将另外 N 列保留为自定义字段**也采用相同匹配规则，能复用已有字段就复用。

手动可以让两列填充同一字段，例如把 `Phone` 和 `Mobile` 合并为一个号码。每行会指出另一列；两列都有值时，使用更靠右的值。空单元格不会覆盖另一列的值。

<Callout type="info" title="在整个工作区内按转为小写的邮箱地址匹配重复联系人">
`Dana@Acme.com` 和 `dana@acme.com` 是同一联系人。联系人属于工作区，因此队友已添加的地址也算已有。可以选择**保持原样**，不动详情；或**更新详情**，用文件补齐空白详情。API 也接受 `create_duplicate`，但它同样执行更新，因为每个工作区中一个地址只对应一个联系人。

跳过字段更新，仍会将联系人加入导入目标中的营销活动、分群和标签；它只是保留字段，不是把联系人排除在名单外。同一地址在一个文件中出现两次时，只生成一个联系人，多余行计为跳过，并指出重复了哪一行。
</Callout>

如果某个地址已经是你所属另一个工作区中的联系人，就不能添加到当前工作区；该行会失败并说明原因。这里的导入绝不会修改另一个工作区的联系人。

某一行无法保存，例如自定义字段值过大，只会使该行失败；同时导入的其他行不受影响。

缺少或无效电子邮件地址的行会报告行号和原因，不会导入。地址以小写存储，并去除外层显示姓名，因此 `Dana Reyes <dana@acme.com>` 会导入为 `dana@acme.com`，同一地址的两种写法落到同一联系人。空单元格不会清除已有值，因此重新导入不完整的导出文件会补全联系人，而非擦除信息。

映射本身的问题，例如未命名自定义字段或不可用名称，会在任何写入之前统一报告，避免一个拼写错误导致所有行失败。

在**审阅**步骤，**营销活动**将文件中的所有人作为潜在客户加入所选活动；如果从活动的潜在客户标签页开始，该活动显示为固定目标。**分群**以手动包含方式将其固定加入所选[分群](/guides/segments/)，不受分群条件影响。通过选择器创建的分群没有条件，因此只包含被固定加入的联系人。从分群开始导入时，该分群始终应用并显示为固定行，下方选择器可添加更多。

**从 Google Sheets 导入**时，表格是可重复使用的**同步来源**，而非一次性上传。连接一次后，Warmbly 只读取你选择的工作表，绝不回写。粘贴 URL 中 `/d/` 与 `/edit` 之间的电子表格 ID，选择工作表并映射列，再设置重复处理、来源名称，以及可选的加入活动、应用标签和固定加入分群。**不会自动同步**：必须点击**立即同步**，或保存后立即同步。

如果**通过 Google 连接**提示未配置 OAuth 凭据，实例运维人员需要完成 [Google Sheets 应用设置](/development/configuration/#google-sheets-app)。连接 Gmail 邮箱或通过 Google 登录 Warmbly，并不会配置这个客户端。Warmbly Cloud 用户应联系支持；自托管实例则需配置后端凭据并重启。

分群目标在每次运行都应用，因此持续新增行的表格会持续补充同一受众。从分群成员列表打开**同步来源**时，只列出向该分群提供数据的来源，新建来源也会预设该分群为目标。之后删除的分群会从运行中移除，不会阻止整个同步。

保存的来源位于同步来源列表，可重新运行、编辑或移除。每次同步都按转为小写的邮箱地址和所选重复处理方式去重，因此为新增行重新同步同一表格是安全的。

### 导入审查提供的名单信息 [#what-the-review-tells-you-about-the-list]

审阅步骤和结果也会报告地址本身的特征：多少格式错误、多少位于已知一次性域名、多少是 `info@` 这样的共享邮箱。当文件至少四分之一地址格式错误或属于一次性邮箱时，两处都会说明。

- **共享邮箱会统计，但不会降低名单质量判断。** 向 `info@` 发信是一种选择，许多合法 B2B 名单本来就以岗位地址为主。
- **导入仍会执行。** 这些是你的记录，因此这里不会据此拒绝。名单质量差到需要拦截时，会在你尝试用它启动营销活动、实际可能造成损害的阶段阻止。参见[启动检查](/guides/campaigns/)。
- **少于 20 行的名单不评判**，因为几行数据的占比没有参考意义。

这不是地址验证。它只是分析地址；验证则会询问接收服务器地址是否存在，在导入后一分钟内另行后台运行。如果文件已经携带其他服务的验证结果，例如 `status` 或 `ZeroBounce Status` 列，映射时会识别并提供**验证状态**选项。已有判定会保留，后台检查跳过它们。参见[地址验证](/guides/deliverability/#address-verification)。

## 自定义字段 [#custom-fields]

自定义字段用于身份信息以外的内容，例如行业、套餐档位、客户负责人。可以在导入时将列映射为新自定义字段，也可以在联系人详情标签页创建。以后导入时，从映射菜单选择同一字段即可继续写入，参见[映射到自定义字段](#mapping-into-your-custom-fields)。

### 手动填写字段 [#filling-them-in-by-hand]

**新建联系人**，在营销活动潜在客户标签页中称为**添加潜在客户**，以及联系人的**详情**标签页，会将工作区自定义字段显示为表单：每个字段有独立输入框和名称，使用最多的优先，只需填写值。默认显示前六个，**显示另外 N 个**展开其余；超过十二个时，提供按名称查找的筛选框。联系人已有的字段始终显示。清空字段值后保存，会将该字段从联系人移除。

**新建字段**添加尚无人使用的字段。输入名称时，会建议已有字段；选择已有项，会将刚输入的值移到该字段。名称与已有字段相同，或只在大小写和分隔符上不同，会提示并提供**使用它**切换。不可用名称、有值无名称，或同一字段重复填写，都会在保存之前标记。若字段名在上述命名规则推出之前就已存储，会继续在已有联系人的表单上显示，但锁定，不能从表单修改或移除。

自定义字段用于个性化，这也是正确映射导入数据的主要原因。

字段名可以包含字母、数字、下划线、空格和连字符，例如 `industry`、`account_owner`、`Company Mobile`、`first-name`。其他字符，例如 `/`、`#`、`(`、`)`，会被拒绝，因为无法将这样的字段合并到邮件中。将列映射为自定义字段时，向导会从列标题填入名称，不可用则就地提示。

<Callout type="info" title="字段名也可以包含空格">
简单名称，即字母、数字和下划线，使用点号引用：`{{.industry}}`、`{{.account_owner}}`。含空格或连字符的名称也可以，按实际名称原样书写：

```
Your role as {{.job title}} at {{.Company}} caught my eye.
```

两种形式在所有位置都适用，包括 `{{if}}` 条件和辅助函数。
</Callout>

完整模板语言参见[个性化与表达式](/guides/expressions/)。

</Fold>

## 筛选列表 [#filtering-the-list]

联系人列表上方是筛选栏。**标签**、**分群**、**状态**和**营销活动**始终可见；打开并勾选值后，列表立即更新，旁边显示匹配数量。**添加筛选**可添加自定义字段条件，包括字段、包含/等于/开头为/结尾为和值；也可添加创建或更新日期范围、营销活动数量范围、地址验证判定、[邮箱服务商](#email-provider)，以及营销活动潜在客户标签页中的潜在客户状态和互动条件。每项启用的筛选以标签显示，可重新打开修改，或点击叉号移除；**清除**移除全部；**保存为分群**将当前条件转为[分群](/guides/segments/)。自由文本搜索、排序和列选择器仍在工具栏中。

自由文本搜索匹配名字、姓氏、电子邮件、公司和电话。输入的每个词都必须在其中一个字段匹配，因此 `Test Demo` 可找到名字 Test、姓氏 Demo 的联系人，`Demo Acme` 可找到 Acme 公司所有名为 Demo 的人。词语顺序任意，只使用前六个词。

## 选择显示列 [#choosing-columns]

工具栏中的**列**打开列选择器。电话、公司或自定义字段等可选详情列，如果当前列表没有任何联系人填写，会暂时让位，不显示整列短横线；一旦某个联系人有值就重新出现，选择器会标记**此处为空**。勾选显示，取消勾选隐藏；拖动已显示列旁的手柄可调整顺序。姓名始终是第一列。**自定义字段**下提供工作区所有自定义字段作为列，因此 Apollo 或 Clay 导入的列表，可以直接展示用于筛选优先级的行业、职位、员工人数，无需逐个打开联系人。

布局属于你自己：它保存在该工作区的个人账户设置中，会跟随你到其他浏览器；队友查看同一列表时保留自己的列。营销活动潜在客户标签页拥有独立布局，与联系人页面分开。选择器底部的**恢复默认**可还原标准列。

## 排序 [#sorting]

点击列标题按该列排序，再次点击切换方向。文本列，包括姓名、公司、电话和自定义字段，默认升序；日期和数量默认最新或最大优先。工具栏的**排序**菜单提供相同排序方式，还包括隐藏列、手机屏幕放不下的列、邮箱服务商，以及工作区所有自定义字段。

自定义字段按文本值排序。没有该字段或值为空的联系人，升序时集中在末尾，降序时在开头。排序随布局保存，下次打开仍保持离开时的方式。

</Fold>

## 邮箱服务商 [#email-provider]

每位联系人的头像上有一个小徽章，显示收件箱托管服务商徽标，例如 Google Workspace、Gmail、Microsoft 365、Outlook.com、Yahoo Mail、iCloud Mail、Zoho Mail 及其他 Warmbly 能识别的主机。悬停可查看名称。公司域名也支持：如果 Acme 邮件由 Google 托管，`dana@acme.com` 会显示为 Google Workspace。Warmbly 在后台读取域名邮件记录，通常在联系人添加后一分钟内完成，并实时更新列表。没有徽章表示尚未检查，或域名没有可识别的邮件服务器。

公司域名的联系人会以公司徽标替代姓名缩写，**公司**列也会在公司名旁显示徽标；没有公司资料时，显示邮箱所属域名。Gmail、Outlook.com、Yahoo 等个人邮箱保留姓名缩写。Warmbly Cloud 默认开启徽标，自托管实例默认关闭，除非运维人员开启，因为浏览器会从 DuckDuckGo 获取各徽标；参见[数据控制](/development/data-control/#outbound-calls)。

联系人页面和营销活动潜在客户标签页都会显示服务商。可以从**排序**按服务商排序，使用**添加筛选** > **邮箱服务商**筛选，包括**未知或尚未检查**，然后全选匹配项进行批量操作，例如加入活动、添加标签或导出，也可保存为分群。营销活动的 [ESP 匹配](/guides/campaigns/)使用同一数据，将潜在客户配对到相同服务商的发件邮箱。

</Fold>

## 选择数据行 [#selecting-rows]

勾选某行可选中它，勾选表头可选择目前已加载的所有行。联系人列表随滚动分页加载，因此表头复选框单独使用时只覆盖已加载到界面的内容。

匹配联系人数多于已加载数量时，表头下方出现**选择全部 N 个匹配项**。点击后，下一次操作使用整个筛选集合，无论涉及多少页；选择栏显示总数，而非已加载行数。之后取消勾选某行，只排除该联系人，计数同步变化。点击选择栏的**清除选择**或表头复选框，恢复无选择状态。

选中集合就是列表当前展示的范围：搜索、筛选、订阅分类，以及列表所限定的营销活动或分群都会缩小范围。改变其中任一项会清除选择，因为它不再代表最初选择的集合。超过 `250,000` 位联系人的选择会被拒绝，不会只应用一半；请添加筛选，分批处理。

所有批量操作都使用该选择，包括**编辑**、**分群**、**从分群移除**、**从营销活动移除**、**研究**、**验证**、**标记为可投递**和**删除**。**推送到 CRM**和**研究**有额外限制：推送会逐联系人调用 CRM 并等待，研究则每次消耗 AI 积分，因此两者每次仍最多 `500` 人。使用 [HubSpot 模式](/guides/hubspot/)或 [Pipedrive 模式](/guides/pipedrive/)的工作区，无需对相应 CRM 使用**推送到 CRM**：Warmbly 首次向联系人发信时，就会在那里创建记录。

营销活动潜在客户标签页和分群页面的**从联系人选择**选择器，也支持**选择全部匹配项**，因此整个搜索结果可以一步加入潜在客户或成员。

</Fold>

## 编辑单个联系人 [#editing-one-contact]

点击一行打开联系人面板。**详情**标签页可编辑姓名、电子邮件地址、公司、电话、订阅、营销活动、标签和自定义字段。在点击**保存**之前，不会提交任何修改；**放弃**将面板恢复为已存储值；存在未保存修改时，关闭前会确认。

可在这里修改邮箱地址，适用于导入时拼错地址或联系人迁往新域名。新地址会转为小写并移除显示姓名，而且必须未被占用；其他联系人已有的地址会被拒绝，因为合并两人的活动历史无法通过普通编辑撤销。新地址还会清除该联系人的[验证](/guides/deliverability/#address-verification)判定和平台对旧邮箱的全部观察，使后台检查在下一轮从头验证新地址；用于发件邮箱匹配的收件服务商也会根据新域名重新识别。已经发送的邮件仍对应旧地址，时间线按实际历史保留。

## 批量编辑联系人 [#editing-many-contacts-at-once]

在任意联系人列表、分群成员或营销活动潜在客户中勾选行，再点击选择栏的**编辑**，打开批量面板。可添加或移除营销活动、添加或移除标签、强制设置订阅状态，以及排队执行自定义字段操作，包括添加、编辑、删除和重命名。操作应用于每位所选联系人，输入字段键时会建议已有字段，也支持覆盖未加载页面的**选择全部匹配项**。

配置过程中不会应用任何修改。标题会说明选择来自哪个列表；按钮上方的**将应用**区域以标签列出全部待执行修改，可以逐项撤回，再点击应用。缺少字段键，或需要值却未填写的字段操作，会标记并跳过，不会以半成品提交。

## 标签 [#labels]

彩色标签用于分组和筛选联系人，例如 `Warm lead`、`Conference 2026`、`Enterprise`。同一套标签也用于[收件箱会话](/guides/unibox/#labels)，以及[表单](/guides/forms/)提交的归类。批量编辑、联系人详情、新建联系人对话框、筛选，以及导入和同步向导都使用同一个选择器。

选择器支持边输入边搜索。输入未匹配名称时，会提供**创建**，一步添加并选中。标签在所有显示位置都保留自己的颜色。

标签属于工作区，而非创建者；所有队友看到同一列表，并可用其标记联系人。**联系人 > 标签**列出每个标签及实时联系人数。可以在这里创建、重命名、改色、删除，或点击一行打开按该标签筛选的联系人列表。删除标签会保留联系人，只从联系人和收件箱会话上移除标签。

标签也驱动自动化：序列可在联系人推进时执行**添加标签**或**移除标签**，例如收到积极回复后自动加标签。**加入分群**和**从分群移除**对[分群](/guides/segments/)提供相同能力。

要将标签和活动转为可复用受众，可构建[分群](/guides/segments/)：保存一组基于联系人标签、字段、营销活动和互动的条件，然后一步浏览或加入营销活动。

</Fold>

| 表单 | 提交托管[表单](/guides/forms/) | 表单 |

新联系人也是一个事件。`contact.created` 会发送到你的 [Webhook](/guides/webhooks/)，也可用联系人字段和来源启动[自动化流程](/guides/automations/#triggers)。批量到达除外，它们保持静默：文件导入、表格同步，以及单次 API 请求添加超过 100 位联系人。

## 活动时间线 [#activity-timeline]

联系人的**活动**标签页是工作区共享、按最新优先排列的动态，汇集 Warmbly 了解的所有相关情况。每位有权查看联系人的成员都看到同一时间线，不受联系人或活动创建者影响。它包含每次活动邮件发送、打开、点击、回复和退信，并注明活动、步骤、主题和发件邮箱；还包括带分类意图的回复、送达能力和禁止发送事件、备注、会议，以及联系人生命周期：何时如何创建，每次加入或离开活动、添加或移除标签。

打开按事件逐次出现，而非每封邮件仅一条：另一设备上的第二次打开是独立行。打开显示阅读设备和邮件客户端，例如 **iPhone · Apple Mail 应用**或 **Gmail · 设备隐藏**；点击显示打开链接的设备和浏览器，已知时还显示城市与国家，参见[邮件通过何种方式打开](/guides/analytics/#how-an-open-was-read)。展开后可看操作系统、浏览器、完整位置，以及服务商图片代理抓取邮件时为何隐藏设备。概览标签页在**阅读方式**下汇总各客户端和设备的打开次数与最近时间。点击会指出链接：例如该行显示**点击了价格链接**；展开后展示链接文字、完整 URL、携带的 UTM 来源/媒介/活动/内容及浏览器。邮件中的每个链接独立跟踪，因此点击两个链接产生两行。机器而非人工产生的打开和点击，例如邮件隐私代理或投递时遍历全部链接的安全网关，带有**自动**标记；展开后会说明命中的规则。参见[链接跟踪与 UTM 参数](/guides/campaigns/#link-tracking-and-utm-parameters)。

筛选标签可缩小动态范围，包括**邮件**、**回复**、**送达**、**备注**、**会议**、**营销活动**和**生命周期**。搜索框匹配主题、活动、步骤、邮箱、标签和原因；对于点击，还匹配链接文字、URL 和 UTM 值。日期选择器限定时间。每行默认只占一行，点击展开后显示事件全部详情。队友和调度器写入时，动态实时更新。

标签页顶部是营销活动面板：针对联系人参与的每个活动，展示带有该联系人进度的流程、潜在客户状态，以及调度器下一步会做什么。下一步如何计算及状态含义，参见[营销活动](/guides/campaigns/)。

尚未添加流程步骤的活动也会显示，标记 **0/0 步骤**和**尚未开始**。添加步骤之前，进度条隐藏，联系人其他活动仍可查看。

</Fold>

## 商机与销售管道 [#deals-and-pipelines]

**销售管道**是一组有名称、有顺序的**阶段**，商机沿这些阶段推进。在管道页面可创建管道，新管道预设 `Open`、`Qualified`、`Won`，然后添加、重命名、改色和删除阶段；每阶段显示商机数量。阶段顺序就是看板从左到右的列顺序。

![所有销售管道的商机，顶部显示进行中和已赢单金额](/guides/deals.webp)

| 视图 | 行为 |
|------|----------|
| **表格**（默认） | 展示全部管道的商机，由服务器分页。进行中数量和管道金额等汇总是整个结果集的真实总和，不只统计已加载行 |
| **看板** | 单管道看板，每阶段一列，拖动卡片移动阶段。每列独立分页，表头数量来自服务器汇总 |

商机具有名称、阶段、金额和币种，默认 `USD`，以及预计成交日期和 `open`、`won` 或 `lost` 状态。关联联系人只读显示。

营销活动可通过**创建商机**和**移动商机阶段**自动创建并推进商机，使 CRM 无需手动录入也能保持最新。

### 将 HubSpot 用作 CRM 时 [#when-hubspot-is-your-crm]

在 [HubSpot 模式](/guides/hubspot/)下，这些页面中的商机、管道、任务和备注都是 HubSpot 记录：

- 每次修改先写入 HubSpot；HubSpot 拒绝时不保存，并显示其原因
- 管道、阶段和任务类型在 HubSpot 管理，因此这里拒绝编辑；HubSpot 中的变更几分钟内到达
- 仅存在于 Warmbly 的管道中的商机会从表格和看板隐藏，直到复制到 HubSpot 或切回原模式
- 任务类型使用 HubSpot 的四种：待办、电话、电子邮件、LinkedIn；标记赢单或输单会将商机移入对应的已关闭阶段
- 自动化流程和回复跟进写入的记录，通过同步队列到达 HubSpot

每条镜像记录都链接到自己的 HubSpot 页面。

### 将 Pipedrive 用作 CRM 时 [#when-pipedrive-is-your-crm]

[Pipedrive 模式](/guides/pipedrive/)以相同方式使用 Pipedrive 记录，并遵循其数据模型：

- 任务对应 Pipedrive 活动，任务类型使用公司自己的活动类型
- 赢单和输单是商机状态，因此标记赢单会保留原阶段
- 联系人面板显示人员负责人、标签和组织，指定标签可以停止营销活动

每条镜像记录都链接到自己的 Pipedrive 页面。

## 任务 [#tasks]

**CRM > 任务**是整个工作区的跟进清单，将每个人需要为联系人或商机做的事集中在一处。任务包含标题、说明、类型，默认 `Call`、`Email`、`Meeting`，也支持自定义类型；还包含截止日期、`low`、`medium`、`high` 或 `urgent` 优先级，`pending`、`in progress`、`completed` 或 `cancelled` 状态，以及个人、团队或无人负责的分配对象。

两种视图共用同一列表。**表格**是每字段一列的平铺列表；**按截止日期**分为逾期、今天、明天、本周、以后和无截止日期。两者都由服务器筛选、排序和分页，因此顶部的逾期、高优先级、待处理、进行中和已完成总数，覆盖整个匹配集合，而非已加载行。状态标签、搜索框、负责人/团队/类型分类和筛选弹层，都缩小同一集合。

点击行可编辑。每行标题前有两个控件：最左侧复选框用于选择批量操作，标题旁的方框则单独将任务标记完成。

### 批量选择任务 [#selecting-many-tasks]

勾选行选择任务；勾选表头选择目前已加载的全部行；在按截止日期视图中，也可勾选组标题选择整组。匹配任务多于已加载数量时，会出现**选择全部 N 个匹配项**，让下一项操作使用整个筛选集合，无论涉及多少页。之后取消勾选某行，只排除该任务，并更新计数。

选择代表建立时的筛选范围，因此修改任何筛选都会清除选择。超过 `50,000` 个任务的选择会被拒绝，不会只执行一部分；请增加筛选并分批处理。

选中行后，底部出现操作栏：**标记完成**、**状态**（四种任一）、**优先级**（四种任一）和**删除**；删除会先确认并显示数量。这样可清理无人需要的积压任务，无需逐个打开。如果要清理工作区在收紧下述设置之前积累的跟进任务，可搜索 `out_of_office`，勾选表头，再选择**全部 N 个匹配项**并一次删除。

### 从回复生成跟进任务 [#follow-up-tasks-from-replies]

回复到达时，Warmbly 可自动创建任务，让有回应的潜客进入跟进清单，而不只留在收件箱。任务分配给接收回复的邮箱所有者，24 小时后到期，标题包含意图和发件人，例如**跟进：来自 dana@acme.com 的积极回复**。

哪些回复创建任务，由你在**设置 > 发送 > 回复跟进**中决定。每条回复先分类，分类器能够区分人和机器：休假通知、服务台自动回复、退信和投递报告通过邮件头识别，不只依靠正文，因此从未提到休假的自动回复也能识别。

| 意图 | 默认是否创建任务 |
| --- | --- |
| 积极：感兴趣、想通话 | 是 |
| 问题：提出问题 | 是 |
| 中性：无法归入其他类别的人工回复 | 是 |
| 消极：不感兴趣 | 是 |
| 自动：休假、自动回复、退信 | 否 |

只有发件人成为联系人之后到达的邮件才创建任务。导入名单或通过 API 创建联系人，不会把邮箱里已有的旧邮件变成回复；对营销活动会话的回复始终算数。

这项规则推出之前，导入发件人可能使旧邮件创建任务并记录回复意图。Warmbly 在每次消费者启动时检查一次，但只有保存的标识符能关联到确切邮件，并且跟进还能关联到确切任务时，才撤回相应影响。没有这些关联的旧记录保持不动，即使发件人、主题或时间相似也不处理。关联任务只有仍待处理且无人编辑时才取消，每次取消写入审计日志。已经开始、编辑或完成的任务保持原样。临时清理错误会在检查继续推进前重试。

自动回复刻意默认关闭。休假通知不是需要跟进的工作，一周发送产生的通知就足以淹没真实回复。如果确实希望每条机器回复都创建任务，可勾选**自动**；也可取消不需要的人工类别。取消全部等同于关闭总开关。

分类不仅决定是否创建任务：自动回复绝不计为**收到回复后停止**或序列**已回复**分支的人工回复；其通知使用**检测到休假**偏好，而非**新回复**，因此静音其中一类不会静音另一类。

</Fold>

## 禁止发送 [#suppression]

被禁止发送的联系人不会再收到邮件。所有营销活动都会自动跳过已退订联系人；可以在详情标签页切换订阅状态，并按已订阅或已退订筛选列表。

收件人退订或回复要求停止、硬退信、垃圾邮件投诉，以及序列执行**退订**操作时，也会自动禁止发送。**禁止发送名单**标签页列出全部条目，支持手动添加地址或整个域名，以及解除条目；被禁止发送联系人的概览也会显示原因并提供同样操作。

这是收到负面信号后的稳妥默认处理：停止发送，避免继续累积退信和投诉。完整说明参见[退订与禁止发送](/guides/unsubscribe/)，相关信号参见[邮件送达能力](/guides/deliverability/)。
