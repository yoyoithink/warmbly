发件域名是邮箱地址中使用的域名。Warmbly 会自动列出这些域名，你可以在这里为每个域名设置跟踪主机，以及访客访问裸域名时的跳转目标。

![发件域名：各域名的邮箱、身份验证和跟踪主机](/guides/sending-domains.webp)

## 设置域名 [#set-up-your-domains]

<Steps>

<Step>

勾选列表中的域名，或勾选表头的复选框，选择当前显示的所有域名。

</Step>

<Step>

在底部操作栏中选择**跟踪域名**或**重定向**。

</Step>

<Step>

设置跟踪子域名，默认为 `link`，并填写访客应跳转到的网站。

</Step>

<Step>

除非邮箱供应商会代为配置，否则请在 DNS 服务商处添加对话框列出的 DNS 记录。

</Step>

</Steps>

## 使用须知 [#good-to-know]

- 无需手动添加域名：连接一个地址位于 `acme.io` 的邮箱后，`acme.io` 就会出现在这里。
- 跟踪主机会在其 DNS 记录尚未存在时先行保存。在记录可以正确解析之前，链接继续使用共享跟踪主机。
- 重定向会将访问裸域名的访客带到公司网站，让域名看起来是实际业务的一部分。
- 邮件不受影响：`MX`、SPF、DKIM 和 DMARC 记录与这些记录并存，这里的操作不会修改它们。
- 如果域名由邮箱供应商管理，Warmbly 可以代你设置转发或写入跟踪记录。

## 什么是发信域名 [#what-a-sending-domain-is]

浏览时使用的筛选、搜索和视图选项会[保存在浏览器标签页中](/guides/browsing/)，刷新页面或切换页面后仍然保留，并按用户和工作区分别保存。

发件域名是工作区中某个邮箱地址所使用的域名。Warmbly 根据邮箱本身生成列表，因此无需手动添加：连接一个地址位于 `acme.io` 的邮箱后，`acme.io` 就会出现在这里。

[导入邮箱](/guides/mailbox-import/#tracking-domains-and-root-redirects)时也可逐个域名配置相同选项，因此能够一次完成新域名的设置。

## 域名列表 [#the-domains-list]

每个域名显示以下内容：

| 列 | 内容 |
| --- | --- |
| 邮箱 | 工作区中使用该域名的邮箱数量，以及邮箱的托管服务商 |
| 身份验证 | 是否已发布 SPF、DKIM 和 DMARC，以及域名整体状态。参见[域名身份验证](/guides/deliverability/#domain-authentication) |
| 跟踪主机 | 该域名邮箱使用的[自定义跟踪域名](/guides/mailboxes/#custom-tracking-domain)、每个主机被多少邮箱使用，以及是否已验证 |
| 重定向 | 裸域名的访客会被发送到哪里，以及重定向是否已生效 |
| 供应商 | 如果工作区已连接的某个[邮箱供应商](/guides/mailbox-import/#import-from-an-inbox-vendor)账户持有该域名，则显示该账户、当前转发设置，以及其 API 能为该域名执行的操作 |

## 整个域名共用一个跟踪主机 [#one-tracking-host-for-a-whole-domain]

跟踪主机通常按邮箱设置。在域名页面，可以一步为该域名的所有邮箱设置同一个主机，也可以为所有邮箱清除设置。

Warmbly 会建议一个主机：优先使用该域名某个已验证邮箱正在使用的主机；否则使用 DNS 已指向此实例的主机，依次尝试 `link`、`links`、`track`、`t`、`click`、`go`、`email` 和 `trk`；再没有则使用 `link.<domain>`。建议值会附带需要添加的 `CNAME` 值。默认使用 `link`，因为收件人悬停查看链接时，它看起来像普通链接。

即使 DNS 记录尚不存在，主机也会保存。在记录解析成功之前，链接继续使用共享跟踪主机，因此不会失效。每小时运行的跟踪检查会自动验证该主机，此后的新发送就会切换到它。再次设置相同主机不会产生任何变化。

如果邮箱供应商账户持有该域名，并允许为其写入 DNS 记录，Warmbly 可以代为添加 `CNAME`；参见[由邮箱供应商管理的域名](#domains-held-by-an-inbox-vendor)。

## 批量设置域名 [#set-up-many-domains-at-once]

勾选列表中的域名，或使用表头复选框选择当前显示的所有域名；按住 Shift 可以勾选两次点击之间的所有行。选中后，底部会出现操作栏：

| 操作 | 作用 |
| --- | --- |
| **跟踪域名** | 打开下述设置对话框，并启用跟踪域名选项 |
| **重定向** | 打开下述设置对话框，并启用重定向选项 |
| **更多 > 立即检查 DNS** | 重新检查仍在等待 DNS 的所有跟踪主机和重定向，无需等待下一次自动检查 |
| **更多 > 复制待添加的 DNS 记录** | 复制所选域名仍需添加的全部记录，每行包含域名、类型、名称和值，可直接粘贴到电子表格或 DNS 服务商的批量导入中 |
| **更多 > 导出为 CSV** | 下载所选域名及其邮箱、身份验证、跟踪主机、重定向和供应商信息 |
| **更多 > 清除跟踪域名** | 确认后，将所选域名的全部邮箱恢复为使用共享跟踪主机 |
| **更多 > 移除重定向** | 确认后，停止各个重定向；供应商 API 允许时，也移除供应商转发 |

设置对话框为所有选中的域名提供一组基础值：

- **自有跟踪域名。** 子域名默认为 `link`，可以修改；对每个域名都设置为 `link.<domain>`，并应用到其全部邮箱。已验证跟踪域名的域名会保留原设置，除非勾选同时替换它们的选项。
- **将根域名重定向到你的网站。** 为所有选中的域名指定同一个网站。如果大多数域名已经跳转到同一网站，会预填该网站。

**逐域名修改**会打开所选域名列表，每个域名的跟踪主机和网站先按基础值填入。你可以覆盖其中任一项，为某个域名单独设置；取消勾选可以排除该域名；点击**重置**可恢复基础值。以后修改基础值时，会更新所有未单独修改的域名，保留已单独修改的域名。

对话框会预先说明有多少域名可由[邮箱供应商](#domains-held-by-an-inbox-vendor)代为设置，有多少需要你添加 DNS。每个域名分别采用最方便的方式：供应商 API 支持时，由供应商写入 `CNAME` 或转发根域名；否则先保存主机或重定向，等待 DNS，与单个域名设置时相同。完成后，对话框会列出仍需添加的 `CNAME` 记录，并提供**全部复制**；还会列出等待 DNS 的重定向，以及被拒绝的域名和原因。一个域名被拒绝不会影响其他域名，再次运行相同设置也不会改动已经正确配置的内容。

只要仍有域名使用共享跟踪主机，或尚未设置重定向，页面顶部就会显示数量，并提供**全部设置**，为这些域名打开同一个对话框。关闭提示后，它会保持隐藏，直到出现另一个需要设置的域名。

## 根域名重定向 [#root-redirects]

为冷邮件购买的域名，在有人将其输入浏览器时通常不会显示任何内容。收件人想核实发件人身份，或过滤器检查域名时，会看到空白页或错误，让它显得像一次性域名。重定向会将裸域名及其 `www` 的访客带到公司主网站，让域名呈现其真实用途：实际业务的一部分。

DNS 证明了两件事后，Warmbly 会通过当前实例的跟踪服务提供重定向：你控制该域名，以及其根域名指向这里。已关联 Warmbly Cloud 的自托管实例还可以[让 Cloud 提供重定向](#serve-it-from-warmbly-cloud)，无需在自己的服务器上配置。

### 设置重定向 [#set-one-up]

输入访客应跳转到的网站，例如 `https://yourcompany.com`。地址必须使用 `http` 或 `https`，且位于其他主机；不允许跳回同一域名或其 `www`。**包含 www**默认开启。Warmbly 随后会列出需要在 DNS 服务商处添加的记录：

| 用途 | 类型 | 名称 | 值 | 验证是否必需 |
| --- | --- | --- | --- | --- |
| 所有权 | `TXT` | `_warmbly.<domain>` | `warmbly-verify=<value>` | 是 |
| 根域名 | `A` 和 `AAAA` | `<domain>` | 列出的跟踪主机公网地址 | 是 |
| www | `CNAME` | `www.<domain>` | 跟踪主机 | 否 |

所有权验证值专属于此实例中你的工作区与该域名的组合，因此其他工作区发布的记录不能证明你的所有权。[Google Workspace 管理员授权](/guides/mailbox-import/#prove-the-workspace-controls-the-domain)也接受同一条记录作为证明，因此域名已经为其中一项发布过该记录时，另一项无需额外记录。

如果跟踪主机没有可列出的公网地址，根域名记录会改为显示指向跟踪主机的 `ALIAS`。无论是否列出地址记录，支持根域名 `ALIAS`、`ANAME` 或扁平化 `CNAME` 的服务商都可以用它们代替地址记录：Warmbly 比较的是根域名最终解析出的地址。

重定向要生效，根域名必须指向这里，因此根域名已经用于托管网站的域名不适合此方案。邮件不受影响：`MX`、SPF、DKIM 和 DMARC 记录与这些记录并存，这里的操作不会修改它们。

### 验证 [#verification]

当 `TXT` 记录和根域名记录都已就绪时，重定向通过验证。`www` 记录是可选的；没有它时，只有裸域名会重定向。

DNS 验证只能证明域名指向这里，不能证明访客实际得到重定向：Warmbly 前面的代理仍可能代为响应。因此 DNS 验证通过后，Warmbly 会像访客一样通过 `http` 和 `https` 打开域名；两者都跳转到你的网站时，重定向显示为**已生效**。如果其他服务代替 Warmbly 响应，则显示**未能触达访客**，说明响应方，并计入**需要处理**。另外两种情况会保留**已生效**并附说明，因为检查无法将它们与正常重定向区分：检查完全没有收到响应，或跟踪服务仍在接收刚通过验证的重定向配置。参见[访客没有收到重定向时](#when-visitors-do-not-get-it)。

Warmbly 会在保存后立即检查记录，也会在点击**立即检查**时检查，并自动定期检查：等待验证的前 14 天每 10 分钟一次，之后每 6 小时一次；已验证但未能触达访客时，自验证之日起的 14 天内每 10 分钟一次，之后每 6 小时一次；正常生效后每 6 小时一次。只有明确发现记录已不存在或指向其他位置时，已验证的重定向才会停止。DNS 查询失败或超时会保持运行，访问测试失败也一样。

再次保存重定向以修改目标网站或 `www` 设置时，会保留同一个所有权验证值，因此之前添加的 `TXT` 记录仍然有效。

### 访客会看到什么 [#what-visitors-get]

访问该域名，以及启用时的 `www`，会返回指向所填网站的 `302` 响应，可缓存五分钟。原请求路径不会带到目标网站：每次访问都会落到同一个地址。刻意采用临时重定向，是为了让修改或删除在几分钟内影响所有访客，避免浏览器长时间保留旧结果。

HTTPS 需要该域名的证书。Warmbly Cloud 会在首次访问时按需签发，并且只为重定向已经验证的域名签发，包括代已关联实例提供重定向的域名。使用随附 Caddy 安装的自托管实例也会如此。如果使用运维人员自己的代理，该代理必须将域名路由到跟踪服务，并持有对应证书；[自定义跟踪域名](/guides/mailboxes/#custom-tracking-domain)中介绍了同样的注意事项。

### 访客无法获得重定向的情况 [#when-visitors-do-not-get-it]

重定向标签页会说明检查发现了什么，并为常见原因给出修改建议：

| 检查结果 | 常见原因 | 处理方式 |
| --- | --- | --- |
| 其他 Web 服务器响应，通常是 `404`；能够识别时，标签页会显示其名称，如 Traefik、nginx、Caddy 或 Apache | Warmbly 前面的代理只响应已经配置的主机名 | 在配置跟踪主机的同一位置添加该域名，因为跟踪主机已经能访问 Warmbly。标签页会给出 Traefik、Coolify、Dokploy、nginx 和 Caddy 的具体改动 |
| 跟踪服务已响应，但无法识别域名 | 代理转发请求时使用了不同的主机名 | 透传原始 `Host` 请求头，例如在 nginx 中使用 `proxy_set_header Host $host;` |
| 域名跳转到其他位置 | 其他重定向先响应，例如代理规则，或域名/DNS 服务商处的转发 | 移除该重定向 |
| `https` 没有有效证书 | 代理没有该域名的证书 | 将域名加入代理配置，以便获取证书 |
| 端口 80 或 443 没有响应 | 防火墙阻挡，或没有服务监听 | 开放端口，并让代理为该域名提供服务 |

如果检查完全没有收到响应，重定向仍显示**已生效**，同时提示你自行打开域名：某些网络不允许服务器访问自己的公网地址，因此检查无法将这种情况与正常重定向区分。DNS 验证后的第一分钟，跟踪服务尚在接收重定向配置时也一样；标签页会说明情况，并在 10 分钟内再次检查。

如果代理由你自行运行，应在配置跟踪主机的同一位置修改。使用 Traefik 时，扩展已经将跟踪主机路由到 Warmbly 的路由器规则：

```text
Host(`t.example.com`) || Host(`acme.io`) || Host(`www.acme.io`)
```

使用 nginx 时，将这些名称加入代理跟踪服务的 server 块，保留原始主机名，并配置证书：

```nginx
server_name t.example.com acme.io www.acme.io;
proxy_set_header Host $host;
```

在已关联 Warmbly Cloud 的自托管实例中，同一标签页也提供一个选项，让你跳过这些配置，[由 Warmbly Cloud 提供重定向](#serve-it-from-warmbly-cloud)。

### 由 Warmbly Cloud 提供服务 [#serve-it-from-warmbly-cloud]

在[已关联 Warmbly Cloud](/guides/warmbly-cloud/)的自托管实例中，重定向有**提供服务的位置**选项：**此服务器**或 **Warmbly Cloud**。Cloud 使用自己的跟踪服务提供重定向和证书，因此你的服务器无需为该域名设置任何路由。只需将根域名指向 Cloud 列出的地址，并发布它给出的所有权验证值；该值属于 Cloud，与当前实例的值不同。

- 尚未关联的实例可直接在这里关联：在**提供服务的位置**下，或“未能触达访客”的修复提示中，点击**连接 Warmbly Cloud**，即可显示需要在 Warmbly Cloud 上批准的代码；批准后会继续将重定向交由 Cloud 提供。如果多个重定向未能触达访客，页面顶部也会提供一次处理全部的相同入口。
- 实例保持关联时，控制台为新重定向默认选择 Warmbly Cloud；API 则仍默认使用当前实例，除非 `served_by` 指定其他位置。批量设置也有同样的选择；在那里，已有重定向的域名会保留原服务位置，除非你明确选择服务器。移动已生效的重定向前，控制台会要求确认。
- Cloud 按上述相同计划检查记录并访问域名。当前实例显示 Cloud 的判定、记录和最近访问结果，并按自己的计划及点击**立即检查**时重新读取。
- 在当前服务器和 Cloud 之间移动重定向会改变根域名记录，因此已生效的重定向会暂停，直到新记录就绪。控制台会在移动前询问。
- 只有域名、目标网站和 `www` 设置会发送到 Cloud。参见[数据控制](/development/data-control/#outbound-calls)。
- 保存时如果无法访问 Cloud，重定向会保留为等待 Cloud，待其响应后立即发送。如果 Cloud 仍在提供某个重定向，但当前实例已没有任何工作区持有它，例如工作区已删除，该重定向会在大约半小时内释放。
- 断开实例连接，或从 Warmbly Cloud 解除关联，会停止 Cloud 为它提供的全部重定向。每个重定向随后都会说明情况，并可以移回当前服务器。如果关联仍然有效，但 Cloud 上已没有某个重定向，下一次检查会将其重新创建。

### 限制 [#limits]

- 工作区必须在该域名下拥有邮箱。
- 不接受共享邮件服务商的域名，例如 `gmail.com` 或 `outlook.com`。
- 同一实例中的一个域名只能由一个工作区使用重定向。某个工作区的域名重定向已验证期间，另一个工作区为同一域名创建的重定向会以 `domain_redirect_taken` 被拒绝，无法通过验证。
- 实例需要配置跟踪主机（`TRACKING_DOMAIN`），因为实际响应由跟踪服务提供。未配置时不提供重定向，已关联实例通过 Warmbly Cloud 提供的重定向除外。
- Warmbly Cloud 最多为一个已关联实例提供 200 个重定向。

## 由邮箱供应商管理的域名 [#domains-held-by-an-inbox-vendor]

从[邮箱供应商](/guides/mailbox-import/#import-from-an-inbox-vendor)购买的域名，DNS 通常也托管在该供应商处，而且大多数供应商可以自行转发域名。如果工作区已连接的某个供应商账户持有该域名，页面会显示供应商，并提供两种快捷操作，替代上述 DNS 配置工作：

- **通过供应商转发。** 输入目标网站，Warmbly 会请求供应商将根域名转发过去。无需在 DNS 服务商处添加任何记录，当前实例也不负责提供服务。目标网站遵循与重定向相同的规则：必须是位于其他主机的 `http` 或 `https` 地址。清空网站后，会在供应商允许的情况下移除转发。
- **通过供应商写入跟踪记录。** 在该域名下选择一个跟踪主机，Warmbly 会在供应商处写入其 `CNAME`，再为该域名的每个邮箱设置该主机。这是 Warmbly 唯一会写入的记录。同名同类型的记录会被替换；供应商自行管理的记录会保持不动，并拒绝写入。

各供应商 API 支持的操作：

| 供应商 | 转发 | 移除转发 | 跟踪 `CNAME` |
| --- | --- | --- | --- |
| InboxKit | 支持 | 支持 | 支持 |
| Zapmail | 支持 | 支持 | 支持 |
| Cheap Inboxes | 支持 | 支持 | 支持 |
| Maildoso | 支持 | 支持 | 不支持 |
| ScaledMail | 支持，但以请求形式提交，稍后由 ScaledMail 工作人员应用 | 支持 | 不支持 |
| Mailforge | 支持 | 不支持 | 不支持 |
| Infraforge | 支持 | 不支持 | 不支持 |

Mailforge 和 Infraforge 每次修改 DNS 都会替换域名的整套记录，因此 Warmbly 不会在这些服务中写入记录，以免一次写入删除域名的邮件记录。请改在其控制台中添加跟踪 `CNAME`。

[邮箱导入](/guides/mailbox-import/#tracking-domains-and-root-redirects)会自动采用这些方式。导入时选择的根域名重定向，如果域名由供应商账户持有且支持转发，就使用供应商转发；否则使用当前实例提供的重定向。导入时选择的跟踪主机，如果供应商支持，就通过其写入 `CNAME`；否则等待你添加。

供应商域名列表使用工作区自己的 API 密钥读取，仅查询有效连接，并缓存五分钟。无法响应的供应商会被暂时排除，因此其域名在恢复响应之前不会显示供应商信息。

## 导出时一并迁移的内容 [#what-travels-in-an-export]

重定向会随[工作区导出](/guides/workspace-export-import/)迁移。导入后处于未验证状态，直到目标实例自己的检查确认两类记录均已就绪，才开始提供服务。原先由 Warmbly Cloud 为来源实例提供的重定向，导入后改为由目标实例自身提供。所有权验证值属于签发它的实例上的工作区，因此目标实例会列出自己的值：请将新值发布到 `TXT` 记录，并将根域名指向目标实例。跟踪主机属于每个邮箱的设置，随邮箱迁移；导入后同样未验证，当 `CNAME` 指向目标实例后，其每小时检查会完成验证。通过供应商设置的转发保留在供应商处，不受迁移影响。
