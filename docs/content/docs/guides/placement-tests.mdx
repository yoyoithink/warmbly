投递位置测试会从你的真实邮箱发送邮件副本到不同服务商的种子收件箱，然后显示每份副本最终进入了哪里：主收件箱、Gmail 标签页、垃圾邮件文件夹，或始终未收到。

## 运行投递位置测试 [#run-a-placement-test]

<Steps>

<Step>

打开控制台中的**投递位置测试**，新建测试。

</Step>

<Step>

选择发件邮箱和种子面板。发件邮箱必须已连接、处于启用状态，且不能是种子收件箱。

</Step>

<Step>

选择要测试的营销活动步骤，或填写主题和正文，使用临时模板。

</Step>

<Step>

选择发送节奏：**间隔发送**为默认方式，20 个种子约需 20 分钟；**快速发送**不到 3 分钟。

</Step>

<Step>

各个种子收件箱同步到邮件副本后，测试页面会陆续显示结果。

</Step>

</Steps>

## 使用须知 [#good-to-know]

- 每份副本都是真实发送，会计入发件邮箱的每日营销活动发送限额。
- 发送后 120 分钟内仍未发现的副本，会标记为始终未到达。
- 托管产品的付费套餐默认每月可在共享面板免费测试 `40` 次，此后每次 `25` 积分。试用期有 `3` 次。
- 使用自己的种子收件箱测试，既不计入测试额度，也不消耗积分。
- 一次测试可能只是偶然波动。应观察多个测试和服务商之间反复出现的模式。

## 投递位置测试的用途与使用权限 [#what-a-placement-test-is-and-who-can-run-one]

浏览时使用的筛选、搜索和视图选项会[保存在浏览器标签页中](/guides/browsing/)，刷新页面或切换页面后仍然保留，并按用户和工作区分别保存。

投递位置测试帮助你在潜在客户收到邮件之前回答一个问题：这个邮箱发送这封邮件时，会落到哪里？Warmbly 从你的真实邮箱向覆盖不同服务商的一组种子收件箱发送副本，再读取各个种子邮箱，查看副本进入了主收件箱、Gmail 标签页、垃圾邮件文件夹，还是始终未收到。

测试位于控制台的**投递位置测试**中。查看结果需要**查看分析数据**权限；启动或取消测试需要**发送营销活动**权限，因为测试会从真实邮箱发送真实邮件。

## 测试衡量的内容 [#what-a-test-measures]

每份副本会得到以下一种判定：

| 判定 | 含义 |
|---------|---------|
| 收件箱 | 主收件箱 |
| 推广 | Gmail 的“推广”标签页，冷邮件在这里容易被忽略 |
| 其他标签页 | Gmail 的其他标签页：动态、社交或论坛 |
| 垃圾邮件 | 垃圾邮件文件夹 |
| 始终未到达 | 副本已离开发件邮箱，但发送后 120 分钟内未在种子邮箱中发现 |
| 失败 | 副本从未离开发件邮箱，例如工作节点离线 |
| 已取消 | 该副本发送之前，测试已取消 |

各项比率以**已投出**且获得判定的副本为分母，包括收件箱、两类标签页、垃圾邮件和始终未到达。失败和已取消的副本不计入分母，因为它们无法说明接收端的情况。收件箱到达率只计算主收件箱，因此进入“推广”的副本会拉低这一比率。

结果按服务商类别拆分：Gmail、Google Workspace、Outlook.com、Microsoft 365、Yahoo Mail、iCloud、Zoho 等。Gmail 与 Google Workspace 分开，Outlook.com 与 Microsoft 365 也分开，因为个人版和企业版服务使用不同过滤机制，同一封邮件在其中一方表现良好，在另一方可能很差。

## 测试的运行方式 [#how-a-test-runs]

### 测试副本与营销活动实际发送的邮件一致 [#the-copy-is-the-one-your-campaign-sends]

每份副本按营销活动发送时的方式和顺序渲染：为示例潜在客户处理合并字段和随机文本语法，再处理该客户的 AI 内容块、表单链接、邮箱签名、退订行、`List-Unsubscribe` 请求头、附件，以及开启跟踪时的打开像素和改写链接。测试省略的只有真实对话才涉及的内容：接入之前邮件的会话、A/B 变体选择，以及营销活动的抄送和密送。

测试营销活动步骤时，默认按活动中的第一位潜在客户渲染，除非另选联系人。使用 Warmbly Cloud 面板时，默认改用占位联系人，只有你主动选择联系人时，其详情才会离开当前实例，同时会省略 AI 内容块。步骤会在测试开始时复制，因此中途编辑不会改变后续种子收到的内容。跟进步骤如果接在前一个步骤的会话下，就没有独立主题；测试会使用所接续步骤的主题，不添加 `Re:`。手动填写的模板按新营销活动的方式渲染，默认启用工作区退订行和退订请求头。

测试不会为了识别邮件而添加任何内容：没有主题标记、特殊请求头或隐藏文字。每份副本通过 Message-ID 找回，因此种子邮箱过滤器判断的内容，正是潜在客户实际会收到的内容。

测试还会运行与活动编辑器相同的[内容检查](/guides/campaigns/#content-checks)，并在结果旁显示评分和问题。

### 从真实邮箱逐封发送 [#sent-one-at-a-time-from-the-real-mailbox]

副本逐封发送，每封都是从所选邮箱发出的独立邮件，经过该邮箱通常使用的工作节点，并在服务商之间交替发送，避免某一个服务商收到突发流量。副本间隔由测试节奏决定：

| 节奏 | 副本之间的间隔 | 20 个种子的发送时间 |
|------|--------------------|-------------------------|
| **间隔发送**（默认） | 约 60 秒，与营销活动发送方式相同 | 约 20 分钟 |
| **快速发送** | 约 8 秒 | 不到 3 分钟 |

两种模式都会使每次间隔上下浮动最多三分之一。运维人员可以调整间隔发送的基础间隔；快速测试使用两种间隔中较小的一个。快速方式适用于需要立即得到答案的场景，例如修复 DNS 记录之后。每个种子同步到副本后就会显示结果，通常在发送后数分钟内。[监控器](#campaign-placement-monitors)安排的定期测试始终使用间隔发送。

发件邮箱自身保存的每份探测邮件副本不会进入你的统一收件箱。

### 在种子邮箱中查找测试邮件 [#found-in-the-seeds-mail]

种子收件箱是由 Warmbly 同步的普通已连接邮箱。邮件进入种子邮箱时，系统通过 Message-ID 匹配副本，再根据它到达时所在的文件夹和 Gmail 标签给出判定。查看测试的所有人都会实时看到逐份出现的结果。

发送后 120 分钟内未发现的副本会标记为**始终未到达**。Warmbly Cloud 面板的副本额外等待半小时，因为结果还需要从云端返回。所有副本都有判定后，测试结束。如果没有任何副本成功发出，测试以**失败**结束，并显示原因。

## 种子邮箱组 [#seed-panels]

每次测试使用一个种子收件箱面板：

| 面板 | 种子归属 | 可用条件 |
|-------|-------------|-----------|
| **共享面板** | 实例运维人员为所有工作区提供的面板，API 中为 `instance`。在托管产品中，这是 Warmbly 自有面板 | 运维人员已添加种子收件箱时可用。自托管实例由管理员从管理面板添加 |
| **你的种子收件箱** | 在自己工作区中标记为种子的邮箱，API 中为 `workspace` | 至少标记一个后可用 |
| **Warmbly Cloud 面板** | Warmbly Cloud 的面板，API 中为 `cloud` | 仅在[已关联 Warmbly Cloud](/guides/warmbly-cloud/#placement-tests-on-warmbly-clouds-seed-panel)的自托管实例中可用 |

页面会显示每个面板的种子数量和服务商组成；面板不可用时，也会说明原因。

实例面板和 Warmbly Cloud 面板的地址会遮蔽显示，例如 `a***@gmail.com`，防止共享面板的地址被枚举并加入发件人的允许名单。你自己的种子收件箱显示完整地址。

每次测试默认最多使用 20 个种子，运维人员可以调整。种子按服务商类别轮询选择，因此即使测试规模较小，也会覆盖面板中各类服务商。以下两类种子始终跳过：

- **与发件人同域名的种子。** 同一租户内两个邮箱之间的邮件，会绕过测试原本希望观察的大部分过滤。因此，位于 `acme.com` 的种子不会收到由 `sales@acme.com` 发起的测试。
- **发件邮箱本身。**

排除后如果没有剩余种子，测试会以 `placement_no_seeds` 被拒绝，不发送任何邮件。

### 仅测试部分服务商 [#testing-only-some-providers]

在共享面板和 Warmbly Cloud 面板上，面板下方的**服务商**标签可将测试范围缩小到所选服务商。例如回复在 Outlook.com 和 Microsoft 365 上突然减少时，可以只测试这两类。测试随后仅从这些服务商选择种子，仍然轮询分配，也不显示其地址。保留**全部**选择即可覆盖面板中的所有服务商。

### 选择接收测试副本的自有种子邮箱 [#choosing-which-of-your-seeds-get-a-copy]

在**你的种子收件箱**面板中，可以自行选择测试发送到哪些种子，而不由 Warmbly 自动按服务商分散。例如只选择准备手动打开检查的 Gmail 和 Outlook.com 种子。面板下方的选择器列出种子收件箱及其服务商，每个服务商标签可一次选中该服务商的全部种子。不选择任何种子时，按通常方式自动选择。

你选中的每个种子都会收到副本：常规的每次测试种子数量上限不适用于手动选择。若发件邮箱当日剩余额度不足以覆盖全部选项，系统会拒绝测试并显示数量，不会默默跳过一部分。与发件人同域名的种子会显示为灰色并跳过，未连接的种子不可选择。只有自己的面板支持逐个选择种子；共享面板和 Warmbly Cloud 面板的地址是遮蔽的，因此只能选择服务商。

## 自有种子测试邮箱 [#your-own-seed-inboxes]

工作区中任何已连接邮箱都可以成为种子收件箱。在投递位置测试页面的**种子收件箱**标签页中进行标记，需要**管理邮箱**权限，每个工作区最多 50 个。

合适的种子收件箱应像陌生人的邮箱一样工作：

- **使用与发件邮箱不同域名的独立地址。** 如前所述，与发件人同域名的种子会被跳过。
- **使用主流服务商的个人账户。** 一个 Gmail、一个 Outlook.com 和一个 Yahoo 账户，可以覆盖大多数个人邮箱过滤机制。再添加一个位于你另一个域名下的 Google Workspace 或 Microsoft 365 邮箱，以观察企业邮箱情况。
- **不要人为干预。** 不要将发件人添加到联系人，不要把其邮件标记为非垃圾邮件，也不要修改过滤规则。每一种操作都会教会服务商“你希望收到这些邮件”，而潜在客户的邮箱恰恰还没有学到这一点。

标记为种子后，Warmbly 会改变对该邮箱的处理方式：

- **不参与预热。** 标记时会关闭预热，取消标记之前，启动预热会以 `mailbox_is_seed` 被拒绝。若种子与预热池交换邮件，它就不再是池中各发件人的陌生收件人。
- **不发送营销活动邮件。** 它会从所有营销活动的发件邮箱中排除，也不能自行发送投递位置测试。
- **为测试进行同步。** 它获得较大的每日同步额度，避免多个测试的副本被延迟到 120 分钟窗口之后，并且不导入历史邮件。收到的副本像其他同步邮件一样存储。

实例面板中的邮箱不能同时成为你的种子；邮箱仍在发送测试时，也不能标记为种子。取消种子标记后，它恢复为普通邮箱，但预热仍保持关闭，直到你主动启动。

## 开始测试 [#starting-a-test]

测试需要发件邮箱、面板和待发送内容。发件邮箱必须已连接并启用，且本身不能是种子收件箱。

- **测试营销活动步骤**：选择营销活动和步骤。系统会填入步骤主题和正文，并应用该活动的退订行、跟踪和附件。如果希望合并字段和 AI 内容块使用第一位潜在客户以外的人，请另选联系人。
- **测试临时模板**：填写主题和正文。适合在草稿变成营销活动之前先行测试。

取消正在运行的测试，会停止尚未发送的副本。已发送副本仍会继续分类，因此已取消测试也会显示它们最终到达的位置。

### 跟踪 [#tracking]

| 选项 | 副本携带的内容 |
|--------|----------------------|
| 跟随营销活动 | 使用活动自己的打开和点击跟踪；临时模板不带跟踪。这是默认选项 |
| 开启 | 打开像素和改写链接 |
| 关闭 | 两者都不带 |
| 对比 | 向同一批种子运行两个关联测试，一个不带跟踪，一个带跟踪 |

对比测试会向每个种子连续发送两个版本，每个种子的顺序随机，使两份邮件在同一时间面对同一过滤器。两组结果的差异反映跟踪像素和改写链接带来的影响。每个种子收到的两个版本文字完全相同：该种子的副本只渲染一次，解析随机文本语法、合并字段、AI 内容块、表单链接、签名和退订行；带跟踪的版本只额外添加像素并改写链接。不同种子仍可以抽到不同的随机文本，就像不同潜在客户一样。如果某个种子的副本无法渲染，两个版本都不会发送给它。对比计为两次测试，发送的副本数量也翻倍。纯文本营销活动不携带跟踪，因此其**开启**和**对比**选项会以 `placement_invalid_tracking` 被拒绝。

## 测试费用 [#what-a-test-costs]

**每份副本都算发件邮箱的一次发送。** 它会计入邮箱的每日营销活动限额，邮箱的营销活动也会在当日预算和最小发送间隔中考虑这些发送。向 20 个种子测试会占用当天 20 次发送，对比则占用 40 次。尚未发出的副本也已预留当天额度，因此测试发送期间，营销活动不能消耗这些额度。如果邮箱剩余额度不足以完成整个测试，系统会减少种子数量；每次测试不足五个种子时，会以 `placement_daily_budget` 拒绝，因为更小的测试只会产生噪声。请选择仍有余量的邮箱，或在当天营销活动开始前测试。

一个邮箱同一时间只运行一个测试：在当前测试的全部副本发出之前，同一邮箱的新测试会以 `placement_sender_busy` 被拒绝。

### 免费测试次数与积分 [#free-tests-and-credits]

托管产品的每个工作区每月都可在共享面板获得免费测试：

| 工作区 | 每月免费次数 | 用完之后 |
|-----------|----------------------|------------|
| 免费试用 | `3` | 等待下个月或升级 |
| 付费套餐 | `40` | 每次 `25` [积分](/guides/ai-credits/) |

这些是默认值，运维人员可以调整次数和价格。月份按 UTC 日历月计算。跟踪对比计为两次测试。投递位置测试页面会显示已使用的免费次数，新建测试对话框会说明本次使用第几次免费测试。

**未同意价格之前，付费测试绝不会开始。** 免费次数耗尽后，对话框显示测试费用和余额，必须勾选**为本次测试支付 25 积分**才能开始；按钮也会重复显示价格。API 使用 `max_credits` 表达相同授权，即你同意支付的最高积分。价格超过该值时，例如等待期间最后一次免费测试被队友使用，会以 `placement_quota_exceeded` 拒绝并说明价格，不扣任何积分。积分与其他消耗一样，先使用月度额度，再使用充值积分，并遵循你的[消耗限额](/guides/ai-credits/#usage-and-spend-controls)。扣费在积分历史中记录为**投递位置测试**。

- **未发出任何副本的测试会退款。** 如果付费测试没有任何副本离开发件邮箱，例如工作节点离线，或首份副本发送前就取消，积分会退回原来源，记录为**投递位置测试退款**，也不再计入消耗限额。扣费后月度额度已经重置的积分不会退回，因为它们本来也会随重置过期。以这种方式结束的免费测试也不会占用免费次数。
- **只剩一次免费测试时进行对比**，一半使用免费次数，另一半付费。
- **监控器绝不消耗积分。** 定期测试与其他测试一样使用免费次数，用完后会记录原因，并在一天后再试。
- **试用账户不能付费购买测试。** 积分属于付费套餐，因此试用账户需要等待下个月。

使用自己的种子收件箱测试，既不计入测试额度，也不消耗积分。自托管实例完全不对自己的面板计量。使用 Warmbly Cloud 面板时，消耗的是实例所关联的 Warmbly Cloud 工作区的免费次数；此面板不提供通过积分购买额外测试的方式。

## 营销活动投递位置监测 [#campaign-placement-monitors]

监控器按计划重新测试运行中的营销活动，让投递位置下降在回复率下降之前就被发现。从营销活动中设置。

| 设置 | 默认 | 范围 |
|---------|---------|-------|
| 间隔 | 每 `7` 天 | `1` 至 `30` 天 |
| 面板 | 实例面板 | 实例面板、你的种子收件箱或 Warmbly Cloud |
| 提醒阈值 | 收件箱到达率低于 `70%` | `0` 至 `100` |
| 提醒时暂停 | 关闭 | 开启或关闭 |

每次运行会测试活动中第一个同时具有主题和正文的邮件步骤，按第一位潜在客户渲染，并使用活动自身的跟踪设置。各次运行会轮换使用活动的发件邮箱，每次一个，因为每个邮箱的信誉不同，目标正是找出表现下滑的邮箱。新建或重新启用的监控器会在约五分钟内运行首次测试。

监控器只测试正在运行的营销活动。如果无法启动，例如活动暂停、没有已连接邮箱、额度用尽，或邮箱当日余量不足，监控器会记录原因，并在一天后重试，而不是等待完整监控间隔。其测试与其他测试一样，计入月度测试额度和邮箱每日限额。

**监控测试结果低于阈值时**，工作区内所有可以查看营销活动的成员都会收到**投递位置监控提醒**，包含结果和测试链接。开启**提醒时暂停**后，营销活动还会自动暂停，并在活动日志中说明原因。与所有[自动暂停](/guides/campaigns/#auto-pause-guardrails)一样，它不会自行恢复：请先查明变化原因，再手动启动活动。

</Fold>

## 批量测试邮箱集群 [#testing-a-fleet-with-batches]

单次测试回答一个邮箱的投递位置。拥有数百甚至数千个发件邮箱时，问题变成了：整个邮箱集群是否健康？如果不健康，问题出在单个邮箱、某个域名，还是某类服务商？**投递位置批量测试**从多个邮箱运行相同测试，并统一分析结果。可以在投递位置测试页面点击**新建批次**，在营销活动设置中点击**测试发件邮箱池**，或从覆盖率提示中点击**测试尚未测试的邮箱**。

批次中的每个邮箱都会运行独立的普通投递位置测试，并保留各自结果，因此上文关于运行方式、费用和结果解读的说明都适用。批次额外提供共享设置、统一进度视图、跨邮箱集群的分组结果，以及一个取消按钮。

### 选择发件邮箱 [#choosing-the-senders]

| 发件邮箱选择方式 | 选择范围 |
|---------|-----------------|
| **选择邮箱** | 手动勾选的邮箱，API 中为 `sender_account_ids` |
| **营销活动的发件邮箱** | 活动实际使用的全部发件邮箱，与调度器使用同一集合，API 中为 `sender_scope.type` 的 `campaign` |
| **全部邮箱** | 工作区中的所有邮箱，API 中为 `sender_scope.type` 的 `workspace` |

营销活动发件邮箱和全部邮箱可以进一步按服务商（Google Workspace、Microsoft 365、SMTP 等）、发件域名、邮箱标签筛选，也可限制为最近指定天数内没有完成投递位置测试的邮箱。默认排除未连接邮箱，除非选择包含；手动勾选的邮箱始终保留，轮到它时如果无法发送，会按名称报告原因。种子收件箱绝不参与发送。

批次开始时，服务器会解析并记录发件邮箱名单。之后新加标签或新加入活动的邮箱不会进入已经运行的批次；之后从活动移除的邮箱也不会退出该批次。

### 抽样 [#sampling]

测试每个邮箱最全面，但每个邮箱都会消耗一次测试和当日发送额度。抽样只测试集群的一部分：

| 抽样方式 | 结果 |
|--------|--------|
| **全部** | 所有选中的邮箱 |
| **随机** | 随机选取指定数量的邮箱 |
| **百分比** | 选择相应比例的邮箱，向上取整。**分散到各服务商**按各服务商在集群中的占比分配样本，因此对 800 个 Google Workspace、400 个 SMTP 和 147 个 Microsoft 365 邮箱抽取 10% 时，分别选择 80、40 和 15 个，而非完全随机抽取 135 个 |
| **按域名** | 每个发件域名最多选择指定数量的邮箱，避免大型域名占据过多样本 |
| **按服务商** | 每个发件服务商最多选择指定数量的邮箱 |

### 批次的运行方式 [#how-a-batch-runs]

一个批次可以包含数千个邮箱，但同一时间只有少量邮箱发送。某个邮箱发完测试的全部副本后，Warmbly 才会启动下一个邮箱；每个工作区最多同时有 `20` 个批次邮箱在发送，每个批次每分钟最多启动 `10` 个邮箱，整个实例最多同时运行 `200` 个批次邮箱，避免共享种子面板收到突发流量。这三项都可以由运维人员调整。所有批次测试都使用间隔发送，快速方式仅适用于单次测试。连续启动会在不同发件服务商和域名之间轮换，不会接连处理同一服务商的邮箱。批次中的邮箱总数不会影响并发数量；运维人员设置的批次规模上限默认是 `10,000`，仅用于保护实例。

批次开始时不会预留任何额度。轮到每个邮箱时，才按与单次测试完全相同的方式检查其每日限额、最小间隔、连接、工作节点及工作区风险状况。因此，批次逐步处理邮箱集群时，营销活动可以继续发送；批次也不能绕过单次测试会遇到的任何保护措施。

轮到某个邮箱时无法运行，如何处理取决于批次策略：

| 策略 | 当日无余量、未连接或离线的邮箱 |
|--------|------------------------------------------------------|
| **重试直到所有发件邮箱都已测试**（默认，`defer`） | 等待后重试：每日限额耗尽时在下一个 UTC 日开始后重试，未连接时一小时后重试。批次继续处理其他邮箱，并自批次开始起最多重试七天 |
| **跳过无法立即发送的邮箱**（`skip`） | 记录原因并跳过，继续处理后续邮箱 |

如果邮箱正在发送另一项测试，始终在十五分钟后重试。没有可用种子的邮箱，例如所有种子都与它同域名，在两种策略下都会跳过。一个邮箱失败不会让整个批次失败：每个邮箱保留自己的结果或原因，例如每日限额、连接或工作节点问题。

全部邮箱都完成测试时，批次为**已完成**；部分跳过或失败时，为**已完成但有警告**；没有任何邮箱完成时，为**失败**；也可能为**已取消**。如果中途免费次数或你同意支付的积分耗尽，或被测试的活动或步骤被删除，尚未启动的邮箱会以相应原因跳过，批次带着已有结果结束。

取消批次会停止启动新邮箱，取消尚未发出的副本，并保留已发送副本继续分类，因此已取消的批次保留所有已有结果。

### 查看批次结果 [#reading-a-batch]

批次页面先显示进度和整体投递位置，再提供四种视图：

- **邮箱**：按收件箱到达率从低到高排序，显示跳过、延期或失败原因。每个邮箱都可打开自己的测试。
- **域名**：汇总各发件域名下邮箱的投递位置，最差的排在前面。整体健康域名中的单个异常邮箱通常是邮箱问题；整个域名都低，则指向该域名的信誉或身份验证。
- **服务商**：按发件服务商进行相同汇总，便于发现某一类邮箱的问题。
- **收件服务商**：用表格交叉展示发件域名与收到副本的服务商，便于发现只被某个服务商过滤的域名。

进行跟踪对比时，整体指标使用带跟踪的一半，即营销活动实际发送的版本，旁边同时展示不带跟踪的一半。

批次不会按工作节点分组。工作节点登录你的邮箱服务商，而服务商从自己的服务器投递邮件，因此收件方过滤器看不到哪个工作节点处理了该邮箱。

### 批次费用 [#what-a-batch-costs]

开始前，对话框会说明工作量：测试数量、最多可能发送的副本数，即每次种子数乘以邮箱数，跟踪对比再翻倍，以及同时发送的邮箱数量。各邮箱的每日限额只会使实际数量减少。

每个邮箱的测试都计为一次月度免费测试，对比计两次，与单次测试完全相同。如果批次需要的次数超过免费余量，你需要事先同意剩余部分的最高费用；API 使用整个批次的 `max_credits` 表示该上限。批次绝不会超额消耗，未发出任何副本的测试仍按通常规则退款。如果无法付费，例如试用账户或不支持付费测试的面板，超过剩余免费次数的批次会被拒绝；请缩小样本，或使用始终不计量的自有种子收件箱。

### 邮箱集群覆盖情况 [#fleet-coverage]

投递位置测试页面显示已连接邮箱集群中，有多少在最近 30 天完成过投递位置测试，以及有多少从未测试过。**测试尚未测试的邮箱**会恰好为这些邮箱创建批次。

## 如实解读结果 [#reading-the-results-honestly]

投递位置测试提供的是信号，解读时应考虑它的局限：

- **种子不是你的潜在客户。** 种子收件箱从未收到过你的联系，这正是其价值所在；但它也没有真实收件邮箱积累的历史，而服务商会高度重视每位收件人的自身行为。
- **不覆盖企业安全网关。** 许多企业收件人在 Microsoft 365 或 Google Workspace 邮箱之前，还部署了 Mimecast、Proofpoint 或 Cisco 等安全网关。种子展示的是服务商自身的过滤结果，无法代表前置网关的处理。
- **一次测试可能只是噪声。** 每个服务商通常只有少量种子，过滤器也不会对同一邮件的每份副本一视同仁。一份进入垃圾邮件未必有问题；多个测试中，同一服务商将大多数副本归为垃圾邮件，才值得关注。
- **跨多次测试和服务商比较。** 测试多个发件邮箱，换一天重复，并寻找模式：仅一个服务商恶化，通常指向该服务商处的身份验证或内容问题；所有服务商都恶化，则更可能指向发件人。
- **始终未到达本身也是信号。** 副本可能因服务商丢弃或延迟而消失，也可能只是种子尚未同步。一份缺失说明不了太多；某个服务商的大部分副本都缺失，通常表示其正在拒绝或推迟接收你的邮件。

测试结果也会进入[邮件送达能力](/guides/deliverability/#the-dashboard)页面的种子投递位置数据，在所选范围内按服务商汇总所有测试。

## 迁移工作区 [#moving-a-workspace]

投递位置测试及其结果作为记录，随[工作区导出](/guides/workspace-export-import/)中的“投递事件”迁移，但不包含付费测试的费用，因为积分不会迁移。投递位置批次及其邮箱和结果也会迁移。导出时仍在运行的批次，导入后为已取消，避免目标实例继续发送。营销活动投递监控器随营销活动迁移。哪些邮箱被标记为种子不会迁移，因此需要在目标实例重新标记。仍在发送的测试不会迁移尚未发出的副本。
