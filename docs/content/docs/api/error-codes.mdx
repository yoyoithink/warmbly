Warmbly API 使用标准 HTTP 状态码，并以 JSON 格式返回结构化错误响应。

## 错误响应格式 [#error-response-format]

所有错误均采用以下结构：

```json
{
  "error": "Error Type",
  "message": "Human-readable description of what went wrong.",
  "code": "machine_readable_code",
  "request_id": "req_or_uuid_for_support"
}
```

`error` 和 `message` 供用户阅读。客户端逻辑应使用 `code`、HTTP 状态码及 `retry_after` 等端点特有字段。联系支持时，请附上 `request_id`。

## HTTP 状态码 [#http-status-codes]

### 发送准入诊断 [#send-admission-diagnostics]

这些错误码出现在营销活动动态和任务失败元数据中，不是 HTTP 响应状态码：

| 错误码 | 含义 |
|------|---------|
| `CAMPAIGN_DAILY_LIMIT_REACHED` | 此营销活动在当前发件邮箱上已达到配置的 UTC 当日发送上限。其他邮箱有独立的营销活动额度。 |
| `MAILBOX_SENDING_PLAN_DENIED` | 邮箱已启用的本地日发送计划不可用、当前不在工作时段或处于休息时间，或每日/每小时额度已耗尽。容量恢复后，调度器会重试。 |
| `MANUAL_SEND_LIMIT_REACHED` | 统一收件箱发送（回复、转发或新建邮件，包括 `POST /unibox/*` 和 `POST /emails/:id/send`）将超过邮箱的合理使用额度：单封邮件收件人数、每小时收件人数、24 小时收件人数、24 小时新会话收件人数，或工作区所有邮箱共用的套餐 24 小时额度。失败消息会指出具体限制。统一收件箱发送从不计入营销活动或预热上限。参见 [发送控制](/guides/unibox/#sending-controls)。 |
| `RECIPIENT_SUPPRESSED` | 收件人直接或因其域名而位于工作区禁止发送名单中。失败消息会指出地址。统一收件箱转发不会因此遭拒。 |
| `SEND_ADMISSION_DENIED` | 其他当前发送授权、收件人或邮箱容量检查拒绝了准入。 |

分发前的准入拒绝会释放发送预留，不消耗一次失败发送尝试。遭拒的统一收件箱发送以 `failed` 状态结束，不会重试，并向邮箱所有者报告。独立可配置上限及每日目标量，参见 [营销活动](/guides/campaigns/) 和 [发送行为](/guides/sending-behavior/)。

### 客户端错误（4xx） [#client-errors-4xx]

| 错误码 | 错误 | 说明 |
|------|-------|-------------|
| 400 | 请求无效（Bad Request） | 请求语法或参数无效，或将超过配额（`storage_limit_reached`） |
| 401 | 未通过身份验证（Unauthorized） | 缺少身份验证信息或信息无效 |
| 402 | 需要付款（Payment Required） | 积分不足（`insufficient_credits`），或本月没有剩余免费投递位置测试（`placement_quota_exceeded`、`placement_not_entitled`） |
| 403 | 禁止访问（Forbidden） | 已通过身份验证但缺少权限，或工作区邮箱数量额度已满（`mailbox_allowance_reached`） |
| 404 | 未找到（Not Found） | 资源不存在 |
| 409 | 冲突（Conflict） | 资源已存在 |
| 422 | 无法处理（Unprocessable） | 验证失败 |
| 429 | 请求过多（Too Many Requests） | 超过速率限制或 AI 用量上限（`rate_limit_exceeded`、`usage_cap_exceeded`），或同时运行的投递位置测试或批次过多（`placement_too_many_running`、`placement_too_many_batches`） |

### 服务端错误（5xx） [#server-errors-5xx]

| 错误码 | 错误 | 说明 |
|------|-------|-------------|
| 500 | 服务器内部错误（Internal Server Error） | 未预期的服务器错误 |
| 501 | 尚未实现（Not Implemented） | 功能不可用 |
| 503 | 服务不可用（Service Unavailable） | 服务暂时不可用 |

## 错误详情 [#error-details]

### 400 Bad Request（请求无效） [#400-bad-request]

请求因语法无效而无法处理时返回。

**常见原因：**
- 请求体中的 JSON 无效
- 缺少必填字段
- 字段类型无效
- 值超出允许范围

**示例：**

```json
{
  "error": "Bad Request",
  "message": "The request body is missing or has invalid fields: \"to\" is required; \"subject\" is required.",
  "code": "bad_request",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

无法读取请求体时，`message` 会说明原因：

| 请求体情况 | `message` |
|----------|-----------|
| 为空 | `The request body is empty. ...` |
| 不是有效 JSON | `The request body is not valid JSON: <reason> (at byte N).` |
| 顶层 JSON 类型错误 | `The request body must be a JSON array, not a JSON object.` |
| 某字段的 JSON 类型错误 | `Field "to" must be a JSON array, not a JSON string.` |
| 包含非 RFC 3339 格式的时间 | `The request body has a time that is not RFC 3339 (such as 2026-10-01T09:00:00Z): "tomorrow".` |
| 文本字段包含 NUL 字符 | `Field "<name>" contains a NUL character, which is not supported.` |
| 缺少必填字段或值超出范围 | `The request body is missing or has invalid fields: "to" is required; ...`（最多列出五个字段，其余以数量表示） |

字段以 JSON 键名标识，嵌套字段采用点分路径（`inner.name`）。所有情况下，`code` 均为 `bad_request`，因此应依据 `code` 分支处理，并显示或记录 `message`。

带版本的 API 路由在端点运行前检查每个查询参数的名称和值，包括直接读取筛选条件的端点。旧版别名 `/invitations/lookup` 采用相同验证。NUL 字符、无效 UTF-8 和格式错误的查询编码会返回 `400`，而不会将不支持的文本传给数据库。例如，`?q=%00` 返回 `Query parameter "q[0]" contains a NUL character, which is not supported.`。有效 Unicode 文本和正确编码的标点保持不变。

邮箱、营销活动和联系人路由上的资源 ID 必须为 UUID。邮箱的 `tags` 及营销活动的 `email_tags`、`folders` 数组也要求 UUID 值。格式无效的值会在写入数据库之前返回 `400`，并带有 `code: "bad_request"` 和 `request_id`。有效 UUID 会被规范化，重复关系 ID 会去重；工作区归属检查仍然适用。

**解决方法：**
- 检查 JSON 是否有效
- 确认所有必填字段均已提供
- 确保字段值符合预期类型
- 将请求体结构与端点参考页面对照：某些端点接受数组，多数接受对象

**具体 400 错误码：**

| `code` | 含义 |
|--------|---------|
| `invalid_lead_status` | `POST /contacts/search` 或 `POST /contacts/export` 收到的 `lead_status` 不属于文档列出的值 |
| `invalid_sort_by` | `POST /contacts/search`、`POST /contacts/export` 或批量操作的 `all` 选择收到形如 `custom:<key>` 的 `sort_by`，但其中的键不可能是有效自定义字段名（仅允许字母、数字、下划线、空格或连字符） |
| `invalid_column`, `duplicate_column`, `too_many_columns`, `invalid_sort` | `PUT /me/views/:view` 收到该视图无法显示的列 ID、重复列、超过 64 列，或排序字段既不是可排序联系人列，也不是格式正确的 `custom:<key>`（`unibox_rail` 完全不支持列或排序） |
| `invalid_layout` | `PUT /me/views/:view` 为不支持布局的视图提供了 `layout`，或提供的 `unibox_rail` 布局包含未知字段、空键或过长键（200 字节）、列表超过 500 个键或超过 32 个分区，或收藏名称超过 40 个字符 |
| `invalid_mail_host` | `POST /contacts/search`、`POST /contacts/export` 或批量操作的 `all` 选择收到的 `mail_hosts` 项不属于文档列出的服务商值 |
| `invalid_engagement` | `POST /contacts/search` 或 `POST /contacts/export` 收到的 `engagement` 不属于文档列出的值 |
| `lead_filter_requires_campaign` | 设置了 `lead_status` 或 `engagement`，但 `campaign_ids` 未恰好包含一项；这两个筛选条件均描述联系人在单个营销活动中的情况 |
| `unknown_verification_status` | 联系人的 `verification_status` 不是任何已知验证服务使用的值 |
| `unknown_verification_provider` | 联系人的 `verification_provider` 指定了平台无法识别的服务商状态词 |
| `invalid_action` | `POST /contacts/verification` 收到的 `action` 不是 `verify`、`mark_deliverable` 或 `mark_undeliverable` |
| `no_contacts` | `POST /contacts/verification` 未选中联系人：既没有 `contacts`，也没有包含验证遭拒潜在客户的 `campaign_id` |
| `list_bounce_risk` | `POST /campaigns/:id/start` 根据名单的预估退信率拒绝启动。请清理或验证名单，或以 `acknowledge_list_risk: true` 重试请求 |
| `leads_undeliverable` | `POST /campaigns/:id/start` 因地址验证拒绝了所有剩余潜在客户而无内容可发；营销活动停留在 `paused_undeliverable`，直到重新验证或将其标记为可投递 |
| `empty_step_body` | `POST /campaigns/:id/start` 发现某个邮件步骤的两种正文均为空，若继续将向触达的每位潜在客户发送空白邮件。请编写步骤正文后重新启动 |
| `no_leads` | 对从未有过潜在客户且 `continuous` 关闭的营销活动调用 `POST /campaigns/:id/start`。请添加联系人，或设置 `continuous`，使其可空启动并等待联系人。所有潜在客户均已完成的活动则不同：它会启动并等待 |
| `no_remaining_leads` | 平台发起重启时，营销活动无内容可发且 `continuous` 关闭，因此无工作可做，活动再次成为 `completed`。您主动请求的启动绝不会返回此错误：它会开启 `continuous` 并等待 |
| `too_many_tasks` | `PATCH /crm/tasks` 或 `DELETE /crm/tasks` 单次请求收到超过 `1000` 个 ID，或超过 `50,000` 个排除项。请分批处理 |
| `too_many_contacts` | 联系人批量操作单次请求收到超过 `10,000` 个联系人 ID，或超过 `250,000` 个排除项。请分批处理，或改用筛选选择而非 ID |
| `selection_too_large` | `"all": true` 批量选择的结果超过上限：`250,000` 位联系人，或 `50,000` 个 CRM 任务。请缩小筛选范围并分批运行；未作任何更改 |
| `invalid_filter` | 任务筛选条件携带了无效 ID：`assigned_to`、`contact_id` 和 `deal_id` 指向记录，并与 ID 列匹配。由 `POST /crm/tasks/search`、`POST /crm/tasks/summary` 及 `"all": true` 批量选择的 `filters` 提交 |
| `invalid_setting` | `PATCH /outreach/settings`（或营销活动高级设置）包含文档规定范围之外的值，例如 `reply_intent.crm_task_intents` 中有非回复意图的项，或 `inbox_tagging.questions` 中存在无问题文本、标签缺失/重复/为内置标签、选择题少于两个选项的项，或 `inbox_tagging.languages` 中含不支持的语言代码 |
| `invalid_slug` | `PATCH /organization/current` 收到的 `slug` 不符合规则：2 至 80 个小写字母、数字或连字符，并以字母或数字开头和结尾 |
| `invalid_sync_folder` | `PUT /emails/:id/sync` 收到同步始终跟随的文件夹（`INBOX`，或按属性/名称识别的已发送、草稿、垃圾邮件、垃圾箱或归档文件夹）、去除首尾空白后为空、超过 255 个字符或含控制字符的名称、超过 50 个名称，或非 IMAP 邮箱。`message` 指出被拒绝的条目 |
| `no_organization` | 请求需要工作区，但调用者尚未选择。所有权益、限制及禁止发送规则均以工作区为范围，因此可能在无范围状态下执行的写入会被拒绝，而不会跳过检查。API 密钥始终携带工作区；控制台会话在登录时选择工作区，因此这通常表示会话早于工作区选择。请选择工作区后重试 |
| `lead_cc_limit` | [设置潜在客户的抄送对象](/api/reference/campaigns/#set-a-leads-cc) 收到超过 `2` 位联系人 |
| `lead_cc_self` | [设置潜在客户的抄送对象](/api/reference/campaigns/#set-a-leads-cc) 将潜在客户本人指定为抄送对象 |
| `invalid_recipient` | `POST /emails/:id/send`、`POST /unibox/reply` 或 `POST /unibox/compose` 中某个 `to`、`cc` 或 `bcc` 项并非恰好一个邮箱地址（`ana@example.com` 或 `Ana <ana@example.com>`），或完全没有 `to` 地址。请将每个地址分别放在独立项中 |
| `recipient_suppressed` | `POST /emails/:id/send`、`POST /unibox/reply` 或 `POST /unibox/compose` 指定的某个 `to`、`cc` 或 `bcc` 地址，直接或因其域名而位于工作区 [禁止发送名单](/guides/unsubscribe/#the-suppression-list) 中。`message` 指出地址和对应条目。没有任务入队。转发（带有 `forward_message_id` 的 `POST /unibox/reply`）不检查该名单 |
| `invalid_message_id` | `POST /emails/:id/send` 或 `POST /unibox/reply` 收到的 `in_reply_to` 项并非单个 Message-ID：应为无空格和换行的可打印字符，可带或不带外围 `<` 和 `>` |

#### 密码被拒绝的情况 [#password-refusals]

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `password_breached` | 400 | 密码出现在公开泄露密码名单中，因此遭拒。请换用不在名单中的密码 |
| `sso_link_expired` | 400 | `link_required` 登录返回的待处理令牌未知、已过期（十分钟）、已使用，或已经输入三次错误密码。请重新发起服务商登录 |

密码须为 8 至 128 个字符。不要求特定字符组合，但会不区分大小写地与英国国家网络安全中心发布的 100,000 个最常泄露密码比对。

```json
{
  "error": "Bad Request",
  "message": "This password appears in a public list of breached passwords. Choose one that does not.",
  "code": "password_breached",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

#### App Attest 验证被拒绝的情况 [#app-attest-refusals]

原生应用在登录、注册和密码重置时通过 [App Attest](/api/reference/account-org/#app-attest-native-apps) 证明自身身份，以替代验证码。

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `app_attest_failed` | 400 | 证明未通过验证：质询过期或已使用、证明来自其他应用或服务端不接受的开发版本、断言计数器未递增、密钥 ID 已注册，或对象格式无效。请获取新质询并生成新证明；若持续失败，请更新应用 |
| `app_attest_key_unknown` | 400 | `key_id` 从未在此服务器注册。请通过 `POST /auth/app-attest/keys` 重新注册密钥，然后重试调用 |
| `app_attest_unavailable` | 404 | 在关闭 App Attest 的实例上调用 `POST /auth/app-attest/challenge` 或 `/keys`。当 `GET /auth/config` 报告需要验证码但没有 `app_attest` 时，应用内无法使用邮箱和密码登录；“通过 Apple 登录”、Google 登录和通行密钥仍可使用 |

每个已注册密钥每小时最多执行 30 次受保护调用。超过后返回 `400`，错误码为 `bad_request`，消息为 `Too many attempts, please try again later.`，与其他登录尝试额度的响应相同。

```json
{
  "error": "Bad Request",
  "message": "We couldn’t verify this copy of the app. Update it from the App Store and try again.",
  "code": "app_attest_failed",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

#### Warmbly Cloud 预热被拒绝的情况 [#warmbly-cloud-warmup-refusals]

由 Warmbly Cloud 预热的邮箱必须通过云端更改预热设置（参见 [预热设置](/guides/warmbly-cloud/#warmup-settings)）。无法执行时，`PATCH /emails/:id` 及预热启动、暂停和恢复路由会返回以下错误。所有情况下，实例均不会应用此次更新的其余部分。在 `cloud_warmup_not_applied` 之后，邮箱本地保存的 Warmbly Cloud 设置仍会刷新为 Cloud 报告的值。使用相同 `Idempotency-Key` 重放会返回已保存响应，因此请使用新键重试。

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `cloud_warmup_value_unsupported` | 422 | Warmbly Cloud 不接受实例将起始量、最大量、每日递增量或回复率设为 0。请使用 1 或更大的值，或在 Warmbly Cloud 中更改 |
| `cloud_warmup_not_applied` | 409 | Warmbly Cloud 已响应，但未应用指定设置。邮箱现在显示 Warmbly Cloud 报告的值 |
| `cloud_warmup_managed` | 409 | 参与状态、共用每日及收件人数限制，以及停止预热，需通过邮箱的 Warmbly Cloud 控制项更改，不能直接在邮箱设置中更改 |
| `cloud_link_disconnecting` | 409 | 工作区正在断开 Warmbly Cloud。完成后重试 |
| `cloud_link_unreachable` | 503 | 无法连接 Warmbly Cloud |
| `cloud_link_bad_response` | 503 | Warmbly Cloud 已响应，但未包含邮箱预热设置 |

#### 名称被拒绝的情况 [#name-refusals]

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `invalid_name` | 400 | 名、姓、工作区名称、公司名称、OAuth 应用名称或邮箱显示名称违反命名规则。`message` 指出字段及规则 |

名称会显示给其他人，包括出现在邀请和通知邮件中，因此仅允许纯文本。控制台、API、设置页面及 `warmblyctl` 采用相同规则：

- 名或姓最多 50 个字符，且包含字母；工作区或公司名称最多 64 个字符，且包含字母或数字；邮箱显示名称仍采用自身的 2 至 100 个字符限制
- 不得包含链接、网址或邮箱地址：不得含有 `@`、`//`、`www.` 或 `https:` 等协议前缀，也不得含有 `example.com` 这样的主机名或 IP 地址。全角点和中文句号也按点处理
- 不得包含控制字符、不可见格式字符（零宽字符和双向覆盖字符）、`<`、`>`、`` ` `` 或 `\`，也不得叠加超过三个组合附加符号
- 去除首尾空格，连续空格合并为一个，并以此规范化形式保存

### 401 Unauthorized（未通过身份验证） [#401-unauthorized]

身份验证失败时返回。

**常见原因：**
- 缺少 `Authorization` 请求头
- API 密钥格式无效
- API 密钥已过期
- API 密钥已撤销

**示例：**

```json
{
  "error": "Unauthorized",
  "message": "Token not found.",
  "code": "unauthorized",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 包含 `Authorization: Bearer wmbly_...` 请求头
- 确认 API 密钥正确
- 检查密钥是否已过期或撤销
- 必要时生成新密钥

有两种 `401` 情况与 API 密钥无关。首次认领端点在设置链接无效、已使用或已过期时返回 `setup_token_invalid`。通过 `warmblyctl setup-link` 输出新链接，详见 [首次运行](/development/first-run/)。

`POST /auth/sso/exchange` 在兑换交接代码时未提供 `POST /auth/<provider>/begin` 发给登录发起浏览器的绑定密钥，则返回 `sso_wrong_browser`。交接被刻意设计为不可转移：转发的登录链接或在其他浏览器打开的链接不能使接收者登录。请在打算使用的浏览器中重新开始登录。

### 402 Payment Required（需要付款） [#402-payment-required]

请求 AI 操作或使用积分支付的投递位置测试，但组织积分不足时返回。响应携带稳定错误码 `insufficient_credits`。

```json
{
  "error": "Payment Required",
  "message": "You're out of AI credits. Add more to keep using the assistant.",
  "code": "insufficient_credits",
  "request_id": "req_..."
}
```

**解决方法：**
- 等待每月额度重置，或购买充值包（参见 [AI 积分](/guides/ai-credits/)）
- 相关情况：错误码为 `usage_cap_exceeded` 的 `429` 表示触及短期 AI 用量上限；请稍后重试

投递位置测试也会返回 `402`，错误码为 `placement_not_entitled` 或 `placement_quota_exceeded`；参见 [投递位置测试拒绝原因](#placement-test-refusals)。付费投递位置测试超出积分余额时返回 `insufficient_credits`，超出支出上限时返回 `429` 和 `usage_cap_exceeded`；两者均不收费。

### 403 Forbidden（禁止访问） [#403-forbidden]

已通过身份验证但缺少所需权限时返回。

**常见原因：**
- API 密钥缺少所需权限
- 请求 IP 不在允许列表中
- 邮箱账户不在允许列表中
- 组织访问受限
- 成员仅限访问选定资源（`member_access_restricted`）

**示例：**

```json
{
  "error": "Forbidden",
  "message": "You don't have access to this feature.",
  "code": "forbidden",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 检查 API 密钥权限
- 若配置了 IP 限制，请核对
- 必要时申请更多权限

#### `mailbox_gmail_oauth_disabled` [#mailbox_gmail_oauth_disabled]

`code` 为 `mailbox_gmail_oauth_disabled` 的 `403` 来自带有 `provider: "gmail"` 的 `POST /emails/onboarding/oauth/start`。后端没有完整的 Google 邮箱客户端凭据，或通过 `BOX_GOOGLE_OAUTH_CONNECT` 显式禁用新 Google OAuth 连接；`GET /auth/config` 将其声明为 `gmail_oauth_connect: false`。调用者权限并无问题。重新授权现有 Gmail 邮箱（`POST /emails/onboarding/oauth/reauth/:id`）绝不会因此遭拒。

```json
{
  "error": "Forbidden",
  "message": "New Gmail mailboxes connect with an app password over IMAP and SMTP on this deployment, not with Google sign-in.",
  "code": "mailbox_gmail_oauth_disabled",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 通过 `POST /emails/onboarding/smtp-imap` 连接邮箱，使用 `smtp.gmail.com:465` 和 `imap.gmail.com:993`，两者均采用 TLS，并提供 Google 应用密码。参见 [Gmail 与 Google Workspace](/guides/mailboxes/#gmail-and-google-workspace)
- 使用自有 Google 应用的实例必须同时设置 `BOX_GOOGLE_CLIENT_ID` 和 `BOX_GOOGLE_CLIENT_SECRET`。将 `BOX_GOOGLE_OAUTH_CONNECT` 留空或设为 `true`，然后在应提供 Google 登录的部署上启用 [控制台显示开关](/development/configuration/#google-sign-in-per-dashboard-deployment)

#### 注册和邀请被拒绝的情况 [#registration-and-invitation-refusals]

注册和邀请拒绝携带各自的 `code`，使客户端可以根据具体条件分支处理，无需匹配文本。它们描述部署策略，绝不透露给定地址是否存在。

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `registration_invite_only` | 403 | 服务器运行 `DISABLE_REGISTRATION=invite_only`。创建账户需要邀请链接，其中携带许可注册的令牌 |
| `registration_closed` | 403 | 服务器运行 `DISABLE_REGISTRATION=true`。注册已关闭，邀请不能覆盖此设置 |
| `invitation_invalid` | 403 | 邀请已过期、取消、使用，或发给不同邮箱地址 |
| `setup_already_complete` | 403 | 在已有账户的实例上尝试首次运行认领 |

```json
{
  "error": "Forbidden",
  "message": "This server is invite only. Ask an administrator to invite you, then open the link in the invitation to create your account.",
  "code": "registration_invite_only",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：** 在自托管部署中，这些属于配置行为，而非故障。参见 [账户与访问](/development/accounts-and-access/#registration-modes)。

#### 需要确认 [#confirmation-required]

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `reauth_required` | 403 | 此操作需要比当前会话更新的身份证明。请通过 `POST /v1/auth/reauth` 确认，然后重试 |
| `reauth_limited` | 400 | 此账户一小时内确认失败过多。请等待，或退出后重新登录：登录后的五分钟内视为已确认 |
| `reauth_no_factor` | 400 | `POST /auth/reauth` 为既无密码也无验证码因素的账户提交了密码或代码。请使用通行密钥，或 `GET /auth/reauth/methods` 列出的关联登录服务商确认；若这些方式均无，则退出后重新登录（登录后的五分钟内视为已确认） |
| `reauth_identity_mismatch` | 400 | 确认期间验证的 Google、Apple 或单点登录账户，并非关联到此 Warmbly 账户的身份。请继续使用平时登录的账户 |
| `reauth_expired` | 400 | 确认代码或 nonce 已过期或已使用。请重新开始确认 |
| `admin_mfa_required` | 403 | 未提供第二因素的会话访问了管理员路由。请开启 2FA 或添加通行密钥，然后重新登录 |
| `passkey_user_verification_required` | 400 | 通行密钥登录所用认证器未通过 PIN 或生物识别验证用户。请为安全密钥设置 PIN，或改用其他方式登录 |
| `two_fa_invalid_code` | 400 | 认证器代码或恢复代码不匹配。请等待新代码后重试；每个待处理会话的登录质询允许五次尝试 |
| `password_changed_sign_in_again` | 409 | `POST /auth/me/password` 已保存新密码，但无法为调用设备签发新会话。所有先前令牌均已失效；请丢弃并使用新密码重新登录 |

`reauth_required` 保护会发放长期凭据、披露签名密钥、更改访问者、不可撤销，或访问整个域邮件的更改。完整列表见 [需要近期确认的操作](/api/endpoints/#actions-that-need-a-recent-confirmation)。通过 `GET /v1/auth/reauth/methods` 列出账户可用的确认方式（包括通行密钥，以及关联的 Google、Apple 或单点登录身份；参见 [端点](/api/endpoints/#actions-that-need-a-recent-confirmation)）。使用密码或当前双重验证代码时：

```bash
curl -X POST "https://api.warmbly.com/v1/auth/reauth" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"password": "..."}'
```

```json
{ "valid_for_seconds": 300 }
```

确认记录在会话上，并在返回的时间窗口内有效，因此连续执行相关更改只需确认一次。

启用双重身份验证（`POST /auth/2fa/enroll/start` 和 `/confirm`）同样受保护，因为已确认的认证器本身也可用于确认身份。有密码的账户按上述方式确认。既无密码也无 2FA 的账户（通过 Google、Apple 或单点登录创建）使用通行密钥或关联身份确认。若均无，则与其他需确认操作一样，可在登录后五分钟内执行；更早的会话返回 `reauth_no_factor`，需退出后重新登录。API 密钥和 OAuth 令牌没有可供确认的会话，因此这些路由仅能通过已登录会话访问；对于密钥创建，这是有意设计，否则泄露的密钥可能继续签发更多密钥。

```json
{
  "error": "Forbidden",
  "message": "Confirm it is you before making this change.",
  "code": "reauth_required",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

#### 成员访问范围 [#member-access-scope]

仅限访问 [选定资源](/guides/team-roles/#access-scope) 的成员，以及代表该成员的 API 密钥或 OAuth 应用，只能访问按授权范围筛选的读取路由。范围相关拒绝如下：

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `member_access_restricted` | 403 | 调用者的选定资源范围不覆盖此路由。资源写入及联系人、设置等工作区整体接口均被拒绝。只有受限成员关系的账户不能创建工作区，实例管理员除外；限额申请操作要求在目标工作区具有非受限成员关系 |
| `invalid_access_resource` | 400 | `PUT /organization/members/:id/access` 或邀请指定了不属于此工作区的营销活动文件夹、营销活动或邮箱 |
| `invalid_access_scope` | 400 | 范围既不是 `workspace`，也不是 `restricted` |
| `too_many_access_grants` | 400 | 单个列表超过 500 个文件夹、营销活动或邮箱 |
| `owner_access_unrestricted` | 403 | 工作区所有者始终可访问整个工作区，不能受限 |

超出受限调用者授权范围的营销活动或邮箱返回 `404`，与不存在的资源相同，因此不会通过权限范围泄露工作区中的其他资源。`GET /unibox/thread/labels` 对未知会话、位于所选工作区之外的会话，或可访问邮箱中没有任何邮件的会话，也返回相同的 `404`。可访问但无标签的会话返回空列表。

解析受限范围或范围内计数失败时，请求会失败，而不会返回工作区整体数据。实时授权查询错误会停止营销活动、邮箱和组织通道；无法验证授权的用户通道事件会被暂扣。参见 [有时限的实时授权](/api/realtime/#channels)。

```json
{
  "error": "Forbidden",
  "message": "Your access to this workspace is limited to selected campaigns and mailboxes, and this is outside it.",
  "code": "member_access_restricted",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：** 请具有 **管理团队** 权限的成员在 **设置 > 成员** 中扩大访问范围。

#### `slack_link_email_mismatch` [#slack_link_email_mismatch]

`code` 为 `slack_link_email_mismatch` 的 `403` 来自未提交 Slack 登录结果的 `POST /integrations/slack/link`。以这种方式确认 [Slack 关联](/guides/slack/#link-your-slack-account)，要求 Slack 账户资料中的邮箱与已登录用户的 Warmbly 邮箱相同，比较时忽略大小写。代码仍可使用：请提供来自 `POST /integrations/slack/link/verify` 的 `slack_code` 和 `state` 再次确认。`GET /integrations/slack/link/:code` 通过 `email_matches` 提前报告匹配检查结果，并通过 `verify_available` 说明 Slack 登录是否可用。

```json
{
  "error": "Forbidden",
  "message": "This Slack account's email is not the one you sign in to Warmbly with. Continue with Slack to confirm the account is yours.",
  "code": "slack_link_email_mismatch",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 使用 Slack 个人资料中的邮箱登录 Warmbly，然后再次确认
- 若地址已经相同，请具有 `manage_settings` 的成员在 **集成 > Slack** 中重新连接 Slack，使连接授予 `users:read` 和 `users:read.email`

### 404 Not Found（未找到） [#404-not-found]

请求的资源不存在时返回。

**常见原因：**
- 资源 ID 无效
- 资源已删除
- 资源属于其他组织
- 端点 URL 拼写错误

**示例：**

```json
{
  "error": "Not Found",
  "message": "Resource not found.",
  "code": "not_found",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 确认资源 ID 正确
- 检查资源是否已删除
- 确保使用正确端点

**具体 404 错误码：**

| `code` | 含义 |
|--------|---------|
| `unknown_view` | `/me/views/:view` 收到的视图名称不是 `contacts`、`campaign_leads` 或 `unibox_rail` |
| `app_attest_unavailable` | 在关闭 App Attest 的实例上调用 `POST /auth/app-attest/challenge` 或 `/keys`。参见 [App Attest 验证被拒绝的情况](#app-attest-refusals) |
| `lead_cc_contact_not_found` | [设置潜在客户的抄送对象](/api/reference/campaigns/#set-a-leads-cc) 指定了不属于工作区的联系人 |
| `slack_not_connected` | 为尚未连接 Slack 或连接已移除的工作区调用了 [Slack](/guides/slack/) 路由。请在 **集成 > Slack** 中连接 |
| `slack_link_invalid` | Slack 关联代码未知、已过期或已使用。请在 Slack 中提及机器人或向其发消息，获取新的关联按钮 |
| `slack_verify_failed` | `POST /integrations/slack/link` 提交的 Slack 登录结果未知、已过期、已使用、由他人发起或属于另一代码。请从 `POST /integrations/slack/link/verify` 重新开始 |

| `slack_not_linked` | 尚未在此工作区关联 Slack 账户的成员调用 `PATCH /integrations/slack/link` |

### 409 Conflict（冲突） [#409-conflict]

请求与现有数据冲突时返回。

**常见原因：**
- 尝试创建已存在的资源
- 唯一值重复
- 尝试删除当前状态尚不允许删除的资源，例如仍可用于身份验证的 API 密钥

**示例：**

```json
{
  "error": "Conflict",
  "message": "resource already exists",
  "code": "conflict",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

为已有账户的地址创建账户，会返回 `409`，使用通用 `conflict` 错误码，并提示登录或重置密码。启用邮箱验证时，邮件验证码证明地址属于调用者后，由 `POST /auth/register/confirm` 返回；未启用时则由 `POST /auth/register` 直接返回。

部分冲突具有独立 `code`。邮箱导入冲突见 [邮箱导入拒绝原因](#mailbox-import-refusals)。联系人的邮箱地址必须未被占用，因此将其改为另一联系人已使用的地址时会被拒绝，而不会合并两位联系人：

| `code` | 状态 | 含义 |
|--------|--------|---------|
| `contact_email_taken` | 409 | 提供给 [更新联系人](/api/reference/contacts/#update-a-contact) 的地址已属于另一位联系人 |
| `lead_cc_lead_is_copied` | 409 | 对本身已是同一营销活动中另一潜在客户抄送对象的潜在客户调用 [设置潜在客户的抄送对象](/api/reference/campaigns/#set-a-leads-cc)；它不再收到自己的独立邮件，因此无法再为其抄送他人 |
| `lead_cc_has_copies` | 409 | [设置潜在客户的抄送对象](/api/reference/campaigns/#set-a-leads-cc) 指定了在营销活动中已有自身抄送对象的联系人 |
| `mailbox_is_seed` | 409 | 在投递位置种子收件箱上启动或恢复预热。参见 [投递位置测试拒绝原因](#placement-test-refusals) |
| `mailbox_not_google_signin` | 409 | 对非通过逐邮箱 Google 登录连接的邮箱调用 `POST /emails/onboarding/app-password/:id`。参见 [切换应用密码的拒绝原因](#app-password-switch-refusals) |
| `approval_not_pending` | 409 | `POST /ai/sessions/:id/approve` 指定了会话当前并未等待的工具调用：可能已在另一选项卡或 Slack 中作出决定，或已被更新消息替代 |
| `mailbox_cloud_unenroll_failed` | 409 | 邮箱已关联 [Warmbly Cloud](/guides/warmbly-cloud/)，但无法释放关联，因此 `DELETE /emails/{id}` 将导致 Warmbly Cloud 继续持有凭据或认领状态。邮箱记录保留，并尝试恢复到工作节点 |

`mailbox_cloud_unenroll_failed` 表示自托管实例在删除过程中失去与 Warmbly Cloud 的联系。删除已加入预热池的邮箱时，必须先撤销加入关系，再移除记录，因为池中持有邮箱自身的 SMTP/IMAP 凭据，而该记录是唯一知道加入关系存在的地方。同一调用还会在移除记录前释放云端托管镜像，使邮箱返回云端工作区并可再次接管，而不会继续被已经不再保有它的实例认领。邮箱记录会保留。Warmbly 立即尝试将其恢复到工作节点；若失败，工作节点协调器可能稍后恢复。实例恢复云端连接后，请重试删除。先在 **设置 > Warmbly Cloud** 中取消加入并无帮助，因为它调用的是同一接口。

### 422 Unprocessable（无法处理） [#422-unprocessable]

请求数据验证失败时返回。

**常见原因：**
- 邮箱地址格式无效
- 字符串超过最大长度
- 数字超出有效范围
- 枚举值无效

**示例：**

```json
{
  "error": "Unprocessable",
  "message": "validation failed",
  "code": "unprocessable",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

### 500 Internal Server Error（服务器内部错误） [#500-internal-server-error]

服务器发生未预期错误时返回。

**示例：**

```json
{
  "error": "Internal Server Error",
  "message": "Something went wrong.",
  "code": "internal_error",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 稍作等待后重试请求
- 若持续发生，请附带请求详情联系支持

500 始终携带相同消息。不返回底层详情，因为它通常是包含表名、列名和主机名的数据库或服务商输出，对调用者没有帮助。详情会与响应中的 `request_id` 关联记录，因此在支持请求中引用该 ID 即可关联两者。

有一种 `internal_error` 情况需要区分。身份验证端点无法发送邮件时，消息会明确说明，而不是报告通用故障，因为自托管实例上看到消息的人通常就是能够修复它的人：

```json
{
  "error": "Internal Server Error",
  "message": "We couldn't send the email. If you administer this server, check the mail transport configuration.",
  "code": "internal_error",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

在自托管部署中，这涉及 `MAIL_TRANSPORT` 和 `SMTP_` 变量。参见 [自托管](/development/deployment-guide/)。

### 503 Service Unavailable（服务不可用） [#503-service-unavailable]

服务暂时不可用时返回。

**示例：**

```json
{
  "error": "Service Unavailable",
  "message": "service unavailable",
  "code": "service_unavailable",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 等待后采用指数退避重试
- 检查状态页面是否有故障事件

#### `mailbox_provider_not_configured` [#mailbox_provider_not_configured]

`code` 为 `mailbox_provider_not_configured` 的 `503` 不是暂时性问题，重试无效。它表示部署未配置请求所需邮箱服务商的 OAuth 客户端，仅发生在自托管安装中。

```json
{
  "error": "Service Unavailable",
  "message": "Gmail is not configured on this deployment. Set BOX_GOOGLE_CLIENT_ID and BOX_GOOGLE_CLIENT_SECRET in your .env, then restart.",
  "code": "mailbox_provider_not_configured",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 在安装根目录的 `.env` 中设置 `BOX_GOOGLE_CLIENT_ID` 和 `BOX_GOOGLE_CLIENT_SECRET`，或 `BOX_OUTLOOK_CLIENT_ID` 和 `BOX_OUTLOOK_CLIENT_SECRET`，然后重启
- 或改用 SMTP 和 IMAP 连接邮箱，无需这些配置
- 完整步骤：[连接邮箱](/development/deployment-guide/#connect-mailboxes)

#### `ai_not_configured` [#ai_not_configured]

`code` 为 `ai_not_configured` 的 `503` 不是暂时性问题，重试无效。它来自 `POST /templates/analyze`，表示部署完全没有配置 AI 服务商。客户端可据此区分“此处没有 AI”和“服务商暂时异常”；后者返回通用 `service_unavailable`，值得重试。

```json
{
  "error": "Service Unavailable",
  "message": "AI analysis is not configured on this deployment.",
  "code": "ai_not_configured",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 在安装根目录的 `.env` 中设置 `AI_PROVIDER` 和 `AI_API_KEY`，然后重启。参见 [配置参考](/development/configuration/)
- 在客户端隐藏 AI 功能入口，而非重试：修改请求内容无法使其成功

#### `slack_not_configured` [#slack_not_configured]

`code` 为 `slack_not_configured` 的 `503` 不是暂时性问题，重试无效。实例未配置 [Slack](/guides/slack/)，仅发生在自托管安装中。未设置 `SLACK_SIGNING_SECRET` 时，三个 Slack 请求 URL（`/api/v1/integrations/slack/events`、`/interactivity` 和 `/commands`）都会返回此错误。

```json
{
  "error": "Service Unavailable",
  "message": "Slack is not set up on this Warmbly instance.",
  "code": "slack_not_configured",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 创建实例的 Slack 应用，并在后端和消费者进程上设置 `SLACK_OAUTH_CLIENT_ID`、`SLACK_OAUTH_CLIENT_SECRET` 和 `SLACK_SIGNING_SECRET`，然后重启。参见 [Slack 应用](/development/slack-app/)
- 客户端应从 `GET /integrations/slack/status` 读取 `app_configured` 和 `interactive_configured`，并隐藏 Slack 功能入口，而非重试

这些请求 URL 对 Slack 签名验证失败的请求返回 `401` `unauthorized`。将 Slack 账户关联到自己并非成员的工作区，返回 `403` `forbidden`；关联邮箱不属于自己的账户且未通过 Slack 登录验证时，返回 `403` [`slack_link_email_mismatch`](#slack_link_email_mismatch)。

#### `mailbox_allowance_reached` [#mailbox_allowance_reached]

`code` 为 `mailbox_allowance_reached` 的 `403` 可来自所有邮箱连接途径：`POST /emails/onboarding/oauth/start`、`POST /emails/onboarding/oauth/finish`、`POST /emails/onboarding/smtp-imap`，以及 `POST /emails/onboarding/smtp-imap/bulk` 内的逐行结果。[邮箱导入](/guides/mailbox-import/) 不以 HTTP 错误返回它：超出额度的行以 `cause` 为 `allowance_reached` 失败，额度提高后可重试。这不是权限问题：工作区已用完全部 [邮箱数量额度](/guides/mailboxes/#mailbox-allowance)，付费套餐中每日每包含一封发送量对应一个邮箱，免费工作区则为 `10`。未连接任何邮箱。

```json
{
  "error": "Forbidden",
  "message": "This workspace holds 15000 of its 15000 mailboxes. Request an increase, or move to a plan with more daily sends.",
  "code": "mailbox_allowance_reached",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 先读取 `GET /emails/allowance`：`remaining` 表示还能成功连接多少个邮箱，`pending_request` 表示是否已申请增额
- 通过 `POST /organization/:orgId/limit-requests` 为 `max_email_accounts` 提交增额申请，或升级到每日发送量更高的套餐。申请获批会立即提高额度，届时重试连接
- 重新连接现有邮箱绝不会返回此错误码

#### `storage_limit_reached` [#storage_limit_reached]

`code` 为 `storage_limit_reached` 的 `400` 来自 `POST /campaigns/:id/attachments`、`POST /email-images`，以及会复制附件的营销活动复制操作。工作区存储字节数（所有营销活动附件加邮件图片库）将超过配额。检查与写入在两者共用的单个工作区锁下完成，因此争抢最后剩余配额的两个上传无法同时通过。未存储任何内容。

```json
{
  "error": "Bad Request",
  "message": "Storage limit reached: 51190 MB of 51200 MB used, 12 MB to add. Remove attachments or images, or upgrade your plan.",
  "code": "storage_limit_reached",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- `GET /organization/current/limits` 报告 `storage.used_bytes` 和 `storage.limit_bytes`；若套餐变更导致工作区超额，还报告 `storage.over_quota`。无论是否超额，现有附件仍可继续发送
- 删除不再需要的附件（`DELETE /campaigns/:id/attachments/:attachmentId`）或图片（`DELETE /email-images/:id`），或升级到付费套餐以获得更大配额

#### `mailbox_validation_timeout` [#mailbox_validation_timeout]

`code` 为 `mailbox_validation_timeout` 的 `400` 来自 SMTP 和 IMAP 连接及重新授权端点。Warmbly 在保存任何内容前，通过实际连接邮件服务器验证凭据，但某一路连接在验证窗口内始终未响应。消息会指出未响应的一端，并说明另一端是否已成功登录。未保存任何内容，也未创建邮箱。

```json
{
  "error": "Bad Request",
  "message": "SMTP (smtp.gmail.com:465) did not answer in time. IMAP (imap.gmail.com:993) signed in. Nothing was saved. Check the host and port, then try again. Port 465 did not answer and the worker could not use 587 with STARTTLS on the same server either. Some networks block outbound mail ports; check that the server is reachable from outside and which port it listens on.",
  "code": "mailbox_validation_timeout",
  "request_id": "6f3c0a1e-2d47-4c6b-9a1f-2b7c5f0e8d31"
}
```

同一错误码的消息若以 `Warmbly's worker did not report back` 开头，表示根本没有工作节点回应检查，因此邮件服务器从未被测试。检查依次交给每个健康工作节点，最多等待两个已接受却不回应的工作节点，因此此错误意味着整个节点集群都未响应。在托管产品上，请重试，持续失败则联系支持。在自托管实例上，请检查工作节点是否运行、是否有心跳，以及是否能访问与后端相同的 Redis：检查通过 Redis 到达工作节点，结果也通过同一路径返回。

**解决方法：**
- 阅读消息，确认哪一端未响应。一端通过而另一端挂起，说明问题在工作节点到该端口的网络，而非密码：无人监听或被防火墙丢弃数据包的端口会等待完整超时，而不会立即拒绝
- 465 始终未响应时，工作节点还会尝试同一服务器的 587 STARTTLS，连接成功则使用它；验证通过后保存的端口为 587。此错误表示两个端口均未响应，请检查服务器是否可从网络外部访问，以及实际监听哪个端口
- 请重试。负载较高的邮件服务器可能某次响应较慢，下次立即响应
- 确认服务器接受来自网络外部的连接，并确保安全模式与端口匹配：465 和 993 使用 `tls`，587 和 143 使用 `starttls`

#### `mailbox_auth_refused` [#mailbox_auth_refused]

`code` 为 `mailbox_auth_refused` 的 `400` 来自 SMTP 和 IMAP 连接及重新授权端点。邮件服务器已响应，但拒绝登录。消息会指出哪一端、哪台服务器，引用服务器原始回复；对于 Google 服务器，还会说明应用密码的含义。未保存任何内容。

```json
{
  "error": "Bad Request",
  "message": "SMTP (smtp.gmail.com:587) refused the sign-in: 535 5.7.8 Username and Password not accepted. IMAP (imap.gmail.com:993) refused the sign-in: imap: NO [AUTHENTICATIONFAILED] Invalid credentials (Failure). Nothing was saved. Google itself refused this address and password. Use a 16-letter app password from myaccount.google.com/apppasswords, created while signed in to the Google account that owns this address, and enter the account's own sign-in address rather than an alias or a group. A deleted app password stops working at once, and on Google Workspace the administrator can block app passwords or IMAP.",
  "code": "mailbox_auth_refused",
  "request_id": "6f3c0a1e-2d47-4c6b-9a1f-2b7c5f0e8d31"
}
```

**解决方法：**
- 阅读消息中的服务器回复：它说明哪一端拒绝，通常也说明原因（密码错误、需要应用密码、域名关闭 IMAP）
- 用户名通常为完整邮箱地址。账户启用两步验证时，密码应为服务商的应用密码，绝不能使用账户密码
- 空白字符不是问题：Warmbly 在所有途径都会去除密码首尾空白，对 Google 服务器使用的密码还会去除所有空格
- 对于 Google，使用真实应用密码仍遭拒时，几乎总是地址并非签发该密码的账户：请填写账户自己的登录地址，而非别名或群组；登录该账户后创建应用密码，并确认之后没有删除。在 Google Workspace 中，管理员也可能对组织禁用应用密码或 IMAP

#### `mailbox_unreachable` [#mailbox_unreachable]

`code` 为 `mailbox_unreachable` 的 `400` 来自同一组端点。工作节点完全无法连接服务器：域名解析失败、端口拒绝连接，或防火墙丢弃数据包。消息指出服务器和具体情况。未保存任何内容。

```json
{
  "error": "Bad Request",
  "message": "SMTP (smtp.example.com:465) could not be reached from the worker: the port refused the connection. Nothing was saved.",
  "code": "mailbox_unreachable",
  "request_id": "6f3c0a1e-2d47-4c6b-9a1f-2b7c5f0e8d31"
}
```

**解决方法：**
- 检查主机和端口是否拼写错误
- 连接从工作节点发出，而非浏览器或 API 主机：工作节点所在网络必须能访问服务器的对应端口。部分托管服务商默认封锁外发邮件端口，需要申请开放

#### `mailbox_tls_failed` [#mailbox_tls_failed]

`code` 为 `mailbox_tls_failed` 的 `400` 来自同一组端点。已连到服务器，但无法建立安全连接：证书不能通过该主机名验证、握手失败，或端口要求不同模式（在 STARTTLS 端口使用 `tls`，或反之）且服务器未提供 STARTTLS。未保存任何内容。

```json
{
  "error": "Bad Request",
  "message": "IMAP (mail.example.com:143) did not complete a secure connection: the server offers no STARTTLS on this port. Nothing was saved.",
  "code": "mailbox_tls_failed",
  "request_id": "6f3c0a1e-2d47-4c6b-9a1f-2b7c5f0e8d31"
}
```

**解决方法：**
- 安全设置须与端口匹配：465 和 993 使用 `tls`，587 和 143 使用 `starttls`，除非服务商文档另有说明
- 使用证书签发的主机名，即服务商文档中的主机名，而非别名或 IP 地址

#### `mailbox_server_declined` [#mailbox_server_declined]

`code` 为 `mailbox_server_declined` 的 `400` 来自同一组端点。登录因凭据之外的原因无法完成：服务器要求稍后重试（`4xx` 回复，常见于登录限流）、未提供 Warmbly 实现的登录方式、返回与密码无关的 `5xx`（不支持某种机制、强制要求 STARTTLS）、协议交互中断，或探测在收到回复前自身失败。若服务器有回复，消息会携带该回复。未保存任何内容。

```json
{
  "error": "Bad Request",
  "message": "SMTP (smtp.example.com:587) declined the sign-in for now and asks for a retry: 454 4.7.0 Too many login attempts, please try again later. Nothing was saved.",
  "code": "mailbox_server_declined",
  "request_id": "6f3c0a1e-2d47-4c6b-9a1f-2b7c5f0e8d31"
}
```

**解决方法：**
- 对于 `4xx` 回复，请等待几分钟后重试
- 若服务器仅提供 Warmbly 未实现的机制（NTLM、GSSAPI），请使用服务商文档中的 SMTP 提交主机，通常提供 `LOGIN` 或 `PLAIN`；更换密码不会增加认证机制

#### `mailbox_worker_unreachable` [#mailbox_worker_unreachable]

`code` 为 `mailbox_worker_unreachable` 的 `503` 来自 `DELETE /emails/{id}`。断开邮箱前，必须先通知负责同步的机器，再删除记录，因为记录删除后就无法再通知该机器停止。指令无法投递时，不删除任何内容，邮箱完全保持原样。

```json
{
  "error": "Service Unavailable",
  "message": "This mailbox could not be disconnected right now because the machine syncing it could not be reached. Nothing was removed, so try again in a moment.",
  "code": "mailbox_worker_unreachable",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

**解决方法：**
- 重试删除。可安全重复：邮箱已不存在时返回 `404`，仍存在时保持不变

#### `mailbox_send_as_unsupported` [#mailbox_send_as_unsupported]

`code` 为 `mailbox_send_as_unsupported` 的 `400` 来自 `POST /emails/{id}/identity/refresh`，以及设置 `send_as_email` 的 `PATCH /emails/{id}`。只有 Gmail 和 Google Workspace 邮箱会提供允许使用的发件地址列表；Outlook 或 SMTP/IMAP 邮箱没有此类列表，因此无内容可刷新，也无地址可选择。

```json
{
  "error": "Bad Request",
  "message": "This mailbox's provider does not expose send-as addresses. Only Gmail and Google Workspace mailboxes do.",
  "code": "mailbox_send_as_unsupported",
  "request_id": "9f0a6f21-2c7e-4f2d-9d0e-1f7b9a2c4e55"
}
```

**解决方法：**
- 先读取 `GET /emails/{id}/identity`。这些邮箱的 `supported` 字段为 `false`，`identities` 为空
- 使用邮箱自身地址发送，即将 `send_as_email` 留空

#### `mailbox_send_as_unknown` [#mailbox_send_as_unknown]

`code` 为 `mailbox_send_as_unknown` 的 `400` 来自将 `send_as_email` 设为服务商尚未为该邮箱验证的地址的 `PATCH /emails/{id}`。此处即拒绝选择，而非等到发送时；否则服务商可能几天后才针对营销活动步骤返回拒绝，且没有足以指导修复的信息。

```json
{
  "error": "Bad Request",
  "message": "That address is not one your provider has verified this mailbox to send as. Refresh the list, or add and verify the address in your provider first.",
  "code": "mailbox_send_as_unknown",
  "request_id": "b71c3f88-0b3e-4a41-9a52-2f4f1fd0c0aa"
}
```

**解决方法：**
- 在 Gmail（设置、账户、“用这个地址发送邮件”）中添加别名并完成验证
- 调用 `POST /emails/{id}/identity/refresh`，让 Warmbly 重新读取列表，再将 `send_as_email` 设为 `verified` 为 `true` 的地址

#### `mailbox_signature_too_large` [#mailbox_signature_too_large]

`code` 为 `mailbox_signature_too_large` 的 `400` 来自设置了 `import_signature` 的 `POST /emails/{id}/identity/refresh`。服务商签名超过 Warmbly 存储上限（`20000` 个 HTML 字符），因此拒绝而非截断：不完整签名比没有签名更糟。发件地址列表也不会保存，因此调用不作任何更改。

```json
{
  "error": "Bad Request",
  "message": "The signature on this mailbox is larger than Warmbly stores (20000 characters). Shorten it in your provider and import it again.",
  "code": "mailbox_signature_too_large",
  "request_id": "2d5e9a13-7c41-4f9b-bb17-a0f1d9c6e332"
}
```

**解决方法：**
- 在 Gmail 中缩短签名，通常可将内嵌图片改为图片链接，然后重新导入
- 或通过 `PATCH /emails/{id}` 直接在 Warmbly 中编写签名

#### `mailbox_identity_unavailable` [#mailbox_identity_unavailable]

`code` 为 `mailbox_identity_unavailable` 的 `503` 来自 `POST /emails/{id}/identity/refresh`。读取邮箱发件地址属于账户操作，因此在持有该邮箱的工作节点上执行，而不由 API 自身执行。当该机器不可用时，此操作也不可用：例如邮箱正在工作节点间迁移、工作节点刚重启，或新连接邮箱尚未分配。未作任何更改。

```json
{
  "error": "Service Unavailable",
  "message": "Warmbly could not reach the machine running this mailbox, so its sending addresses were not refreshed. Nothing was changed; try again in a moment.",
  "code": "mailbox_identity_unavailable",
  "request_id": "6e2f1a90-5d13-4a77-9c0b-73f0b5a2e118"
}
```

**解决方法：**
- 请重试。分配通常很快完成，第二次尝试往往成功
- `GET /emails/{id}` 报告邮箱的 `status`；`inactive` 邮箱根本不会分配到工作节点，在重新激活前会持续拒绝

## 错误处理最佳实践 [#error-handling-best-practices]

### 实现重试逻辑 [#implement-retry-logic]

对于暂时性错误（5xx、429），请实现指数退避：

```javascript
async function requestWithRetry(url, options, maxRetries = 3) {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    try {
      const response = await fetch(url, options);

      if (response.ok) {
        return response.json();
      }

      // Don't retry client errors (4xx) except rate limits
      if (response.status >= 400 && response.status < 500 && response.status !== 429) {
        throw new Error(`Client error: ${response.status}`);
      }

      // Retry server errors and rate limits
      if (attempt < maxRetries - 1) {
        const delay = Math.pow(2, attempt) * 1000;
        await new Promise(resolve => setTimeout(resolve, delay));
        continue;
      }
    } catch (error) {
      if (attempt === maxRetries - 1) throw error;
    }
  }
}
```

### 解析错误响应 [#parse-error-responses]

始终解析并处理错误响应：

```javascript
async function apiRequest(url, options) {
  const response = await fetch(url, options);

  if (!response.ok) {
    const error = await response.json();
    throw new ApiError(response.status, error.error, error.message);
  }

  return response.json();
}

class ApiError extends Error {
  constructor(status, type, message) {
    super(message);
    this.status = status;
    this.type = type;
  }
}
```

## 速率限制 [#rate-limiting]

超过速率限制时，您将收到：

```
HTTP/1.1 429 Too Many Requests
Retry-After: 60
```

```json
{
  "error": "Too Many Requests",
  "message": "Rate limit exceeded. Please retry after 60 seconds.",
  "code": "rate_limit_exceeded",
  "request_id": "4bbbd1b2-8f86-47dd-8a7f-9476501ad20e"
}
```

使用 `Retry-After` 响应头确定重试时间。

## 管理员设备请求错误 [#admin-device-request-errors]

[管理员设备流程](/api/authentication/#platform-admin-device-sessions) 新增 `admin_device_expired`（404，无法区分无效、未知、过期或已消费请求）、`admin_device_resolved`（409，已作决定，或同意不匹配/被重放）及 `admin_device_slow_down`（429，轮询间隔短于五秒）。过期后重新开始，冲突时绝不自动批准。尝试额度采用现有 `rate_limit_exceeded`。身份验证/MFA/重新验证及依赖失败保留现有错误码。Redis 失败绝不会授权单因素或匿名管理员。[节点诊断](/api/endpoints/#platform-node-diagnostics) 使用通用错误及显式不可用/过时覆盖状态，而不是推断故障。
