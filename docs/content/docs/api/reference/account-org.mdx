title: "账户与组织"
description: "身份验证、会话、个人资料与安全设置、组织管理、团队和订阅计费。"

本组接口涵盖个人账户及其所属工作区相关功能：登录、会话管理、个人资料和安全设置（通知偏好、双因素身份验证、通行密钥）、组织管理（成员、邀请、自定义角色）、成员团队分组，以及账单。

这里几乎所有端点都仅接受会话，依赖绑定到具体用户的 JWT，API 密钥无法访问。有两类例外：团队端点同时接受 JWT 和 API 密钥；公开身份验证端点，包括登录、注册、刷新、密码重置、通行密钥登录和双因素验证，本身无需会话，因为它们用于创建会话。下方各端点均明确标注身份验证要求。

所有错误响应采用共享封装（`error`、`message`、`code`、`request_id`）。参阅[错误码](/api/error-codes/)。

## 身份验证 [#authentication]

这些端点公开开放，无需会话。登录和注册分两步：首次调用通过邮件发送一次性代码，并返回短期签名 `session` 令牌；第二次调用确认代码，签发正式令牌对。部署启用验证码时，启动调用和两个密码重置调用都需要验证码：浏览器提供 Cloudflare Turnstile 令牌，原生应用提供[App Attest 证明](#app-attest-native-apps)。

### 开始登录 [#start-login]

`POST /auth/login`

向账户邮件地址发送登录代码，并返回签名会话令牌，供确认步骤使用。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `email` | string | 是 | 账户邮件地址。 |
| `password` | string | 是 | 账户密码。 |
| `turnstile` | string | 必填，除非发送了 `app_attest` | Cloudflare Turnstile 令牌。 |
| `app_attest` | object | 否 | 原生应用的[App Attest 证明](#app-attest-native-apps)，替代 `turnstile` 发送。 |

```json
{
  "email": "alex@acme.com",
  "password": "correct horse battery staple",
  "turnstile": "0.abc123..."
}
```

#### 响应 [#response]

```json
{
  "session": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

### 确认登录 [#confirm-login]

`POST /auth/login/confirm`

使用邮件代码和会话令牌换取令牌对。账户启用双因素身份验证时，不返回令牌对；`two_fa_required` 为 `true`，改为返回一次性的 `pending_token`，需将其传给 `/auth/2fa/verify/`。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-1]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `session` | string | 是 | `/auth/login` 返回的令牌。 |
| `code` | string | 是 | 邮件中的一次性代码。 |
| `turnstile` | string | 否 | Cloudflare Turnstile 令牌。 |

```json
{
  "session": "eyJhbGciOiJIUzI1NiIs...",
  "code": "489210"
}
```

#### 响应 [#response-1]

成功时返回完整令牌对：

```json
{
  "access_token": "eyJhbGc...",
  "access_token_expires_at": "2026-06-12T13:00:00Z",
  "refresh_token": "eyJhbGc...",
  "refresh_token_expires_at": "2026-07-12T12:00:00Z"
}
```

启用双因素身份验证时，返回验证挑战，而非会话：

```json
{
  "two_fa_required": true,
  "pending_token": "eyJhbGc...",
  "expires_in": 300
}
```

### 开始注册 [#start-registration]

`POST /auth/register`

创建待确认注册，并通过邮件发送确认代码。返回供确认步骤使用的签名会话令牌。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-2]

结构与 `/auth/login` 相同：`email`、`password`，以及 `turnstile` 或 `app_attest`。

```json
{
  "email": "newuser@acme.com",
  "password": "correct horse battery staple",
  "turnstile": "0.abc123..."
}
```

#### 响应 [#response-2]

```json
{
  "session": "eyJhbGciOiJIUzI1NiIs..."
}
```

### 确认注册 [#confirm-registration]

`POST /auth/register/confirm`

确认邮件代码，创建账户并登录：响应结构与完成 `/auth/login` 相同，即 `token` 对或 `two_fa_required` 挑战，因此客户端可直接进入控制台，无需再次登录。部署不要求验证邮件地址时，`/auth/register` 本身会直接返回该结构。地址已存在账户时，返回 `409` `conflict` 并拒绝，参阅[错误码](/api/error-codes/#409-conflict)。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-3]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `session` | string | 是 | `/auth/register` 返回的令牌。 |
| `code` | string | 是 | 邮件中的一次性代码。 |
| `turnstile` | string | 否 | Cloudflare Turnstile 令牌。 |

#### 响应 [#response-3]

```json
{
  "code_required": false,
  "token": { "access_token": "…", "refresh_token": "…", "access_token_expires_at": "…" }
}
```

### 刷新令牌 [#refresh-token]

`POST /auth/refresh`

使用有效刷新令牌换取新的令牌对。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-4]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `refresh_token` | string | 是 | 有效且未过期的刷新令牌。 |

```json
{
  "refresh_token": "eyJhbGc..."
}
```

#### 响应 [#response-4]

新的令牌对，结构与登录确认成功响应相同（`access_token`、`access_token_expires_at`、`refresh_token`、`refresh_token_expires_at`）。

每次刷新都会轮换令牌对：保存新刷新令牌，丢弃旧令牌。已经交换过的刷新令牌会返回 `401` 并被拒绝。如果在交换后超过两分钟再次提交，视为重复使用，整个会话将结束，向该会话签发的所有令牌停止工作。两分钟内则视为两个调用者同时刷新，仅拒绝此次请求。

### 开始重置密码 [#start-password-reset]

`POST /auth/reset-password`

地址存在账户时，通过邮件发送重置代码。始终返回 `200 OK`，不泄露地址是否存在。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-5]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `email` | string | 是 | 账户邮件地址。 |
| `turnstile` | string | 必填，除非发送了 `app_attest` | Cloudflare Turnstile 令牌。 |
| `app_attest` | object | 否 | 原生应用的[App Attest 证明](#app-attest-native-apps)，替代 `turnstile` 发送。 |

#### 响应 [#response-5]

`200 OK`，响应体为空。

### 确认重置密码 [#confirm-password-reset]

`POST /auth/reset-password/confirm`

使用邮件重置代码设置新密码，代码携带在签名 `session` 令牌中。重置令牌只能使用一次，并绑定到请求重置时的密码：无论通过本端点、登录后的修改，还是运维重置，只要密码被写入，此前签发的所有重置令牌都会返回 `401`，无论自身剩余有效期多长。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-6]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `session` | string | 是 | 与该邮件地址绑定的重置会话令牌。 |
| `password` | string | 是 | 新密码。 |
| `turnstile` | string | 必填，除非发送了 `app_attest` | Cloudflare Turnstile 令牌。 |
| `app_attest` | object | 否 | 原生应用的[App Attest 证明](#app-attest-native-apps)，替代 `turnstile` 发送。 |

#### 响应 [#response-6]

`200 OK`，响应体为空。

### 开始通行密钥登录 [#begin-passkey-login]

`POST /auth/passkey/login/begin`

启动可发现的、无需用户名的 WebAuthn 断言。返回供浏览器传入 `navigator.credentials.get()` 的公钥请求选项。

身份验证：公开端点，API 密钥不可用。

#### 响应 [#response-7]

WebAuthn 断言选项对象，包括挑战、RP ID、允许的凭据和超时，可直接传给 WebAuthn API。完成步骤需回传内嵌的 `session`。

### 完成通行密钥登录 [#finish-passkey-login]

`POST /auth/passkey/login/finish`

验证签名断言，并签发令牌对。通行密钥属于强身份验证，因此没有邮件代码步骤。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-7]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `session` | string | 是 | 开始步骤返回的会话值。 |
| `credential` | object | 是 | 浏览器返回的原始 WebAuthn 断言（`PublicKeyCredential`）。 |

#### 响应 [#response-8]

令牌对，结构与登录确认成功响应相同。

### 验证双重身份验证登录 [#verify-2fa-login]

`POST /auth/2fa/verify`

使用需双因素验证的登录返回的一次性 `pending_token`，加上 TOTP 或恢复码，换取正式会话。

身份验证：公开端点，API 密钥不可用。

#### 请求体 [#request-body-8]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `pending_token` | string | 是 | `/auth/login/confirm` 返回的 `pending_token`。 |
| `code` | string | 是 | 当前有效的 TOTP 代码，或未使用过的恢复码。 |

```json
{
  "pending_token": "eyJhbGc...",
  "code": "123456"
}
```

#### 响应 [#response-9]

令牌对，结构与登录确认成功响应相同。

### 第三方账户登录（原生应用） [#social-sign-in-native-apps]

三个端点均公开开放，API 密钥不可用。服务商验证的身份视为强身份验证，因此没有邮件代码步骤；首次登录会创建账户、组织和试用。

| 端点 | 请求体 | 用途 |
|----------|------|---------|
| `GET /auth/providers` | 无 | 本部署支持的原生登录选项，使移动应用无需重新构建即可适配自托管后端。返回 `{apple, google}` 对象，包含 `enabled` 和公开的 `client_id`。 |
| `POST /auth/apple` | `identity_token`（必填）、`first_name`、`last_name` | 交换“通过 Apple 登录”的身份令牌，使用 Apple 密钥验证。Apple 只会将姓名提供给应用，因此首次登录时应将姓名传入，用于预填。 |
| `POST /auth/google` | `id_token`（必填） | 交换 Google Sign-In ID 令牌，使用 Google 密钥及 `/auth/providers` 中的客户端 ID 验证。 |

Apple 和 Google 均返回令牌对，结构与登录确认成功响应相同；账户已启用 TOTP 时则返回双因素验证挑战。

### App Attest（原生应用） [#app-attest-native-apps]

iOS 应用通过 Apple App Attest 证明自身为真实应用，该证明在需要验证码的调用中替代验证码。浏览器仍发送 Turnstile 令牌。下方两个端点均公开开放，API 密钥不可用，并共用独立的每 IP 额度（`APP_ATTEST_IP_RATE_LIMIT`，默认每十五分钟 300 次），与其余 `/auth` 接口的额度分开。实例关闭 App Attest 时，返回 `404`，错误码为 [`app_attest_unavailable`](/api/error-codes/#app-attest-refusals)。`GET /auth/config` 通过 `app_attest` 报告是否开启。

| 端点 | 请求体 | 用途 |
|----------|------|---------|
| `POST /auth/app-attest/challenge` | 无 | 返回 `{"challenge": "..."}`，其中的 base64url 字符串只能使用一次，五分钟后过期。每次证明和每次断言都必须使用新的挑战。 |
| `POST /auth/app-attest/keys` | `key_id`、`attestation`、`challenge`，均必填 | 注册该应用安装的 App Attest 密钥，每次安装注册一次。`key_id` 是 32 字节密钥标识符的 base64 编码，`attestation` 是 `DCAppAttestService.attestKey` 返回对象的 base64 编码；其客户端数据哈希为 `challenge` 的 UTF-8 字节经过 SHA-256 得到的值。返回 `204`。 |

服务器会根据 Apple App Attest 根证书验证证明的证书链，同时验证随机数、应用 ID、值为 0 的计数器、运行环境（除非实例允许，否则拒绝开发签名构建）和密钥 ID，然后保存密钥。密钥 ID 只能注册一次；再次注册相同 ID 会返回 `app_attest_failed` 并被拒绝。

之后，需要验证码的调用（`POST /auth/login`、`/auth/register`、`/auth/reset-password`、`/auth/reset-password/confirm`）携带 `app_attest` 对象，替代 `turnstile`：

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `key_id` | string | 是 | 已注册的密钥标识符，base64 编码。 |
| `assertion` | string | 是 | `DCAppAttestService.generateAssertion` 返回的 base64 断言。 |
| `challenge` | string | 是 | 从 `POST /auth/app-attest/challenge` 获取的新挑战。 |

```json
{
  "email": "alex@acme.com",
  "password": "correct horse battery staple",
  "app_attest": {
    "key_id": "q1Zf3...=",
    "assertion": "omlzaWduYXR1cmVYRzBF...",
    "challenge": "b3Vy1Wq0..."
  }
}
```

断言使用的客户端数据哈希，是以下 UTF-8 字符串的 SHA-256，各部分之间以换行分隔：

```text
warmbly-app-attest/v1
<action>
<challenge>
```

`<action>` 指定调用类型：`login`、`register`、`reset_password` 或 `reset_password_confirm`。为一种调用生成的证明不能用于另一种。每个挑战由首次提交它的调用消耗，断言计数器必须高于该密钥上次提交的值。每个已注册密钥还具有独立额度，每小时 30 次受保护调用；超出后返回 `400`，消息为 `Too many attempts, please try again later.`，与其他登录尝试额度的响应相同。

证明验证失败时返回 [`app_attest_failed`](/api/error-codes/#app-attest-refusals)。密钥 ID 从未在本服务器注册时返回 `app_attest_key_unknown`：应使用新挑战重新注册密钥，再重试调用。部署未启用验证码时，不检查 `turnstile` 或 `app_attest`。

`GET /auth/config` 同时携带 `captcha` 和 `app_attest`，应用需综合判断：未启用验证码时无需发送任何内容；启用验证码且具有 `app_attest` 时发送证明；启用验证码但没有 `app_attest` 时，应用内无法使用邮件地址和密码登录。通过 Apple、Google 或通行密钥登录始终无需验证码。iOS 模拟器无法使用 App Attest，因此本地开发继续使用 `TURNSTILE_BYPASS_TOKEN`，但仅在 `APP_ENV=dev` 时生效。

### 浏览器登录 [#browser-sign-in]

浏览器无法自行完成服务商身份验证，因此需跳转过去，再携带授权码返回。“通过 Google 登录”、“通过 Apple 登录”和通用 OpenID Connect 都采用相同的三个步骤，只是服务商不同；部署提供的选项见 `GET /auth/config` 中的 `providers` 数组。

| 端点 | 请求体 | 用途 |
|----------|------|---------|
| `POST /auth/google/begin` | 无 | 返回 `{"url": "...", "binding": "..."}`。将浏览器转到 `url`，在该浏览器中保留 `binding`，并在交换时提交。state、nonce 和 PKCE 验证值均由服务端生成和保存。 |
| `POST /auth/apple/begin` | 无 | 相同流程，用于“通过 Apple 登录”。 |
| `POST /auth/oidc/begin` | 无 | 相同流程，用于已配置的 OpenID Connect 服务商。 |
| `GET /auth/google/callback` | 无 | Google 将浏览器返回到此地址。响应重定向至 `<APP_URL>/auth/sso?code=...`；登录被拒绝时重定向至 `<APP_URL>/auth/login?sso_error=...`。 |
| `POST /auth/apple/callback` | 表单 POST | Apple 将浏览器返回到此地址。由于流程请求邮件地址权限范围，Apple 使用 `response_mode=form_post`，因此以表单提交而非重定向方式到达；拒绝情况也接受 `GET`。 |
| `GET /auth/oidc/callback` | 无 | OpenID Connect 服务商将浏览器返回到此地址。 |
| `POST /auth/sso/exchange` | `code` 和 `binding`，均必填 | 将任意回调返回的一次性交接代码换取会话。`POST /auth/oidc/exchange` 是同一端点的旧名称。 |
| `POST /auth/sso/link` | `pending_token` 和 `password`，均必填 | 完成交换返回 `link_required` 的登录。接受已有账户的密码，将服务商身份关联到账户，然后返回会话，或双因素验证挑战。 |

回调绝不返回令牌。它向浏览器交付有效期 60 秒的不透明一次性代码，由客户端通过 `POST` 交换，因此令牌不会出现在 URL、浏览器历史、`Referer` 请求头或代理日志中。交换返回令牌对；账户已启用 TOTP 时，返回双因素验证挑战。

交换还有第三种结果。服务商身份通过 `(issuer, subject)` 组合绑定到账户；新身份首次登录时，会使用已验证邮件地址查找现有账户。如果该账户有密码，交换返回 `link_required: true`，附带 `pending_token`（有效期十分钟）、`link_email` 和 `link_provider`，此时尚未建立关联，也没有会话。客户端应要求输入账户密码，并将其连同令牌提交至 `POST /auth/sso/link`；密码正确后建立身份关联并返回会话，之后通过该服务商登录便可直接找到账户。账户已启用 TOTP 时，改为返回双因素验证挑战，只有 `POST /auth/2fa/verify` 通过后才建立身份关联。密码错误会返回与登录相同的 `Invalid email or password.`，并计入相同的每地址额度；三次错误，或经过十分钟后，挑战以 [`sso_link_expired`](/api/error-codes/) 结束，必须重新开始登录。没有密码的账户，例如通过服务商或邀请创建的账户，无需询问密码，首次登录便会关联。原生端的 `POST /auth/google` 和 `POST /auth/apple` 也返回相同的 `link_required` 结果，并通过同一端点完成。

交换还要求 `begin` 返回的 `binding` 机密值。一次性的 `state` 只能证明回调对应本服务器发出的请求，无法证明对应当前浏览器发出的请求。缺少绑定时，攻击者可能用自己的服务商账户运行流程，再把结果链接发送给你，使你登录其工作区。绑定值不会发送给服务商，也不会出现在 URL 中，因此转发的链接缺少它，会返回 [`sso_wrong_browser`](/api/error-codes/) 并被拒绝。

重定向 URI 由 API 提供，而非控制台，默认为 `<API_PUBLIC_URL>/v1/auth/<provider>/callback`，应在服务商处注册此值。参阅[部署指南](/development/deployment-guide/#sign-in-with-google-or-apple-optional)。

## 会话 [#sessions]

已登录用户的自助会话管理。按 ID 撤销始终只能操作调用者自己的会话。

### 退出登录 [#sign-out]

`POST /auth/logout`

## 双重身份验证 [#two-factor-authentication]

基于 TOTP 的双因素身份验证。启用和管理需要有效会话。登录验证端点本身（`/auth/2fa/verify`）公开开放，已在上文说明。

身份验证：仅限会话，API 密钥不可用。

#### 响应 [#response-21]

```json

  "enabled": true,
```

### 开始启用双重身份验证 [#begin-enrollment]

`POST /auth/2fa/enroll/start`

生成 TOTP 密钥和 `otpauth://` 配置 URI，仅返回一次。客户端将 URI 渲染为二维码；其余字段列明相同参数，供手动输入。

与下方确认启用操作一样，需要近期身份确认（`POST /auth/reauth`），否则返回 `403 reauth_required`。既没有密码也没有双因素验证的账户，可通过通行密钥或已关联登录服务商确认（`GET /auth/reauth/methods`）。这些方式都没有的账户，仅接受最近五分钟内登录的会话；更早的会话返回 `400 reauth_no_factor`。

身份验证：仅限会话，API 密钥不可用。

#### 响应 [#response-22]

```json
{
  "secret": "JBSWY3DPEHPK3PXP",
  "otpauth_uri": "otpauth://totp/Warmbly:alex@acme.com?secret=JBSWY3DPEHPK3PXP&issuer=Warmbly&algorithm=SHA1&digits=6&period=30",
  "issuer": "Warmbly",
  "account": "alex@acme.com",
  "algorithm": "SHA1",
  "digits": 6,
  "period": 30
}
```

### 确认启用双重身份验证 [#confirm-enrollment]

验证 TOTP 代码、启用双因素身份验证，并返回一次性恢复码，恢复码仅显示一次。代码不匹配时返回 `400`，错误码为 `two_fa_invalid_code`。需要与开始启用时相同的近期身份确认。

身份验证：仅限会话，API 密钥不可用。

#### 请求体 [#request-body-14]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `code` | string | 是 | 身份验证器当前的 TOTP 代码。 |

#### 响应 [#response-23]

```json
{
  "recovery_codes": ["a1b2-c3d4", "e5f6-g7h8", "..."]
}
```

### 重新生成恢复码 [#regenerate-recovery-codes]

`POST /auth/2fa/recovery-codes`

将全部恢复码替换为新集合，仅返回一次。请求体需要当前 TOTP 或恢复码；不匹配时返回 `400`，错误码为 `two_fa_invalid_code`。新集合签发后，旧码立即失效。此处及 `DELETE /auth/2fa` 的错误代码尝试，与 `POST /auth/reauth` 计入同一账户尝试额度；耗尽后，两者均返回 `400` 和“尝试次数过多”，直到额度重置。无需 `Idempotency-Key`：证明代码只能使用一次，因此重试请求会被拒绝，不会重复轮换。

身份验证：仅限会话，API 密钥不可用。

#### 请求体 [#request-body-15]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `code` | string | 是 | 当前 TOTP 或恢复码。 |

#### 响应 [#response-24]

```json
{
  "recovery_codes": ["a1b2-c3d4", "e5f6-g7h8", "..."]
}
```

## 组织 [#organizations]

组织即工作区租户。这些端点处理工作区创建和切换、当前工作区及其限制、成员、自定义角色、邀请、所有权转移、头像和工作区危险操作区。所有 `/organization/*` 路由仅接受会话。修改操作由调用者的组织角色权限控制，各端点分别注明。

### 获取工作区发送限制状态 [#get-the-workspace-sending-posture]

`GET /organization/current/risk`

返回工作区的滥用风险处置状态，受限时同时说明原因。任何成员均可读取：发送受限的工作区应能够看到这一状态。

身份验证：仅限会话，API 密钥不可用。

#### 响应 [#response-33]

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `state` | string | `trusted`、`watch`、`restricted` 或 `suspended`。 |
| `restricted` | boolean | `restricted` 和 `suspended` 时为 true，发送量降低。 |
| `suspended` | boolean | 完全停止发送时为 true。 |
| `reason` | string | 有摘要时，提供通俗说明。 |

```json
{
  "state": "restricted",
  "restricted": true,
  "suspended": false,
  "reason": "imported list is 30% invalid; disposable signup domain"
}
```

有意不返回状态背后的检测证据。这些信息供运维人员使用；向被检测方提供触发判断的精确信号，会帮助其规避后续检查。各状态含义及可能触发它们的信号见[工作区发送限制状态](/guides/deliverability/)。

### 列出时区 [#list-timezones]

`GET /timezones`

返回控制台选择器使用的时区列表，每项显示名称带有当前 UTC 偏移量。任何设置时区的位置，包括营销活动日程、邮箱和工作区，都接受任意 IANA 名称，因此该列表只是便于选择，并非全部有效值集合。

身份验证：任意已通过身份验证的调用者，JWT 或 API 密钥均可。
