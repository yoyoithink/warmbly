title: "收件箱投递位置测试"
description: "启动单次或批量投递位置测试，读取每封测试邮件的实际投递位置，管理工作区的种子测试邮箱，并安排营销活动的投递位置监控。"
---

收件箱投递位置测试会从工作区中的一个邮箱，将模板或营销活动步骤发送到一组种子收件箱，并报告每封副本实际到达的位置：主收件箱、Gmail 分类标签页、垃圾邮件，或始终未到达。[投递位置测试指南](/guides/placement-tests/)介绍测试邮件如何渲染、发送和查找，以及如何解读结果。

每条路由都限定在所选组织内，API 密钥始终绑定到一个组织；请求中的每个 ID 都会据此检查。发件邮箱、营销活动、步骤或联系人属于其他工作区时，返回 `404`。错误使用共享的 `{error, message, code, request_id}` 封装；这些路由新增的错误码列于[投递位置测试拒绝原因](/api/error-codes/#placement-test-refusals)。

测试开始、每次出现新的判定结果，以及测试完成或取消时，变更会以 `PLACEMENT_TEST_UPDATED` 事件实时推送到组织的[实时通信](/api/realtime/)通道。批次开始、跳过或延后某个邮箱，以及完成时，也会发送同一事件，以 `batch_id` 替代 `test_id`。

## 获取概览 [#get-the-overview]

`GET /placement/overview`

返回工作区可使用的种子邮箱组，包括各组的种子数量、服务商分布，以及工作区月度额度。

身份验证：**权限范围** `READ_ANALYTICS` · **组织权限** `view_analytics`


| 字段 | 说明 |
|-------|-------------|
| `panels[].panel` | `instance`（运维人员维护的邮箱组）、`workspace`（工作区自己的种子收件箱）或 `cloud`（Warmbly Cloud 邮箱组）。自托管实例会列出 `cloud`，其他环境仅在可用时列出 |
| `panels[].available` | 当前能否在该邮箱组上运行测试。不能时，`reason` 用一句话说明原因 |
| `panels[].families` | 各服务商类别的种子数。`family` 是稳定 ID（`gmail`、`google_workspace`、`microsoft365`、`outlook`、`yahoo`、`aol`、`icloud`、`zoho`、`fastmail`、`gmx`、`proton`、`yandex`、`other` 等）；`label` 是显示名称 |
| `panels[].metered` | 在该邮箱组上测试是否计入月度额度 |
| `usage` | 当前 UTC 自然月已使用的免费测试数，相对于当月免费测试额度 `limit`。使用积分付费的测试，或结束时没有任何副本成功投递的测试，不计入此数。实例不计量测试时，`limit` 为 `null`；自托管实例始终如此 |
| `usage.credits_per_test` | 免费测试用尽后，在 `instance` 邮箱组运行一次测试所需的积分。无法付费测试时为 `0`，此时免费额度已用尽的工作区须等到下个月 |
| `usage.credit_balance` | 工作区可用积分；积分功能关闭时为 `null` |
| `seeds_per_test` | 单次测试最多发送到多少个种子收件箱 |
| `spacing_seconds` | 同一发件邮箱发送两封测试副本之间的平均间隔 |

## 启动测试 [#start-a-test]

`POST /placement/tests`

启动一次测试，或用于跟踪对比的两次关联测试。所有检查，包括功能资格、额度、进行中的测试数、发件邮箱状态和每日上限、可用种子，均在安排任何发送前完成，因此被拒绝的请求不会发送邮件，也不会扣费。付费测试启动时扣除积分，如果最终没有任何副本成功投递，会自动退款；`insufficient_credits`（`402`）或 `usage_cap_exceeded`（`429`）拒绝不会扣费。支持 `Idempotency-Key`，使用相同键重试绝不会重复扣费。

身份验证：**权限范围** `SEND_CAMPAIGNS` · **组织权限** `send_campaigns`

### 请求体 [#request-body]

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `sender_account_id` | uuid | 是 | 发送全部副本的邮箱。必须已连接且处于有效状态，不能是种子收件箱；如果 API 密钥有邮箱允许列表，还必须是密钥获准使用的邮箱 |
| `campaign_id` | uuid | 否 | 使用此营销活动的设置进行测试，包括退订说明、跟踪和附件 |
| `sequence_id` | uuid | 否 | `campaign_id` 中的一个步骤。请求未提供主题和正文时，使用该步骤的内容。需要同时提供 `campaign_id` |
| `contact_id` | uuid | 否 | 用于渲染联系人合并字段和 AI 内容块的联系人。默认使用营销活动的首位潜在客户；但在 `cloud` 邮箱组中，默认使用占位联系人，除非你明确选择联系人，否则不会让潜在客户详情离开实例。未使用联系人时省略 AI 内容块 |
| `subject` | string | 否 | 邮件主题。没有可读取主题的步骤时必填 |
| `body_html` | string | 否 | HTML 正文。测试必须提供此字段或 `body_plain` |
| `body_plain` | string | 否 | 纯文本正文 |
| `tracking` | string | 否 | `campaign`（默认：采用营销活动自身的打开和点击跟踪设置，临时测试则不跟踪）、`on`、`off`，或 `compare`（向同一组种子分别运行不跟踪和启用跟踪的两次测试，每个种子在两次测试中收到相同的渲染内容） |
| `panel` | string | 否 | `instance`（默认）、`workspace` 或 `cloud` |
| `families` | string[] | 否 | 仅使用这些服务商类别的种子，取值见 `panels[].families[].family`。适用于所有邮箱组；`instance` 和 `cloud` 的地址已脱敏，因此这是缩小测试范围的唯一方式。如果邮箱组中没有这些服务商的种子，会返回 `placement_no_seeds` 并拒绝测试 |
| `pace` | string | 否 | `spaced`（默认，副本间隔约 60 秒）或 `quick`（约 8 秒，使测试在数分钟内发完） |
| `max_credits` | integer | 否 | 当月 `instance` 邮箱组免费测试用尽后，你同意为此次测试支付的最高积分。价格超过此值，或未提供此字段的请求，会返回 `placement_quota_exceeded`，其 `message` 会说明价格，且不扣费。仍有免费测试时忽略此字段 |
| `seed_ids` | uuid[] | 否 | 仅适用于 `panel` 为 `workspace`：只向工作区中指定的种子收件箱发送。每个邮箱都必须是本工作区已连接且正在运行的种子收件箱，否则返回 `placement_invalid_seeds` 并列出不符合要求的邮箱。每个指定种子都会收到一封副本，`seeds_per_test` 不限制手动选择的列表。如果发件邮箱每日额度无法覆盖全部种子，则返回 `placement_daily_budget` 并拒绝请求，不会只发送其中一部分。与发件邮箱同域名的种子仍会照常跳过。省略时由测试自动选择 |

```json
{
  "sender_account_id": "a0a1a2a3-0000-0000-0000-000000000003",
  "campaign_id": "b1f2c3d4-0000-0000-0000-000000000001",
  "sequence_id": "c7d8e9f0-0000-0000-0000-000000000002",
  "tracking": "compare"
}
```

## 列出测试 [#list-tests]

`GET /placement/tests`

返回工作区的测试，按最新优先排序，每项包含统计数量。列表省略副本正文。

身份验证：**权限范围** `READ_ANALYTICS` · **组织权限** `view_analytics`

| 参数 | 位置 | 类型 | 说明 |
|-----------|----|------|-------------|
| `limit` | query | integer | `1` 至 `100`，默认 `25`。其他值返回 `400` |
| `cursor` | query | string | 来自此前 `pagination.next_cursor` 的不透明游标。不是由本 API 签发的游标会返回 `400` |
| `campaign_id` | query | uuid | 仅返回此营销活动的测试 |

| `status` | `running`、`completed`、`cancelled` 或 `failed`。没有任何副本成功投递时，测试失败，原因见 `error` |

| `credits_settled_at` | 付费测试结束后完成结算的时间：没有投递则退款，否则保留扣费。免费测试或尚未结算时为 `null` |
| `summary` | 全部副本的统计。`delivered` 等于 `inbox + promotions + other + spam + missing`，包含每封已离开发件邮箱且获得判定结果的副本 |
| `summary.*_rate` | 占 `delivered` 的比例，范围 `0` 至 `1`；尚无投递时为 `null`。`tabs_rate` 包含 `promotions` 和 `other` |
| `families` | 按服务商类别划分的相同统计 |

`GET /placement/tests/:id`

身份验证：**权限范围** `READ_ANALYTICS` · **组织权限** `view_analytics`

### 响应 [#response-3]

```json

    "id": "d1e2f3a4-0000-0000-0000-000000000010",

    "body_plain": "Hi Dana,\n\n...",
    "status": "completed",
    "panel": "instance",
    "summary": { "total": 38, "inbox": 27, "delivered": 38, "inbox_rate": 0.7105 },
    "families": [],
    "results": [
      {
        "seed": "a***@gmail.com",
        "family": "gmail",
        "family_label": "Gmail",
        "folder": "promotions",
        "scheduled_at": "2026-09-25T14:00:05Z",
        "sent_at": "2026-09-25T14:00:06Z",

      }
    ],
    "content": {
      "score": 84,
      "issues": []
    }
  }

```

测试自身字段与[列出测试](#list-tests)中相同，另加 `body_html` 和 `body_plain`；示例作了精简。

| 字段 | 说明 |
|-------|-------------|
| `results[].seed` | 种子地址，在 `instance` 和 `cloud` 邮箱组中脱敏，在 `workspace` 中完整显示 |
| `results[].folder` | `pending`、`inbox`、`promotions`、`other`（其他 Gmail 分类标签页：动态、社交或论坛）、`spam`、`missing`（`sent_at` 后 120 分钟内未发现）、`failed`（始终未离开发件邮箱，原因见 `error`）或 `cancelled` |
| `content` | 测试内容的建议性评分，结构与[为模板内容评分](/api/reference/deliverability-ops/#score-template-content)相同 |

## 取消测试 [#cancel-a-test]

`POST /placement/tests/:id/cancel`

停止尚未发送的副本。已发送的副本继续进行分类。支持 `Idempotency-Key`。

身份验证：**权限范围** `SEND_CAMPAIGNS` · **组织权限** `send_campaigns`

### 响应 [#response-4]

`200 OK`，包含与列表结构相同的测试。测试已经结束时，返回 `409` 和 `placement_not_running`。

## 启动批次 [#start-a-batch]

`POST /placement/batches`

从多个发件邮箱运行相同测试。首先整体验证请求，包括内容、邮箱组、跟踪、额度和同意支付的积分，然后解析并保存发件邮箱列表，立即返回状态为 `queued` 的批次。请求本身不会发送任何邮件：后端每次启动少量邮箱，各自运行独立测试，轮到该邮箱时再检查其每日上限、连接和工作节点。参阅[批量测试发件邮箱](/guides/placement-tests/#testing-a-fleet-with-batches)。支持 `Idempotency-Key`。

身份验证：**权限范围** `SEND_CAMPAIGNS` · **组织权限** `send_campaigns`

### 请求体 [#request-body-1]

内容字段与[启动测试](#start-a-test)相同：`campaign_id`、`sequence_id`、`contact_id`、`subject`、`body_html`、`body_plain`、`tracking`、`panel`、`families` 和 `seed_ids`。批次的 `pace` 始终为 `spaced`；使用 `quick` 返回 `400`。创建批次时只解析一次内容，因此每个发件邮箱测试的是同一封邮件。批次不使用 `sender_account_id`，而必须且只能提供以下两项之一：

| 字段 | 类型 | 说明 |
|-------|------|-------------|
| `sender_account_ids` | uuid[] | 指定的这些邮箱。重复项会被去除；不属于工作区或属于种子收件箱的邮箱返回 `404`；API 密钥邮箱允许列表不允许使用的邮箱返回 `403`。已断开连接的邮箱仍会保留，轮到它时再延后或跳过 |
| `sender_scope` | object | 由服务端解析邮箱集合，因此数千个邮箱也无需提供 ID 列表 |
| `sender_scope.type` | string | `campaign`（`campaign_id` 的调度器实际用于发送的所有邮箱），或 `workspace`（工作区的所有邮箱） |
| `sender_scope.campaign_id` | uuid | `type` 为 `campaign` 时必填 |
| `sender_scope.providers` | string[] | 仅选择由这些类别服务商托管的邮箱，例如 `google_workspace`、`gmail`、`microsoft365`、`outlook` 或 `other` |
| `sender_scope.domains` | string[] | 仅选择使用这些域名发送的邮箱 |
| `sender_scope.tag_ids` | uuid[] | 仅选择带有这些标签之一的邮箱 |
| `sender_scope.include_inactive` | boolean | 保留已断开连接的邮箱。默认 `false` |
| `sender_scope.untested_days` | integer | 仅选择最近指定天数内没有完成投递位置测试的邮箱，范围 `1` 至 `365` 天 |

| 字段 | 类型 | 必填 | 说明 |
|-------|------|----------|-------------|
| `sample` | object | 否 | 从解析出的邮箱中保留哪些。默认 `{"mode": "all"}` |
| `sample.mode` | string | 否 | `all`、`random`（选取 `count` 个邮箱）、`percent`（选取其中 `percent` 的比例，向上取整）、`per_domain` 或 `per_provider`（每组最多 `count` 个） |
| `sample.stratify` | string | 否 | 仅适用于 `random` 或 `percent`：`provider` 或 `domain` 会按各组所占比例分配样本 |
| `on_unavailable` | string | 否 | `defer`（默认：轮到邮箱时无法发送则重试，最长七天），或 `skip` |
| `max_credits` | integer | 否 | 当月免费测试之外，你同意整个批次最多支付的积分。仅在批次所需测试数超过免费额度时需要；该值不足时，请求返回 `placement_quota_exceeded` 并说明最高可能费用。批次绝不会超出该金额 |

```json
{
  "sender_scope": { "type": "campaign", "campaign_id": "b1f2c3d4-0000-0000-0000-000000000001", "providers": ["google_workspace"] },
  "sample": { "mode": "percent", "percent": 10, "stratify": "domain" },
```

## 获取批次 [#get-a-batch]

`GET /placement/batches/:id`

返回单个批次，以及在所有发件邮箱间分组汇总的投递位置。

身份验证：**权限范围** `READ_ANALYTICS` · **组织权限** `view_analytics`

### 响应 [#response-7]

除上述批次字段外，还包含：

| 字段 | 说明 |
|-------|-------------|
| `untracked` | 仅在跟踪对比中出现：未启用跟踪的一半的计数。`summary` 为启用跟踪的一半 |
| `domains` | 按发件域名分组，收件箱到达率最低的在前：`key`（域名）、批次中的 `senders`、`tested`（已完成测试的发件邮箱）和 `counts` |

| `recipients` | 按收件服务商类别的计数，与单个测试的 `families` 类似 |
| `matrix` | 按 `domains` 顺序列出各发件域名，并按 `recipients` 顺序列出其各收件服务商计数 |
| `content` | 批次内容的评分 |

各分组统计的内容版本与 `summary` 相同。不按工作节点划分：工作节点只负责登录邮箱服务商，实际投递由服务商自身的服务器完成，因此收件方过滤器看不到工作节点。

## 设置营销活动的投递位置监控 [#set-a-campaigns-placement-monitor]

`PUT /campaigns/:id/placement-monitor`

创建或更新营销活动监测器。所有字段均可选：省略字段保留当前值，新监测器则采用默认值。请求体声明期望值，而非增量变更，因此重试会得到相同状态。新建或重新启用的监测器会在约五分钟内运行首次测试；修改 `interval_days` 会将下次运行时间调整为上次运行后经过该间隔的时间。

每次运行都会测试营销活动中第一个同时具有主题和正文的邮件步骤，使用首位潜在客户渲染，采用活动自身的跟踪设置，并轮流使用营销活动发件邮箱中的下一个邮箱。仅在营销活动为 `active` 时运行，与其他测试一样计入测试额度和邮箱每日上限。

身份验证：**权限范围** `SEND_CAMPAIGNS` · **组织权限** `send_campaigns`

### 请求体 [#request-body-3]

| 字段 | 类型 | 默认值 | 说明 |
|-------|------|---------|-------------|
| `enabled` | boolean | `true` | 是否运行监测器 |
| `interval_days` | integer | `7` | 运行间隔天数，`1` 至 `30` |
| `panel` | string | `instance` | `instance`、`workspace` 或 `cloud` |
| `alert_below` | integer | `70` | 收件箱百分比，`0` 至 `100`。某次运行的主收件箱占比低于该值时，会向所有有权查看营销活动的成员发送 `placement_alert` 通知 |
| `pause_on_alert` | boolean | `false` | 发出警报时同时暂停营销活动。活动转为 `paused_guardrail`，并在活动日志中记录原因；保持暂停，直到再次启动 |

```json
{ "interval_days": 3, "alert_below": 80, "pause_on_alert": true }
```

### 响应 [#response-14]

`200 OK`，包含上述结构的监测器。
