---
title: "CRM"
description: "管理组织的销售管道、阶段、商机、任务类型和 CRM 任务，并通过 HubSpot 或 Pipedrive 使用 CRM。"
---

CRM 端点描述你的销售流程：商机在销售管道的各阶段间流转，CRM 任务记录关联联系人和商机的跟进工作。每条路由都限定在组织范围内，会话或 API 密钥必须具有当前组织。读取使用 **CRM** 读取权限范围（`READ_CRM` / 组织权限 `view_contacts`），修改使用 **CRM** 写入权限范围（`WRITE_CRM` / 组织权限 `manage_contacts`），但团队成员操作例外，需要 `manage_team`。权限范围与 API 密钥及成员角色的映射见[身份验证](/api/authentication/)和[权限](/api/permissions/)。

每个列表端点都返回 `data` 数组和标准 `pagination` 封装，其中包含不透明的 `next_cursor`。简单的 `GET` 列表端点使用键集游标；多条件 `POST .../search` 端点由于排序列可为空，无法使用键集游标，内部按偏移量分页，但仍提供相同的不透明 `next_cursor`，并额外返回准确的 `total`。

## 创建销售管道 [#create-pipeline]

`POST /crm/pipelines`

创建销售管道，可同时初始化一组有序阶段。

身份验证：**权限范围** `WRITE_CRM` · **组织权限** `manage_contacts`

### 请求体 [#request-body]

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 销售管道名称，1 至 255 个字符。 |
| `stages` | array | 否 | 随销售管道一同创建的阶段，按顺序排列。 |
| `stages[].name` | string | 是 | 阶段名称，1 至 255 个字符。 |
| `stages[].color` | string | 是 | 阶段颜色，十六进制。 |

```json
{
  "name": "Sales",
  "stages": [
    { "name": "Lead", "color": "#0ea5e9" },
    { "name": "Qualified", "color": "#8b5cf6" },
    { "name": "Won", "color": "#22c55e" }
  ]
}
```

### 响应 [#response-1]

`201 Created`，包含创建的销售管道对象，结构与列表响应一致，包含其 `stages`。

```json
{
  "id": "5d8a2b1e-0c4f-4a9b-9f2e-1a2b3c4d5e6f",
  "organization_id": "0a1b2c3d-4e5f-6071-8293-a4b5c6d7e8f9",
  "name": "Sales",
  "position": 0,
  "stages": [
    {
      "id": "7f3c1a90-2b4d-4e6f-8a01-b2c3d4e5f607",
      "pipeline_id": "5d8a2b1e-0c4f-4a9b-9f2e-1a2b3c4d5e6f",
      "name": "Lead",
      "color": "#0ea5e9",
      "position": 0,
      "created_at": "2026-06-12T10:00:00Z",
      "updated_at": "2026-06-12T10:00:00Z"
    }
  ],
  "created_at": "2026-06-12T10:00:00Z",
  "updated_at": "2026-06-12T10:00:00Z"
}
```

## 搜索商机 [#search-deals]

`POST /crm/deals/search`

支持多条件筛选和服务端分页的商机搜索。所有筛选均可选，空请求体匹配组织的全部商机。筛选条件放在 JSON 请求体中，`limit` 和 `cursor` 则为查询参数。

身份验证：**权限范围** `READ_CRM` · **组织权限** `view_contacts`

| 参数 | 位置 | 类型 | 说明 |
| --- | --- | --- | --- |
| `limit` | query | int | 每页数量，范围 1 至 200，默认 50。 |
| `cursor` | query | string | 上一页 `pagination.next_cursor` 中的不透明游标。第一页省略。 |

### 请求体 [#request-body-5]

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `query` | string | 否 | 不区分大小写地匹配商机名称。 |
| `statuses` | string[] | 否 | `open`、`won`、`lost` 中的任意项。 |
| `pipeline_ids` | string[] | 否 | 限定为这些销售管道中的商机。 |
| `stage_ids` | string[] | 否 | 限定为这些阶段中的商机。 |
| `assigned_to` | string[] | 否 | 负责人为这些用户 ID 之一。 |
| `campaign_ids` | string[] | 否 | 归因营销活动为这些活动之一。 |
| `min_value` | number | 否 | 金额大于或等于此值。 |
| `max_value` | number | 否 | 金额小于或等于此值。 |
| `close_after` | string (date-time) | 否 | 预计成交日期不早于此日期。 |
| `close_before` | string (date-time) | 否 | 预计成交日期不晚于此日期。 |
| `created_after` | string (date-time) | 否 | 创建时间不早于此时间。 |
| `created_before` | string (date-time) | 否 | 创建时间不晚于此时间。 |
| `sort_by` | string | 否 | 取值为 `created_at`、`updated_at`、`value`、`expected_close_date`、`name` 之一。 |
| `reverse` | boolean | 否 | `true` 为升序，`false` 为降序，默认降序。 |

```json
{
  "query": "renewal",
  "statuses": ["open"],
  "pipeline_ids": ["5d8a2b1e-0c4f-4a9b-9f2e-1a2b3c4d5e6f"],
  "min_value": 1000,
  "sort_by": "value",
  "reverse": false
}
```

### 响应 [#response-10]

包含商机对象的 `data` 数组，附有关联的 `contact`、`stage` 和 `campaign_name`，加上标准 `pagination` 封装，包含不透明的 `next_cursor` 和准确的 `total`。

```json
{
  "data": [
    {
      "id": "1f2e3d4c-5b6a-4789-90ab-cdef01234567",
      "organization_id": "0a1b2c3d-4e5f-6071-8293-a4b5c6d7e8f9",
      "pipeline_id": "5d8a2b1e-0c4f-4a9b-9f2e-1a2b3c4d5e6f",
      "stage_id": "7f3c1a90-2b4d-4e6f-8a01-b2c3d4e5f607",
      "name": "Acme renewal",
      "value": 12000,
      "currency": "USD",
      "status": "open",
      "created_at": "2026-06-01T12:00:00Z",
      "updated_at": "2026-06-10T09:30:00Z"
    }
  ],
  "pagination": {
    "total": 137,
    "next_cursor": "o1_NTA",
    "has_more": true
  }
}
```

## 商机摘要 [#deals-summary]

`POST /crm/deals/summary`

使用与商机搜索相同的筛选请求体，汇总数量和金额，使顶部总计和各阶段看板列总计反映完整匹配集合，而非单页。

身份验证：**权限范围** `READ_CRM` · **组织权限** `view_contacts`

### 请求体 [#request-body-6]

与[搜索商机](#search-deals)相同。所有筛选维度均可选，空请求体汇总组织全部商机。

```json
{
  "pipeline_ids": ["5d8a2b1e-0c4f-4a9b-9f2e-1a2b3c4d5e6f"],
  "statuses": ["open", "won"]
}
```

### 响应 [#response-11]

返回汇总对象。`stages` 包含各阶段数量及未结商机金额。匹配商机涉及多种货币时，`mixed_currency` 为 `true`，此时顶层金额总和应视为近似值。

```json
{
  "total": 42,
  "open_count": 30,
  "open_value": 415000,
  "won_count": 9,
  "won_value": 220000,
  "lost_count": 3,
  "lost_value": 0,
  "currency": "USD",
  "stages": [
    {
      "stage_id": "7f3c1a90-2b4d-4e6f-8a01-b2c3d4e5f607",
      "count": 18,
      "value": 240000
    }
  ],
  "mixed_currency": false
}
```

## 更新商机 [#update-deal]

`PATCH /crm/deals/:id`

## 选择多个任务 [#selecting-many-tasks]

以下两个批量端点接受相同的**选择范围**，有两种形式。可以明确列出 ID：

```json
{ "tasks": ["3b4c5d6e-7f80-4912-a3b4-c5d6e7f80912"] }
```

也可以选择搜索匹配的全部任务，再排除取消选择的任务：

```json
{
  "all": true,
  "filters": { "statuses": ["pending"], "query": "out_of_office" },
  "exclude": ["3b4c5d6e-7f80-4912-a3b4-c5d6e7f80912"]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `tasks` | string[] | 未设置 `all` 时 | 任务 ID。每次请求最多 `1000` 个。 |
| `all` | boolean | 否 | 将选择方式从 `tasks` 切换为 `filters`。 |
| `filters` | object | 设置 `all` 时 | 与[搜索任务](#search-tasks)使用相同请求体，因此实际操作集合与搜索返回的集合完全一致。 |
| `exclude` | string[] | 否 | 从解析后的集合中移除的 ID。仅在设置 `all` 时生效。 |

选择范围解析后超过 `50,000` 个任务时，会返回 `selection_too_large` 并拒绝，而不会只应用一部分；应缩小筛选范围，分批执行。`filters` 中的 `assigned_to`、`contact_id` 或 `deal_id` 如果不是有效 ID，会返回 `invalid_filter` 并拒绝。

批量更新针对整次调用只触发一个 `crm.task_updated` [Webhook](/api/reference/webhooks/)，而不是每个任务各触发一个；事件携带 `metadata.bulk` 和 `metadata.count`，不含 `entity_id`。批量删除不会触发事件，因为单个任务删除也不会触发。

两个端点都不接受 `Idempotency-Key`：它们写入最终状态而非增量，因此重复调用会收敛到相同结果，但重复调用的返回计数不同。重复删除会找到更少记录，`affected` 最终降至 `0`。重复更新仍会触及选择范围中的每一行，因为会写入 `updated_at`，所以 `affected` 不会下降；状态和优先级只是保持不变。重复完成操作不会向联系人时间线添加第二条记录，也不会改变 `completed_at`。

## CRM 服务商模式 [#crm-provider-mode]

工作区可使用 [HubSpot](/guides/hubspot/) 或 [Pipedrive](/guides/pipedrive/) 运行 CRM，替代 Warmbly 内置 CRM。在外部 CRM 模式下，上述端点保持相同结构，返回的记录来自服务商并镜像到 Warmbly。HubSpot 模式下：

- 创建、更新或删除商机、任务和备注时，先写入 HubSpot，再在本地保存。HubSpot 拒绝时会返回错误，不保存任何内容；参阅[CRM 服务商操作被拒绝的情况](/api/error-codes/#crm-provider-refusals)；
- 创建、更新或删除销售管道、阶段和任务类型时，返回 `409 crm_managed_externally`。`GET /crm/pipelines` 只列出 HubSpot 销售管道，`GET /crm/task-types` 返回 HubSpot 的四种类型（To-do、Call、Email、LinkedIn）；
- 未提供 `pipeline_ids` 筛选时，`POST /crm/deals/search` 和 `POST /crm/deals/summary` 只涵盖 HubSpot 销售管道，排除仅存在于 Warmbly 管道中的商机；
- 将商机 `status` 设为 `won` 或 `lost`，会将其移到管道中该类型的第一个结束阶段；将商机移到结束阶段，也会设置其 `status`。`assigned_to` 必须是已匹配 HubSpot 负责人的成员，否则返回 `400 crm_owner_unmapped`。

Pipedrive 模式遵循相同原则，但采用 Pipedrive 的数据模型：

- 任务对应 Pipedrive 活动。`GET /crm/task-types` 返回公司的活动类型；任务的 `status` 会写为已完成（`completed`、`cancelled`）或未完成，`priority` 则保留在 Warmbly；
- 商机 `status` 对应 Pipedrive 自身的商机状态，因此 `won` 和 `lost` 不改变商机阶段。`lost_reason` 随 `lost` 状态写入。`assigned_to` 必须是已匹配 Pipedrive 用户的成员，否则返回 `400 crm_owner_unmapped`；
- Pipedrive 没有生命周期阶段或潜在客户状态。联系人的 `lifecycle_stage` 是其第一个人员标签，使用 `GET /crm/metadata` 中的 ID；`lead_status` 始终为空。

存在于外部 CRM 的商机、任务、备注和销售管道带有 `external` 对象；镜像管道中的阶段带有该服务商的阶段元数据。非外部 CRM 模式下，两者均省略。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `external.provider` | string | `hubspot` 或 `pipedrive`。 |
| `external.external_id` | string | 外部 CRM 的记录 ID。 |
| `external.url` | string | 在外部 CRM 中打开记录的位置：商机、任务视图（Pipedrive 中为活动关联的商机，否则为活动列表）、备注关联的联系人，或销售管道。未知时省略。 |
| `external.synced_at` | string (date-time) | 上次向外部 CRM 写入或从其读取该记录的时间。 |
| `external.owner_name` | string | 商机或任务的负责人不是工作区成员时，返回外部 CRM 的负责人，此时 `assigned_to` 为空。 |
| `stages[].closed` | boolean | 该阶段是 HubSpot 的结束阶段。为 false 时省略；Pipedrive 中始终省略。 |
| `stages[].won` | boolean | 该阶段是 HubSpot 的赢单结束阶段。为 false 时省略；Pipedrive 中始终省略。 |
| `stages[].probability` | number | 外部 CRM 对该阶段设置的商机成交概率，范围 `0` 至 `1`。 |

```json
{
  "id": "1f2e3d4c-5b6a-4789-90ab-cdef01234567",
  "name": "Acme renewal",
  "status": "open",
  "external": {
    "provider": "hubspot",
    "external_id": "18342007291",
    "url": "https://app.hubspot.com/contacts/4711/record/0-3/18342007291",
    "synced_at": "2026-06-10T09:30:04Z",
    "owner_name": "Dana Kim"
  }
}
```

## 更新 CRM 设置 [#update-crm-settings]

`PUT /crm/settings`

选择 CRM 并保存设置选项。切换到 HubSpot 时，若开启 `write_properties`，会在 HubSpot 创建 Warmbly 联系人属性组，并在后台启动首次拉取。切换到 Pipedrive 时，未发送 `config` 则根据公司自身标签填充标签规则，然后添加 Warmbly 人员字段、注册变更通知并启动首次拉取。从一个服务商切换到另一个时，会替换原连接，原服务商保存的选项会重置为新服务商默认值。此操作写入最终状态，因此可安全重试。

身份验证：**权限范围** `INTEGRATIONS` · **组织权限** `manage_settings`

### 请求体 [#request-body-15]

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `provider` | string | 否 | `native`、`hubspot` 或 `pipedrive`。 |
| `connection_id` | uuid | 否 | 工作区的 HubSpot 或 Pipedrive [集成连接](/api/reference/integrations/)。首次使用该服务商时必须提供。 |
| `config` | object | 否 | 完整选项集合，替换已存集合。结构见上方响应。 |
| `complete_setup` | boolean | 否 | 将设置向导标为已完成。 |

`config` 保存前会验证：`field_map` 的键可为 `first_name`、`last_name`、`email`、`company`、`phone` 或 `custom:<key>`；每个 `field_direction` 条目必须为 `push`、`pull` 或 `both`，并指定已映射字段；`deal_pipelines` 为外部 CRM 管道 ID，空表示全部，最多 50 项；`display_properties` 最多 40 项，`field_map` 最多 100 项，各生命周期阶段列表最多 20 项。`positive_reply.create_deal` 需要 `deal_pipeline_id` 和 `deal_stage_id`，它们是镜像管道及阶段在 Warmbly 中的 ID。

```json
{
  "provider": "hubspot",
  "connection_id": "6e7f8a9b-0c1d-4e2f-8a3b-4c5d6e7f8a9b",
  "complete_setup": true
}
```

### 响应 [#response-29]

设置对象，与 `GET /crm/settings` 返回相同。连接缺少外部 CRM 模式所需权限时，返回 `409 crm_reauth_required`；`connection_id` 不是工作区连接到该服务商的连接时，返回 `400`。

## 将 Warmbly CRM 数据复制到服务商 [#copy-warmbly-crm-data-into-the-provider]

`GET /crm/backfill` · `POST /crm/backfill`

`GET` 统计仅存在于 Warmbly、尚未存在于任何已连接 CRM 的商机、任务和备注；从工作区以前使用的 CRM 镜像而来的记录不计入。`POST` 在后台一次性复制所选类型：商机移到第一个镜像销售管道，优先保留同名阶段，否则使用第一个与其状态匹配的阶段；在 Pipedrive 中则使用第一个阶段，并保留商机状态。已复制的记录不会重复复制，已有运行时再次 `POST` 会合并到当前运行。

身份验证：**权限范围** `INTEGRATIONS` · **组织权限** `manage_settings`

### 请求体 [#request-body-18]

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `deals` | boolean | 否 | 复制商机。 |
| `tasks` | boolean | 否 | 复制任务。 |
| `notes` | boolean | 否 | 复制备注。 |

至少一项必须为 `true`。

### 响应 [#response-36]

`GET` 返回 `{ "deals": 12, "tasks": 40, "notes": 7 }`。`POST` 返回 `202 Accepted`；进度显示在[同步健康状况](#get-sync-health)中。

## 刷新联系人的 CRM 记录 [#refresh-a-contacts-crm-record]

`POST /crm/contacts/:id/refresh`

立即拉取联系人的外部 CRM 记录、商机、任务和备注。未关联的联系人会按邮件地址查找，服务商中存在时建立关联，不会创建任何记录。每个联系人均有防抖限制，因此打开联系人时可安全调用：HubSpot 每分钟最多一次拉取、每五分钟一次查找；Pipedrive 按公司每日计量 API 用量，因此人员记录最多每两分钟重读一次，其商机、活动和备注每六小时一次，未关联联系人每十五分钟查找一次。

联系人的 CRM 记录，结构与 `GET /crm/contacts/:id` 相同。

## 列出 CRM 列表 [#list-crm-lists]

`GET /crm/lists`

列出 HubSpot 账户的联系人列表，最新优先，用于导入。需要 HubSpot 可选的列表权限，连接缺少该权限时返回 `409 crm_reauth_required`。Pipedrive 模式下，返回公司的已保存人员筛选器，按最近修改优先排列；每项包含 `size: -1`（Pipedrive 不统计筛选器结果数）和 `dynamic: true`。

身份验证：**权限范围** `READ_CRM` · **组织权限** `manage_contacts`

| 参数 | 位置 | 类型 | 说明 |

## 预览 CRM 列表导入 [#preview-a-crm-list-import]

`POST /crm/lists/preview`

统计列表将导入和跳过哪些联系人，并按跳过原因分类，不写入任何内容。

身份验证：**权限范围** `WRITE_CONTACTS` · **组织权限** `manage_contacts`

### 请求体 [#request-body-20]

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `list_id` | string | 是 | HubSpot 列表 ID 或 Pipedrive 筛选器 ID，最多 64 个字符。 |
| `apply_guards` | boolean | 否 | 跳过工作区导入保护规则排除的联系人（`config.guards`）。 |

### 响应 [#response-42]

```json
{
  "list_name": "Q3 webinar attendees",
  "total": 840,
  "included": 772,
  "skipped": [
    { "reason": "opted_out", "label": "Opted out of email in HubSpot", "count": 31 },
    { "reason": "lifecycle", "label": "Lifecycle stage is Customer", "count": 25 },
    { "reason": "no_email", "label": "No email address", "count": 12 }
  ],
  "sample": [{ "email": "sam@globex.com", "first_name": "Sam", "last_name": "Lee", "company": "Globex" }],
  "truncated": false
}
```

`reason` 为 `opted_out`、`lifecycle`、`open_deal`、`other_owner`、`no_email` 或 `duplicate`。一次导入最多读取 25,000 个联系人；列表更大时，`truncated` 为 `true`。

## 导入 CRM 列表 [#import-a-crm-list]

`POST /crm/lists/import`

将列表转为[联系人导入](/api/reference/contacts/)草稿，在常规导入审核中完成。请求体和跳过规则与预览相同。导入的联系人会在数分钟后关联到外部 CRM 记录。草稿归调用者所有；使用 API 密钥时，归创建该密钥的成员所有。

身份验证：**权限范围** `WRITE_CONTACTS` · **组织权限** `manage_contacts`

### 响应 [#response-43]

`201 Created`.

```json
{
  "import_id": "4d5e6f7a-8b9c-4d0e-8f1a-2b3c4d5e6f7a",
  "preview": { "list_name": "Q3 webinar attendees", "total": 840, "included": 772, "skipped": [], "sample": [], "truncated": false }
}
```

列表中没有任何可导入联系人时，返回 `400`。
