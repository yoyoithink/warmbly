title: "CLI"
description: "warmbly 命令行界面。登录一次，即可通过终端、CI 或智能体管理营销活动、联系人、邮箱和收件箱。"
---

`warmbly` 是 Warmbly 的命令行界面。它以你的身份登录，为每个主机保存一份凭据，并且仅调用公共 REST API，因此既适用于托管服务，也适用于你能够连接的任何自托管实例。

```bash
warmbly auth login
warmbly campaign list
warmbly inbox list --unseen
warmbly api "/campaigns?limit=10"
```

<Callout type="info" title="此工具与 warmblyctl 不同">
项目提供两个用途不同的 CLI。`warmbly` 安装在你的计算机上，用于使用产品功能。[`warmblyctl`](/development/warmblyctl/) 则是运维工具：它直接访问 Postgres，在后端容器中运行，用于恢复、账户管理、健康检查和备份。如果你想排查某个安装实例出了什么问题，应使用后者。
</Callout>

## 安装 [#install]

任选一种安装方式。它们都会提供同一个独立二进制文件。

**macOS 和 Linux**

```bash
curl -fsSL https://warmbly.com/cli.sh | sh
```

安装到 `~/.local/bin`，无需 root 权限或工具链。脚本会将下载内容与已发布的校验和进行比对；不一致时不会安装任何内容。它还会写入 shell 自动补全文件；如果该目录尚未加入 PATH，会提示需要添加到配置文件中的那一行命令。

**Windows**

```powershell
irm https://warmbly.com/cli.ps1 | iex
```

安装到 `%LOCALAPPDATA%\Warmbly\bin`，并将其加入用户 PATH。无需管理员权限。

**Homebrew**（macOS 和 Linux）

```bash
brew install warmbly/tap/warmbly
```

**Scoop**（Windows）

```powershell
scoop bucket add warmbly https://github.com/warmbly/homebrew-tap
scoop install warmbly
```

**Docker**：适用于 CI，或拉取镜像比安装二进制文件更方便的场景：

```bash
docker run --rm -e WARMBLY_TOKEN ghcr.io/warmbly/warmbly/cli campaign list
```

容器没有浏览器，因此应通过 `WARMBLY_TOKEN` 登录，而不是使用 `auth login`。

**从源码安装**，适用于已安装 Go 的环境：

```bash
go install github.com/warmbly/warmbly/cmd/cli@latest
mv "$(go env GOPATH)/bin/cli" "$(go env GOPATH)/bin/warmbly"
```

软件包目录为 `cmd/cli`，因此 `go install` 会将二进制文件命名为 `cli`。请自行重命名，或使用上述任一安装渠道。

**已经部署了 Warmbly 实例？** 后端镜像中已包含此二进制文件：

```bash
docker compose -p warmbly exec backend warmbly --help
```

### 保持更新 [#keeping-it-current]

```bash
warmbly version
warmbly upgrade
```

`upgrade` 会先根据发布版本的校验和验证下载内容，然后原地替换二进制文件。如果 CLI 通过 Homebrew 或 Scoop 安装，它会提示应运行的更新命令，不会覆盖包管理器管理的文件。CLI 还会每天检查一次新版本，并用一行提示告知；`WARMBLY_NO_UPDATE_CHECK=1` 可关闭此功能，且该检查不会在 CI 或输出被管道转发时运行。

### 安装程序选项 [#installer-flags]

安装脚本接受 `--` 后的选项，每个选项也都有对应的环境变量，因此同样的安装可从 Ansible、cloud-init 或 Dockerfile 中运行：

```bash
curl -fsSL https://warmbly.com/cli.sh | sh -s -- --dir /usr/local/bin
curl -fsSL https://warmbly.com/cli.sh | sh -s -- --version v1.4.0
curl -fsSL https://warmbly.com/cli.sh | sh -s -- --no-modify-path --no-completions
curl -fsSL https://warmbly.com/cli.sh | sh -s -- --dry-run
curl -fsSL https://warmbly.com/cli.sh | sh -s -- --uninstall
```

| 选项 | 变量 | 作用 |
|---|---|---|
| `--dir PATH` | `WARMBLY_INSTALL_DIR` | 二进制文件的安装位置。默认 `~/.local/bin` |
| `--version TAG` | `WARMBLY_CLI_VERSION` | 固定安装指定版本，而非最新版本 |
| `--base-url URL` | `WARMBLY_CLI_BASE_URL` | 从发布资源的内部镜像下载 |
| `--no-modify-path` | `WARMBLY_NO_MODIFY_PATH` | 不修改任何 shell 配置文件 |
| `--no-completions` | `WARMBLY_NO_COMPLETIONS` | 跳过自动补全文件 |
| `--dry-run` | | 打印将执行的操作，不作任何更改 |
| `--uninstall` | | 删除二进制文件和自动补全文件，保留登录信息 |

`--help` 会在终端列出这些选项。通过管道调用时可使用 `sh -s -- --help`。

### 运行前先阅读脚本 [#reading-it-before-you-run-it]

将脚本通过管道传入 shell 执行需要谨慎，因此脚本旁同时发布了校验和：

```bash
curl -fsSLO https://warmbly.com/cli.sh
curl -fsSLO https://warmbly.com/cli.sh.sha256
sha256sum -c cli.sh.sha256
less cli.sh && sh cli.sh
```

每个发布归档都有对应版本中的 `checksums.txt` 校验信息，安装器会在解压前据此验证归档。如果两者不匹配，安装器不会安装任何内容，并会明确提示。

### 命令补全 [#completions]

安装器会为你的 shell 写入自动补全文件。手动配置方式如下：

```bash
warmbly completion bash > /etc/bash_completion.d/warmbly
warmbly completion zsh  > "${fpath[1]}/_warmbly"
warmbly completion fish > ~/.config/fish/completions/warmbly.fish
```

## 登录 [#signing-in]

```bash
warmbly auth login
```

它会询问两个问题：连接哪个实例（托管服务或你自己的主机名），以及采用哪种登录方式（浏览器批准，或粘贴已有密钥）。

浏览器方式会显示一个八字符代码，打开 `app.warmbly.com/cli`，然后等待。你在该页面批准请求，并选择 CLI 要登录的工作区。页面上的客户端名称和计算机名称均由终端报告，因此应核对代码是否与终端打印的一致。由于批准会创建长期凭据，如果你在最近几分钟内未确认身份，页面会要求通过密码或第二因素确认是你本人，规则与创建 API 密钥相同。批准后会生成**一个以你的计算机命名的 API 密钥**（名称取主机名第一个点之前的部分），它会显示在“设置 > API 密钥”中，并可在那里或通过 `warmbly auth logout` 撤销。终端不会处理你的密码，浏览器也不会处理密钥。

```
  Your code: K4TM-9RQD
  Approve at: https://app.warmbly.com/cli?code=K4TM-9RQD

… Waiting for approval (the code expires in 10 minutes)
✓ Signed in to warmbly.com as jane@example.com
  Workspace Acme
```

脚本或智能体可使用以下非交互形式：

```bash
warmbly auth login --hostname warmbly.acme.com --web
echo "$WARMBLY_KEY" | warmbly auth login --with-token
warmbly auth login --scopes read-only
```

### 权限范围 [#scopes]

CLI 默认请求完整访问权限。获得的密钥永远不会超出你在所选工作区的角色权限：批准页面会列出密钥实际将获得的权限范围，CLI 请求中超出角色范围的部分会被省略。如果你的角色不允许其中任何一项，批准会被拒绝，错误码为 `cli_auth_scopes_role`。使用 `--scopes` 可以缩小请求范围：

```bash
warmbly auth login --scopes read-only
warmbly auth login --scopes read_campaigns,read_contacts,send_campaigns
```

密钥创建后，其权限范围即固定不变；要扩大权限，需要创建新密钥。`warmbly auth refresh --scopes full` 会重新执行登录并撤销被替换的密钥，因此刷新操作不会遗留一串旧密钥。

权限范围名称与[权限参考](/api/permissions/)中的名称一致，不区分大小写，并支持 `full` 和 `read-only` 简写。

### 管理多个实例 [#several-instances]

CLI 为每个主机保存一份凭据。`auth status` 中标有 `*` 的主机就是命令当前使用的主机。

```bash
warmbly auth login --hostname warmbly.acme.com
warmbly auth status
warmbly auth switch warmbly.acme.com
warmbly campaign list --host warmbly.com   # one command, other host
```

`warmbly auth status` 还会显示令牌的来源；命令意外失败时，这通常就是定位原因的关键：

```
* warmbly.com
    ✓ signed in as jane@example.com
    - workspace: Acme
    - scopes: all 24
    - api: https://api.warmbly.com
    - token from: /home/jane/.config/warmbly/hosts.yml
    - token: wmbly_ab********wxyz
```

### 在 CI 中使用 [#in-ci]

设置 `WARMBLY_TOKEN` 即可完全跳过登录。它会覆盖文件中的凭据，但绝不会写入该文件。

```yaml
env:
  WARMBLY_TOKEN: ${{ secrets.WARMBLY_TOKEN }}
  WARMBLY_HOST: warmbly.com     # omit for the hosted service
run: warmbly campaign list --json
```

`warmbly auth token` 只输出当前使用的令牌，便于将其交给其他工具。

## 输出 [#output]

在终端中，命令会打印表格；在其他环境中则输出 JSON。因此同一个命令既方便人阅读，也便于管道中的程序解析。

```bash
warmbly campaign list                      # a table
warmbly campaign list > campaigns.json     # JSON, no flag needed
warmbly campaign list --json | jq '.data[].name'
warmbly campaign list --fields name,status
warmbly campaign list --template '{{range .data}}{{.name}}{{"\n"}}{{end}}'
```

在任意列表命令中使用 `--all`，都会沿游标遍历并将所有页合并为一个响应。

## 发送真实邮件 [#sending-real-mail]

任何实际发送邮件的操作都会先请求确认；如果没有可用于询问的终端，则会拒绝操作，不会发送：

```
$ warmbly campaign start 6f1c…
! `warmbly campaign start` sends real mail. Continue? [y/N]
```

只有 `--yes` 能跳过确认，因此审查脚本时应搜索此选项。采用这种行为的命令包括 `campaign start`、`campaign test`、`placement test`、`placement batch-start`、`mailbox send`、`inbox reply`、`inbox compose` 和 `inbox approve-draft`。

### 示例 [#examples]

```bash
# Create a campaign, add a step, check it, start it
warmbly campaign create --name "Q3 outbound" --daily-limit 40
warmbly campaign add-step CAMPAIGN_ID --subject "Quick question" --wait-after 0
warmbly campaign preflight CAMPAIGN_ID
warmbly campaign start CAMPAIGN_ID

# Mailbox health across the workspace
warmbly mailbox list
warmbly mailbox check MAILBOX_ID
warmbly mailbox edit MAILBOX_ID --daily-limit 40

# Send as a verified Gmail alias, and take the signature from Gmail
warmbly mailbox identity MAILBOX_ID
warmbly mailbox refresh-identity MAILBOX_ID --signature
warmbly mailbox edit MAILBOX_ID --send-as hello@acme.com

# One contact is away: hold their sequence without unsubscribing them
warmbly campaign pause-lead CAMPAIGN_ID CONTACT_ID --until 2026-09-21T17:00:00Z --reason "On holiday"
warmbly campaign resume-lead CAMPAIGN_ID CONTACT_ID

# Two people at one company: copy the second on the first lead's emails
warmbly campaign lead-cc-suggestions CAMPAIGN_ID CONTACT_ID
warmbly campaign set-lead-cc CAMPAIGN_ID CONTACT_ID --cc COLLEAGUE_ID

# The inbox
warmbly inbox list --unseen --limit 20
warmbly inbox thread --email-id EMAIL_ID

# Contacts in and out
warmbly contact create --email jane@example.com --first-name Jane --company Acme
warmbly contact list --all --json > contacts.json
```

## 哪些操作需要使用控制台 [#what-needs-the-dashboard]

CLI 有意不提供以下三类功能，因为 API 不允许密钥执行这些操作：

- **连接邮箱。** 需要在浏览器中完成 OAuth 同意授权，或填写凭据表单。`warmbly browse mailboxes` 可打开对应页面。
- **工作区管理。** 成员、角色、邀请、工作区导出和危险操作区的 API 仅接受会话：这些操作依赖绑定到用户本人的会话，会拒绝 API 密钥。可通过 `warmbly browse members` 和 `warmbly browse settings` 打开对应页面。
- **账单。** 出于相同原因，套餐、结账和积分功能也仅接受会话。使用 `warmbly browse billing`。

`warmbly org view` 仍会显示当前所在工作区；`warmbly team`、`warmbly settings` 和 `warmbly audit` 则覆盖密钥可访问的工作区功能。

## 监听事件 [#watching-events]

`warmbly events tail` 将开发者 WebSocket 事件流输出到终端：与控制台使用的事件相同，并在发生时立即打印。这是检查集成是否收到预期事件的最快方式，无需先搭建公共端点。

```bash
warmbly events tail
warmbly events tail --intent EMAIL --intent CAMPAIGN
warmbly events tail --json | jq 'select(.event_type == "EMAIL_REPLIED")'
```

此命令需要具有 `REALTIME_SUBSCRIBE` 权限的密钥，可通过 `warmbly auth refresh --scopes full` 获取。事件流、订阅意图和事件类型的文档见[实时服务](/api/realtime/)。

## 直接调用 API [#calling-the-api-directly]

`warmbly api` 可访问所有端点，包括没有专用命令的端点。路径相对于 `/v1`。

```bash
warmbly api /me
warmbly api "/campaigns?limit=10" --paginate
warmbly api /contacts -f email=jane@example.com -f first_name=Jane
warmbly api /campaigns/CAMPAIGN_ID -X PATCH -F daily_limit=40
warmbly api /contacts/search -X POST --input filter.json
warmbly api /webhooks/WEBHOOK_ID -X DELETE
```

`-f` 会将值保持为字符串。`-F` 会推断类型，因此 `true`、`false`、`null` 和数字会以各自类型传入；`@file` 从文件读取值，`key[sub]=v` 创建嵌套结构，重复的 `key[]=v` 构成数组。`--paginate` 沿游标分页，`-i` 包含状态和响应头，`--idempotency-key` 通过[文档所述请求头](/api/authentication/)传递。

## 配置 [#configuration]

在 `~/.config/warmbly`（或 `XDG_CONFIG_HOME`、`WARMBLY_CONFIG_DIR`）下保存两个文件：

- `hosts.yml`：每个主机一份凭据，以 0600 权限写入
- `config.yml`：偏好设置和别名

登录时，会在凭据旁保存实例报告的 API URL 和控制台 URL，因此 `browse` 和 `events tail` 在自托管环境中也能工作，无需额外配置第二个地址。

```bash
warmbly config list
warmbly config set output json      # default to JSON even on a terminal
warmbly config set confirm always   # confirm every write, not only sends
warmbly config set browser firefox
```

### 别名 [#aliases]

```bash
warmbly alias set hot "campaign list --status active"
warmbly hot --json
```

别名之后输入的所有内容都会追加到命令中，因此别名只是命令的起点，而不是固定不变的完整命令。

### 环境 [#environment]

| 变量 | 作用 |
|---|---|
| `WARMBLY_TOKEN` | 要使用的 API 密钥。覆盖 `hosts.yml` 中的值，但绝不会写入该文件 |
| `WARMBLY_API_KEY` | 作用相同，但使用 `warmblyctl` 所采用的变量名 |
| `WARMBLY_HOST` | 选择要使用的已登录主机 |
| `WARMBLY_API_URL` | 无法从主机推导时使用的 API 基础 URL |
| `WARMBLY_CONFIG_DIR` | 上述两个文件的存放位置 |
| `WARMBLY_NO_UPDATE_CHECK` | 不检查更新版本 |
| `NO_COLOR` | 关闭颜色输出，与其他工具中的用法一致 |

## 退出码 [#exit-codes]

| 错误码 | 含义 |
|---|---|
| `0` | 执行成功 |
| `1` | 命令失败，或你拒绝了确认提示 |
| `2` | 命令行参数有误，或需要用户回答但没有可用于询问的终端 |
| `4` | 未登录，或凭据被拒绝、缺少权限范围 |

每次 API 失败都会将响应中供程序识别的 `code` 和 `request_id` 打印到标准错误输出，使脚本无需解析说明文字即可判断后续逻辑。
